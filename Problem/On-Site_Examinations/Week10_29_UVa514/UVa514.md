# UVa 514 - Rails

## 題目簡述

在一個名為 Rails 的火車調車場中，有一個特定的軌道系統。火車車廂編號依序為 $1$ 到 $N$，並按照 $1, 2, \dots, N$ 的順序從 $A$ 方向駛入車站（Station）。<br>
調車場內部有一個中轉的死胡同軌道（即只能「後進先出」的 Stack 結構）。藉由決定何時將車廂推入中轉軌道，以及何時將車廂從中轉軌道駛向 $B$ 方向，可以改變車廂的排列順序。<br>
給定一個期望的車廂出站序列，請判斷能否透過這個軌道系統成功將原本 $1 \dots N$ 的火車重新排列成該目標序列。

**Sample Input**：

  **5** $\rightarrow$ 火車車廂總數 $N = 5$。<br>
  **1 2 3 4 5** $\rightarrow$ 第一組期望出站序列（可行）。<br>
  **5 4 1 2 3** $\rightarrow$ 第二組期望出站序列（不可行）。<br>
  **0** $\rightarrow$ 當該區塊第一位數字為 0 時，代表該 $N$ 規模的測資結束。<br>
  **0** $\rightarrow$ 當最外層 $N = 0$ 時，代表整個輸入結束。

**Sample Output**：

  **Yes**<br>
  **No**<br>
  <br> $\rightarrow$ **核心注意：每個 N 規模的區塊結束後，必須輸出一個空行。**


## 解題思路與軌道堆疊模擬

### 核心觀念：後進先出的死胡同軌道模型（Stack）
這道題目的本質是經典的**車廂調度問題（Permutation Check）**，完美的對應到了資料結構中的 **堆疊（Stack）** 模型。
調車場中央的死胡同軌道，由於只有一個出入口，最晚開進去的車廂必須最先開出來，這完全符合堆疊「後進先出（Last In, First Out）」的幾何特性。

在模擬時，我們需要維護兩個主要狀態：
1. **`next` 指針**：代表當前正準備從 $A$ 軌道開進調車場的火車車廂編號（初始為 1，逐步遞增到 $N$）。
2. **`station` 堆疊**：代表當前停留在中轉死胡同軌道內的車廂。

### 演算法步驟
遍歷期望的目標出站序列 `target[j]`（`j` 從 0 到 $N-1$）：
1. **貪婪入站（Push 條件）**：如果期望出站的車廂尚未進入車站（即 `next <= n`），且當前中轉軌道頂端的車廂不等於目標（`station.empty() || station.top() != target[j]`），我們就強迫將火車 `next` 開進中轉軌道：`station.push(next++)`。這個動作會一直重複，直到目標車廂被推入軌道頂端，或者 $A$ 軌道的車廂全部用盡。
2. **出站比對（Pop 條件）**：完成入站嘗試後，檢查中轉軌道頂端的車廂（`station.top()`）。

   * 若剛好等於期望的車廂 `target[j]`，代表該車廂可以順利往 $B$ 方向出站，執行 `station.pop()`。
   * 若堆疊頂端與目標不相等（或堆疊已空），代表在當前的後進先出約束下，目標車廂被卡在更深的軌道內部，此時宣告該序列 **不可能（`possible = false`）** 達成，並立即中斷比對。
4. **結論輸出**：當整列火車走訪完畢後，若 `possible == true` 則輸出 `Yes`，否則輸出 `No`。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N)$
  雖然程式碼外層有一個遍歷目標序列的 `for` 迴圈（執行 $N$ 次），內層帶有一個 `while` 迴圈，但仔細觀察可以發現，`next` 變數在整趟模擬中**只會從 1 嚴格遞增到 $N+1$ 一次**。每節車廂最多只會進站（`push`）一次、出站（`pop`）一次。因此，單組序列的比對時間複雜度為最優的線性時間。
* **空間複雜度**： $\mathcal{O}(N)$
  需要動態配置一個大小為 $N$ 的 `vector<int> target` 陣列來儲存目標期望序列，且 `std::stack` 在最差情況下（例如目標為 `5 4 3 2 1`）也需要消耗 $N$ 的空間存放所有車廂。空間開銷與 $N$ 呈線性正比。


## 邊界條件與潛在陷阱

1. **雙重結束符號（0 的雙重防禦）**：
   這題的輸入規格較為繁瑣，包含兩層 0 的終止訊號：
   * **外層結束**：當讀入的車廂總數 $N = 0$ 時，徹底結束整個程式。
   * **內層結束**：在同一個 $N$ 規模下，可以連續輸入多組期望序列。當某一行的第一個數字讀到 `0` 時，代表該 $N$ 規模的測試結束，程式必須跳出內層迴圈，並去讀取下一個新的 $N$。
   原本程式碼中利用 `cin >> target[0]; if(target[0]==0) break;` 的提前攔截設計，完全符合此邊界規範。
2. **空行控制規範（Blank Line Trap）**：
   題目嚴格規定：「在每個 $N$ 規模的區塊結束後（即讀到內層的 0 跳出時），**必須在輸出端補上一個空行 `\n`**」。原程式碼在內層 `while(true)` 結束的外部補上了 `cout << "\n";`，格式完全正確，能精確規避 Presentation Error (PE)。
3. **堆疊解引用指針防禦（Stack Empty Check）**：
   在調用 `station.top()` 比對數值之前，**必須絕對優先進行 `!station.empty()` 的安全檢查**。如果對一個空的堆疊強行讀取頂端值，會在評測系統中觸發 SegFault 導致 Runtime Error (RE)。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n;
    // 外層控制：讀入車廂總數 n，當 n = 0 時徹底結束程式
    while (cin >> n && n != 0) {
        
        // 內層控制：在同一個 n 規模下，持續讀取多組期望序列
        while (true) {
            vector<int> target(n);
            cin >> target[0];
            
            // 核心邊界：若該組序列的第一個數字為 0，代表此 block 結束
            if (target[0] == 0) {
                break;
            }
            
            // 讀取剩餘的 n-1 個車廂編號
            for (int i = 1; i < n; i++) {
                cin >> target[i];
            }
            
            stack<int> station; // 模擬死胡同中轉軌道
            int next = 1;       // A 軌道上準備進站的車廂編號 (從 1 到 N)
            bool possible = true;
            
            // 逐一檢驗目標出站序列
            for (int j = 0; j < n; j++) {
                
                // 只要目標車廂還沒進站，且堆疊頂端不是我們要的車廂，就持續強迫 A 軌道火車推進中轉軌道
                while (next <= n && (station.empty() || station.top() != target[j])) {
                    station.push(next);
                    next++;
                }
                
                // 檢查中轉軌道頂端是否為當前期望出站的車廂
                if (!station.empty() && station.top() == target[j]) {
                    station.pop(); // 成功駛向 B 軌道出站
                }
                else {
                    possible = false; // 發生錯位阻塞，此序列宣告失敗
                    // 注意：因為後續還有剩餘數字需要維持輸入流對齊，所以即便失敗仍需讓外層讀完，
                    // 此處因 target 已在最前段全數讀完，故可安全 break 結束比對
                    break; 
                }
            }
            
            if (possible) {
                cout << "Yes\n";
            }
            else {
                cout << "No\n";
            }
        }
        // 核心格式：每個 N 規模的區塊結束後，必須輸出一個空行
        cout << "\n";
    }
    return 0;
}
```


## 進階優化思考

原做法使用 std::stack 來動態模擬軌道，在結構表現與語意對應上達到了極佳的水平。但在極致效能與常數時間優化的進階資工視角下，存在一個免去物件封裝與記憶體零動態配置的手動優化重構手段。

**輕量化雙指針與數組模擬堆疊**

由於火車的車廂總數 $N$ 在每組 Case 開始前就已經明確給定，我們根本不需要使用高階的 std::stack 容器。

* **做法**：直接開闢一個大小為 $N+1$ 的靜態整數陣列 int my_station[1005]，並搭配一個簡單的整數變數 top_ptr = -1 來當作堆疊指標。

* **優點**：station.push(x) 等價於 my_station[++top_ptr] = x；station.pop() 等價於 top_ptr--。這種直接操作連續記憶體記憶體與暫存器指標的模式，能徹底抹除掉 STL 容器內部封裝的額外微小開銷，在面對極大數據吞吐量時，是競賽中最極致、最穩健的常數級效能調優策略。
