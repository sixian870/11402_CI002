# UVa 11988 - Broken Keyboard (a.k.a. Beiju Text)

## 題目簡述

在輸入文字時，假設鍵盤壞掉了。每當按下 `Home` 鍵（在題目中以字元 `[` 代表），游標（Cursor）就會立刻跳到整行文字的**最前端**；每當按下 `End` 鍵（以字元 `]` 代表），游標就會立刻跳到整行文字的**最尾端**。<br>
輸入一串包含大寫字母、小寫字母、`[` 與 `]` 的損壞鍵盤輸入字串，請計算並輸出最終螢幕上顯示出來的完整文字序列。

**Sample Input**：

  **This_is_a_[beiju]_text** $\rightarrow$ 第一組輸入字串。<br>
  **[[]][][]Help_me___** $\rightarrow$ 第二組輸入字串。

**Sample Output**：

  **beijuThis_is_a__text** $\rightarrow$ 當讀到 `[` 時，游標跳到最前面，因此 "beiju" 被插到了最前端。<br>
  **Help_me___**


## 解題思路與指標調度

### 核心觀念：鏈結串列的游標移位與常數時間插入（Linked List & Iterators）
這道題目的本質是**串列資料結構的游標模擬與線性時間文字對齊**。

如果採用最直觀的 `std::string` 或 `std::vector` 進行模擬，每當讀到 `[` 游標跳到最前端時，後續插入的每個字元都會強迫陣列將其後方的所有字元集體向右搬移一位（這是一項高昂的 $\mathcal{O}(N)$ 搬移開銷）。在字串長度高達 $100,000$ 的極端測資下，這種做法會產生 $\mathcal{O}(N^2)$ 的最壞時間複雜度，進而引發 TLE。

為了解決頻繁在「中間」或「最前端」任意位置插入字元而不需要搬移資料的需求，最佳的資料結構對應就是 **`std::list`（雙向鏈結串列，Doubly Linked List）**。



在鏈結串列中，只要持有特定位置的指標（在 C++ 中為迭代器 `std::list::iterator`），在該位置插入新節點的代價僅僅是修改左右指標的指向，其耗時為完美的 **$\mathcal{O}(1)$ 常數時間**。

### 游標模擬決策
宣告一個 `list<char> dst` 來儲存最終文字，並維護一個動態迭代器 `it` 來扮演畫面的游標：
1. **初始狀態**：游標初始化在串列的末尾：`it = dst.end()`。
2. **分支一：讀到 `[` (Home 鍵)**：將游標直接重置到整條鏈結串列的最前端：`it = dst.begin()`。後續插入的文字將源源不斷地從最左側開始延伸。
3. **分支二：讀到 `]` (End 鍵)**：將游標直接重置到整條鏈結串列的最尾端：`it = dst.end()`。後續文字恢復常規的末尾追加。
4. **分支三：一般字元**：調用 `dst.insert(it, c)`。
   * **關鍵核心細節**：`std::list::insert(it, c)` 的運作機制是在迭代器 `it` 的**前方**插入新字元 `c`，並且在插入完成後，**回傳一個指向該新插入字元的全新迭代器指標**。
   * 為了維持游標的連續性，當在 `it` 前面塞入 `c` 後，原來的 `it` 依然位於新字元的右側。因此，下游字元再度進來時，會自然而然地排在 `c` 的後面。這完美契合了游標在輸入文字時自動向右推進的物理性質，完全不需手動對 `it` 進行額外的遞增或移位。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N)$ <br>
  其中 $N$ 為輸入字串的總長度。我們只需要利用單一層的 `for` 迴圈由左至右掃描一次字串。在迴圈內部，不論是切換游標（`dst.begin()` / `dst.end()`）還是調用鏈結串列的 `dst.insert(it, c)`，所有操作的代價皆在 $\mathcal{O}(1)$ 常數時間內收線。因此，總體時間複雜度與字串長度呈完美的線性正比，可在幾毫秒內極速通過評測。
* **空間複雜度**： $\mathcal{O}(N)$ <br>
  `std::list<char>` 容器需要開闢與實體字母數等量的鏈結節點空間來儲存最終呈現的文本數據，空間開銷與輸入規模呈線性正比。


## 邊界條件與潛在陷阱

1. **多個連續的鍵盤控制符（如 `[[[` 或 `[]]`）**：<br>
   * 當讀到連續的 `[` 時，迭代器會反覆被指定為 `dst.begin()`，這完全不會引發錯誤，後續字元依然會精確從最前端輸出。
   * 當讀到 `[]`（Home 隨即 End），游標先跳最前再跳最後，後續字元正確在尾端平鋪，邏輯完全相容。
2. **沒有任何控制字元的純文字行**：<br>
   此時 `it` 始終保持在初始狀態 `dst.end()`。所有的字元皆透過 `insert(dst.end(), c)` 依序追加，其表現與標準的 `push_back` 完全同構，結果完全正確。
3. **輸入流的讀取**：<br>
   題目並未事先告知有多少組字串，且字串可能包含特殊符號。最外層使用 `while (cin >> s)` 可以安全連續讀取，直到檔案流結束為止。原程式碼的流控制結構相當健康。


## 程式碼實作

```cpp
#include <iostream>
#include <string>
#include <list>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    string s;
    // 連續讀入損壞鍵盤字串 s，直到檔案結束 (EOF) 爲止
    while (cin >> s) {
        
        // 宣告雙向鏈結串列，提供 O(1) 任意位置高效率插入的底層支援
        list<char> dst;
        
        // 宣告動態迭代器，扮演畫面上即時滾動的文字游標
        // 初始狀態下游標預設停駐在串列的最末端 (end)
        auto it = dst.end();
        
        // 遍歷當前字串的每個字元，進行游標調度與插入
        for (char c : s) {
            if (c == '[') {
                // Home 鍵決策：將文字游標立刻強行跳回整行文字的最前端
                it = dst.begin();
            }
            else if (c == ']') {
                // End 鍵決策：將文字游標立刻強行跳回整行文字的最尾端
                it = dst.end();
            }
            else {
                // 常規字元：在當前游標迭代器的前方插入字元 c
                // 由於 C++ 標準庫的特性，insert 後原 iterator 會保持在原位（新字元的右側），
                // 使得下一個字元會自然而然排在其後方，完美實現游標自動右移的物理物理效果
                dst.insert(it, c);
            }
        }
        for (char c : dst) {
            cout << c;
        }
        cout << "\n"; // 每行測資結算完畢後輸出換行
    }
    return 0;
}
```


## 進階優化思考

原做法使用 `std::list` 在時間複雜度上已經達到了最優的 $\mathcal{O}(N)$。但在資工的極限常數時間與記憶體調優（Memory Locality）視角下，雙向鏈結串列因為每個節點都包含額外的 `prev` 與 `next` 兩個指標空間，會產生較大的空間泡沫；且零碎的記憶體動態配置（Dynamic Allocation）對 CPU 的快取非常不友善。

如果想進一步降低常數開銷，存在另外一種改用連續記憶體陣列，配合「鏈結索引化」的進階優化打法。

**陣列模擬單向鏈結串列（Array-Based Linked List, 靜態鏈結）**

* **原理**：我們可以使用一個固定大小的字元陣列 `char val[100005];` 儲存字元，以及一個整數陣列 `int next_ptr[100005];` 來記錄每個節點「它的下一個節點在陣列中的索引位置是什麼」。這就是經典的靜態鏈結串列（Static Linked List）。

* **做法**：

  * 開闢一個虛擬的頭節點 0。利用兩個變數 `head = 0` 與 `tail = 0` ，以及代表當前游標指向的陣列索引 `cur = 0` 。
  * 遇到 `[`：`cur = 0`（回到虛擬頭部）。
  * 遇到 `]`：`cur = tail`（移到最後一個字元）。
  * 插入常規字元：不需要真的搬移陣列，只需要將新字元填入新索引 `idx`，並修改指標：`next_ptr[idx] = next_ptr[cur]; next_ptr[cur] = idx;`，最後更新 `cur = idx;`。

* **效能改善**：此重構版本徹底擺脫了 std::list 物件反覆向作業系統申請記憶體的 Heap 開銷。所有的數據指引全數在一條完全連續的整數緩衝區陣列上透過索引下標移位完成。這不僅能大幅減少記憶體佔用空間，更能讓 CPU 的快取命中率飆升至物理極限，是高階競賽或即時嵌入式開發中非常強大的調優策略。
