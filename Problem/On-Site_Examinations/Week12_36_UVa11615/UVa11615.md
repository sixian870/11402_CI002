# UVa 11615 - Family Tree

## 題目簡述

給定一棵具有 $N$ 層的**滿二元樹（Perfect Binary Tree）**。在這棵樹中，根節點位於第一層，其編號固定為 1。對於樹中的任何一個節點 $X$，其左子節點編號為 $2X$，右子節點編號為 $2X+1$。<br>
已知這棵滿二元樹總共包含 $2^N - 1$ 個節點。現在給定樹中相異的兩個節點 $A$ 和 $B$，我們要移除以 $A$ 為根的子樹以及以 $B$ 為根的子樹（但必須保留 $A$ 和 $B$ 節點本身，僅刪除它們底下的所有子代後裔）。

請計算出在移除這兩棵子樹的後代成員後，這棵家族樹最終還剩下多少個節點？

**輸入規範**：
* 第一行包含一個正整數 $T$，代表測試資料的組數。
* 每組測試資料包含三個正整數 $N, A, B$（ $1 \le N \le 20$ ）。

**Sample Input**：

  **1** $\rightarrow$ 共有 1 組測試資料。<br>
  **3 4 5** $\rightarrow$ 滿二元樹層數 $N = 3$，指定刪除後代的節點為 $4$ 和 $5$。

**Sample Output**：

  **5** $\rightarrow$ 原先 $3$ 層滿二元樹共有 $2^3 - 1 = 7$ 個節點。移除節點 $4$ 與 $5$ 的子代後，剩餘 5 個節點。


## 解題思路與狀態分析

### 核心觀念：滿二元樹性質與獨立子樹修剪（Perfect Binary Tree Properties）
這道題目的本質是**二元樹的幾何性質與節點計數**。



根據滿二元樹的結構特性，若一棵滿二元樹的總層數為 $N$，則其總節點數必為 $2^N - 1$。當我們指定要將某個節點 $X$ 底下的所有子代後裔移除時，我們只需要知道 $X$ 這個節點在整棵樹中所處的**深度（Depth）**，就能精確推導出以 $X$ 為根的子樹到底佔據了多少層，進而算出它包含了多少個後代。

1. **計算節點深度**：
   由於編號是由根節點 1 開始向下依序倍增（$X \rightarrow 2X, 2X+1$），一個節點 $X$ 的深度可以透過將其不斷右移（除以 2）直到變為 0 來計算。計算經過的次數即為該節點所在的層數（根節點 1 的深度為 1，節點 2、3 的深度為 2，依此類推）。
2. **計算被修剪的子樹規模**：
   若節點 $X$ 所在的深度為 $\text{depth}$，則以 $X$ 為根的子樹，其自身的最大高度 $H$ 為：
   $$H = N - \text{depth} + 1$$
   一棵高度為 $H$ 的滿二元樹，其總節點數為 $2^H - 1$。由於題目規定要**保留節點 $X$ 本身**，僅刪除其子代，因此對於節點 $X$ 而言，實際被刪除的後代節點數為：
   $$(2^H - 1) - 1 = 2^H - 2$$
3. **處理兩個節點的包含關係（關鍵卡位）**：
   題目給定了兩個節點 $A$ 和 $B$。在二元樹的結構中，這兩個節點修剪的後代範圍是否會產生重疊？
   * 觀察編號結構可以發現，如果 $A$ 和 $B$ 處於不同的祖先分支上，或者是平行的兄弟節點，它們底下的子樹完全獨立，互不相交。
   * 如果其中一個節點（例如 $A$）剛好是另一個節點（例如 $B$）的祖先，那麼以 $B$ 為根的子樹本來就完全包含在以 $A$ 為根的子樹內部。此時，我們只需要修剪「位置較高（深度較淺）」的那一個節點即可。
   * **結論**：我們只需要找出 $A$ 和 $B$ 之中哪一個節點的深度較深（即靠近葉子節點，其子樹較小），哪一個較淺（靠近根節點，其子樹較大）。實際上，**位置較淺（深度較小）的節點所衍生出的子樹，一定會完全包覆或獨立於另一個節點**。因此，我們只需要抓取兩者之中「最大子樹高度」，也就是 `max_depth = max(get_depth(A), get_depth(B))`，並以此計算出最大被修剪的高度 $H$。

最終剩餘的節點數公式即為：
$$\text{總節點數} - \text{修剪掉的節點數} = (2^N - 1) - (2^H - 2) = 2^N - 2^H + 1$$


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(T \times \log(\max(A, B)))$ <br>
  對於每組測試資料，我們只需要透過位移運算（`>>= 1`）求出 $A$ 和 $B$ 的二進位制長度（即深度），耗時為其數值位元數，即 $\mathcal{O}(\log A)$ 與 $\mathcal{O}(\log B)$。隨後利用位移運算（`1 << N`）在 $\mathcal{O}(1)$ 時間內算出答案。整體執行效率極高，可在時限內輕鬆通過。
* **空間複雜度**： $\mathcal{O}(1)$ <br>
  僅使用固定數量的整型純量變數（`max_depth`, `H`, `ans`），未佔用任何動態記憶體空間。


## 邊界條件與潛在陷阱

1. **位移運算的溢位防禦**：<br>
   題目規範 $N \le 20$，在 C++ 中使用 `1 << N`（即 $2^N$）的最大值為 $2^{20} = 1,048,576$，完全在標準 32 位元有號整數（`int`）的安全承載範圍內（最大約 $2 \times 10^9$），因此不需要使用 `long long` 也不會發生溢位。
2. **保留節點本體的加減修正**：<br>
   公式推導時必須小心減法的臨界值。總節點為 $2^N - 1$，要扣除的是子樹除根之外的後代。若直接扣除整棵子樹會把 $A$ 或 $B$ 本身也拔除，因此代數公式推導為 $(2^N - 1) - (2^H - 1 - 1) = 2^N - 2^H + 1$，尾端的 $+1$ 是保留根節點的核心卡位。


## 程式碼實作
```cpp
#include <bits/stdc++.h>
using namespace std;

// 輔助函式：透過二進位制位移，計算指定編號節點在滿二元樹中的深度（層數）
int get_depth(int x) {
    int depth = 0;
    while (x > 0) {
        depth++;
        x >>= 1; // 相當於除以 2，向上一層尋找父節點
    }
    return depth;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int T;
    if (cin >> T) {
        while (T--) {
            int N, A, B;
            cin >> N >> A >> B;

            // 核心邏輯：找出 A 和 B 之中所處深度較大者
            // 深度較大代表該節點在較低層，其涵蓋的子樹範圍較小
            int max_depth = max(get_depth(A), get_depth(B));
            
            // 計算出受到修剪影響的最大子樹高度 H
            int H = N - max_depth + 1;
            
            // 全域幾何公式：(2^N - 1) - (2^H - 2) = 2^N - 2^H + 1
            int ans = (1 << N) - (1 << H) + 1;
            cout << ans << "\n";
        }
    }
    return 0;
}
```


## 進階優化思考

### 內建位元運算優化（Built-in Bit Manipulation, $\mathcal{O}(1)$ 深度計算）
在目前的實作中，計算節點深度的 `get_depth` 函式是透過一個 `while` 迴圈不斷進行右移，其時間複雜度取決於節點編號的二進位制位元數。雖然對於最大為 $2^{20}$ 的數值來說迴圈最多執行 20 次，速度已經極快，但我們還可以利用現代編譯器的內建硬體指令將其壓榨到絕對的常數時間。

* **優化做法**：在 GCC 編譯器中，提供了一個內建函式 `__builtin_clz(x)`（Count Leading Zeros），可以用來計算一個 32 位元整數在二進位制表示下，前方共有多少個連續的 0。
* **常數化轉型**：利用這個硬體層級的指令，一個數字 `x` 的二進位制有效長度（即深度）可以直接透過以下公式求得：
  ```cpp
  int depth = 32 - __builtin_clz(x);
  ```
  這樣一來，我們連 while 迴圈都不需要執行，CPU 可以在單個時脈週期內透過硬體指令直接秒殺深度的計算，將時間複雜度優化至純粹的 $\mathcal{O}(1)$，這是在撰寫極致性能要求的競賽程式碼時非常實用的底層調優技巧。
