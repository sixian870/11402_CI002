# UVa 732 - Anagrams by Stack

## 題目簡述

給定兩個字串：一個是原始字串（Source string），另一個是目標字串（Target string）。<br>
我們需要透過一個 **堆疊（Stack）** 作為中轉站，將原始字串轉換為目標字串。我們只能執行兩種操作：
* **`i` (push)**：從原始字串中依序取出一個字元，推入堆疊頂端。
* **`o` (pop)**：從堆疊頂端彈出一個字元，輸出至結果字串中。

請寫一個程式，找出所有可行的操作序列（由 `i` 與 `o` 組成），使得原始字串能精確轉換成目標字串。<br>
**格式要求**：每組測資的輸出必須包在 `[` 與 `]` 之間，所有的操作字元（`i` 或 `o`）之間必須以一個空格隔開。若有多個合法的操作序列，必須按照 **字典順序（i 排在 o 前面）** 依序換行印出。

**Sample Input**：

  **madam** $\rightarrow$ 原始字串 $S_1$。<br>
  **adamm** $\rightarrow$ 目標字串 $S_2$。<br>
  **bahama**<br>
  **bahama**

**Sample Output**：

  **\[** $\rightarrow$ 輸出標頭。<br>
  **i i o i o o o i o** $\rightarrow$ 每組操作序列間以空格隔開，一行一個。<br>
  **i i o i o o i o o**<br>
  **]** $\rightarrow$ 輸出結尾。<br>
  **[**<br>
  **i o i o i o i o i o i o**<br>
  **\]**


## 解題思路與回溯法模擬

### 核心觀念：堆疊狀態機與深度優先搜尋（DFS / Backtracking）
這道題目的本質是**利用堆疊限制進行路徑尋找的搜尋問題（Backtracking）**。
因為任何一個狀態下，我們都面臨著「推入新字元（`i`）」或「彈出頂端字元（`o`）」的分支決策，這非常適合以**深度優先搜尋（DFS）**配合回溯法來穷举所有可能性。

為了確保輸出符合題目「字典順序最小（i 在 o 前）」的要求，在撰寫 DFS 的遞迴分支時，**必須絕對優先嘗試 `i` 分支，隨後才嘗試 `o` 分支**。

### 遞迴狀態決策
定義 DFS 函式 `dfs(s1_idx, s2_idx, a1, result)`，其中各變數含意如下：
* `s1_idx`：當前原始字串 $S_1$ 正準備被 push 的字元索引。
* `s2_idx`：當前目標字串 $S_2$ 正期待被比對配對的字元索引。
* `a1`：當前的中轉堆疊（`std::stack<char>`）。
* `result`：當前累積的操作字串紀錄（例如 `"i i o "`）。

在每個遞迴節點，程式執行以下決策樹：
1. **終止條件（Success）**：當 `s2_idx == s2.length()` 時，代表目標字串的所有字元都已經成功被配對並輸出。此時，將 `result` 尾端多餘的空格削去，直接輸出該組操作解。

2. **分支一：嘗試 Push（操作 `i`）**：

   * **可行條件**：只要原始字串還有字元未被推入堆疊（`s1_idx < s1.length()`）。

   * **執行動作**：複製一個新堆疊，將 `s1[s1_idx]` 推入堆疊，遞迴調用 `dfs(s1_idx + 1, s2_idx, next_st, result + "i ")`。

3. **分支二：嘗試 Pop（操作 `o`）**：

   * **可行條件**：堆疊不能為空（`!a1.empty()`），且**目前堆疊頂端的字元必須剛好等於目標字串期待的字元（`a1.top() == s2[s2_idx]`）**。如果頂端字元不對，彈出也無法對齊目標，屬於無效分支。

   * **執行動作**：複製一個新堆疊並將頂端彈出，遞迴調用 `dfs(s1_idx, s2_idx + 1, next_st, result + "o ")`。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(2^{2N})$
  其中 $N$ 為字串的長度。在長度為 $N$ 的字串轉換中，我們必須精確執行 $N$ 次 `i` 與 $N$ 次 `o`，總路徑長度固定為 $2N$。在無任何剪枝的最壞情況下，這是一棵深度為 $2N$ 的滿二元決策樹，總狀態數上限為 $2^{2N}$。由於剪枝防禦線（`a1.top() == s2[s2_idx]`）非常嚴格，實務上大量無效分支會提早夭折，因此在題目限制字串長度內，可在時限內通過。

* **空間複雜度**： $\mathcal{O}(N^2)$
  主要來自遞迴呼叫時系統佔用的堆疊空間（深度上限為 $2N$），以及在每個遞迴層級中，為了保存狀態而複製 `std::stack` 與傳遞 `std::string` 所產生的動態記憶體配置。


## 邊界條件與潛在陷阱

1. **基本長度不合判定**：
   如果原始字串與目標字串的**長度不相等（`s1.length() != s2.length()`）**，依據物理質量守恆，不論如何調度，堆疊都不可能將不同長度的字串完整轉換。此時可以直接跳過 DFS，直接印出空的 `[` 與 `]` 即可，能省下海量的無謂計算。
2. **字母組成完全不同**：
   雖然原程式碼利用了 `a1.top() == s2[s2_idx]` 在過程中進行動態卡位，但如果字串長度相同但字母完全對不上（如 `abc` 轉 `xyz`），DFS 仍會進入前期的幾輪 push。這已具備足夠的安全性。
3. **尾端空格格式移除**：
   題目要求字元間以空格隔開，但**最後一個字元的後面絕對不能殘留空格**。原程式碼在終止條件內，先執行了 `if (!result.empty()) result.pop_back();`，將最後一輪帶入的結尾空格 `" "` 刪除後才進行 `cout`，這是一個非常優秀的格式安全控管手法。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

// 宣告全域字串變數，方便回溯函式直接存取
string s1, s2;

// 核心 DFS 回溯函式：依序穷举所有符合堆疊規範的 i 與 o 組合
void dfs(int s1_idx, int s2_idx, stack<char> a1, string result) {
    // 成功終止條件：目標字串的所有字元都已成功從堆疊中彈出對齊
    if (s2_idx == s2.length()) {
        if (!result.empty()) {
            result.pop_back(); // 核心格式控制：移除最後一個字元尾端多餘的空格
        }
        cout << result << "\n";
        return;
    }
    
    // 分支一：嘗試進行 PUSH 操作 (操作碼 'i')
    // 字典序要求優先輸出 'i'，故此分支必須放置在最上方優先觸發
    if (s1_idx < s1.length()) {
        stack<char> next_st = a1; // 複製當前堆疊狀態以維持回溯獨立性
        next_st.push(s1[s1_idx]); // 將原始字串當前字元推入堆疊
        dfs(s1_idx + 1, s2_idx, next_st, result + "i ");
    }
    
    // 分支二：嘗試進行 POP 操作 (操作碼 'o')
    // 核心安全防禦：堆疊不可為空，且堆疊頂端字元必須完全與目標字串期待的字元重合
    if (!a1.empty() && a1.top() == s2[s2_idx]) {
        stack<char> next_st = a1; // 複製當前堆疊狀態
        next_st.pop();            // 彈出頂端字元
        dfs(s1_idx, s2_idx + 1, next_st, result + "o ");
    }
}

int main() {
    while (cin >> s1 >> s2) {
        cout << "[\n";
        if (s1.length() == s2.length()) {
            stack<char> a1;
            dfs(0, 0, a1, "");
        }
        cout << "]\n";
    }
    return 0;
}
```


## 進階優化思考
原實作在 DFS 函式中採用了直接傳值（Pass-by-value）的封裝方式： `stack<char> a1` 與 `string result` 。雖然這種寫法在回溯法中非常直觀且安全（各個遞迴分支完全不用擔心弄髒彼此的記憶體），但在大型字串下，頻繁在堆疊幀（Stack Frame）中進行物件複製會帶來高昂的時間常數開銷。

**全域單一容器維護與指標回溯（引用回溯優化）**

為了將常數時間開銷壓縮到理論最優，我們可以改用傳引用（Pass-by-reference）加上手動還原狀態的高階競賽思維：

1. **單一堆疊共享**：只維護一個全域的 `stack<char>` 或 `vector<char>` 。
2. **單一結果串流**：以一個字元陣列儲存目前的操作代碼，只透過傳遞長度變數來覆蓋內容。
3. **手動回溯還原**：在遞迴呼叫完畢返回後，手動執行 pop() 或者是把剛才推入的元素移除，將容器恢復原狀。

**畫程式碼實作片段：**
```cpp
// 將堆疊與路徑陣列提升為全域單一實體，杜絕反覆複製
vector<char> current_stack;
vector<char> path; 

void optimized_dfs(int s1_idx, int s2_idx) {
    if (s2_idx == s2.length()) {
        // 一次性格式化印出全域 path 陣列 ...
        return;
    }
    
    // 優先嘗試 Push
    if (s1_idx < s1.length()) {
        current_stack.push_back(s1[s1_idx]);
        path.push_back('i');
        
        optimized_dfs(s1_idx + 1, s2_idx); // 傳遞引用，零複製開銷
        
        path.pop_back();          // 手動還原路徑狀態 (Backtrack)
        current_stack.pop_back(); // 手動還原堆疊狀態
    }
    
    // 嘗試 Pop
    if (!current_stack.empty() && current_stack.back() == s2[s2_idx]) {
        char popped_char = current_stack.back();
        current_stack.pop_back();
        path.push_back('o');
        
        optimized_dfs(s1_idx, s2_idx + 1);
        
        path.pop_back();                 // 手動還原路徑狀態
        current_stack.push_back(popped_char); // 手動還原堆疊狀態 (重新插回)
    }
}
```
* **效能改善**：此重構版本徹底消除了作業系統在執行遞迴時，動態配置記憶體（Dynamic Allocation）與物件深度複製（Deep Copy）的 CPU 開銷。全域資料完全在連續的實體記憶體上進行原地修改（In-place Modification），能最大程度提高 CPU 的 L1/L2 Cache 命中率，是應對複雜深度搜尋考題時最極致、最專業的調優架構。
