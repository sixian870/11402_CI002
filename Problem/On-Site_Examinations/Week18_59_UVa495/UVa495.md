# UVa 495 - Fibonacci Freeze

## 題目簡述

給定一個非負整數 $N$（ $0 \le N \le 5000$ ），請計算出相對應的第 $N$ 個費氏數（Fibonacci number）。

**費氏數列定義**：
* $f(0) = 0$
* $f(1) = 1$
* $f(i) = f(i - 1) + f(i - 2)$，其中 $i \ge 2$。

**輸入與輸出規範**：
連續讀入整數 $N$，每組測試資料必須嚴格依照格式印出：`The Fibonacci number for X is Y`。

**Sample Input**：

  **0** $\rightarrow$ 第一組長度 $N = 0$。<br>
  **1**<br>
  **2**<br>
  **5**

**Sample Output**：

  **The Fibonacci number for 0 is 0** <br>
  **The Fibonacci number for 1 is 1** <br>
  **The Fibonacci number for 2 is 1** <br>
  **The Fibonacci number for 5 is 5**


## 解題思路與狀態轉移

### 核心觀念：動態規劃與高維大數線性建表（Dynamic Programming / Big Integer）
這道題目的本質是**基礎動態規劃與高精確度大數加法的結合**。

由於費氏數列的每一項都嚴格依賴於其前兩項的加總結果，如果使用傳統的遞迴求解，會產生高昂的重疊子問題開銷，進而引發逾時。最佳的策略是採用**動態規劃（Dynamic Programming）的離線建表法（Pre-computation）**：
1. 建立一個一維陣列表格 `a`，長度配置為 5001。
2. 填入遞迴基本邊界：`a[0] = "0"; a[1] = "1";`。
3. 利用一條 `for` 迴圈從 2 順向迭代至 5000。在迴圈內部，直接將前兩項的字串透過大數加法函式進行融合，並填入當前節點：`a[i] = stringAdd(a[i-1], a[i-2])`。
4. 預處理完成後，後續的所有查詢都能直接在 $\mathcal{O}(1)$ 常數時間內秒殺輸出。


## 複雜度分析

* **時間複雜度**：

  * **離線大數預建表階段**： $\mathcal{O}(N_{\text{max}} \times L)$ <br>
    其中 $N_{\text{max}} = 5000$， $L$ 為數列第 5000 項的平均字串長度（約為 1045 位數）。利用字串直式進位加法跑 5000 次線性轉移，每次字串長度為 $L$，總建表時間可以在幾毫秒內極速完工。
  * **線上查詢階段**： $\mathcal{O}(1)$ <br>
    數據流進入後，直接透過下標 `a[x]` 從實體陣列中抽離解答並印出，不含任何迴圈或代數轉移，查詢的時間複雜度為絕對常數時間。
* **空間複雜度**： $\mathcal{O}(N_{\text{max}} \times L)$ <br>
  `std::vector<string> a(5001)` 表格需要配置空間來保留這 5001 個超大數字串。在第 5000 項時字串長度約為 1045 位元組，全域總體記憶體佔用不超過 3 MB，空間佈局十分精簡且對記憶體友善。


## 邊界條件與潛在陷阱

1. **十進位超大數溢位地雷**：<br>
   這是本題最致命的 Wrong Answer 陷阱。費氏數列呈指數級爆增，當 $N = 93$ 時，數值就已經完全擠爆了 C++ 硬體暫存器的物理極限（64 位元無號整數 `unsigned long long` 的天花板）。當 $N = 5000$ 時，答案高達驚人的 1045 位數！

   * **程式碼防禦**：實作中完全捨棄了內建的整數型態，直接使用 `std::string` 搭配雙指標從低位數向高位數模擬小學直式加法（利用 `carry` 處理逐位進位）。這打破了硬體暫存器限制，能安全承載千位數以上的代數運算。

2. **大數加法內部字串反轉對齊**：<br>
   在迴圈內部進行字串逐位相加時，每次算出的個位數都是透過 `+=` 追加到 `a[i]` 的尾端。這會導致高低位倒置（例如 13 加 21 算出 34，但在字串追加中會呈現 `"43"`）。因此，在每層大數計算結束時，**必須調用 `reverse(a[i].begin(), a[i].end())` 將其順序翻轉過來**，才能確保文本輸出的幾何語意完全正確。
3. **字串轉整數的字元偏移量（`-'0'`）**：<br>
   在從 `string b` 與 `c` 中取出字元進行數學相加時，必須寫成 `b[j] - '0'`。這利用了 ASCII 碼的連續性偏移，將字元精確轉換為可運算的整數數值，防範了亂碼偏離。


## 程式碼實作
```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
using namespace std;

int main() {
    vector<string> a(5001);
    a[0] = "0";
    a[1] = "1";
    for (int i = 2; i <= 5000; i++) {
        string b = a[i - 1];
        string c = a[i - 2];
        int carry = 0; // 進位計數器
        
        int j = b.length() - 1;
        int k = c.length() - 1;
        
        // 核心直式加法流：由低位數向高位數反向掃描
        while (j >= 0 || k >= 0 || carry > 0) {
            int sum = carry;
            if (j >= 0) {
                sum += b[j] - '0'; // 利用 ASCII 偏移量將字元轉為整數
                j--;
            }
            if (k >= 0) {
                sum += c[k] - '0';
                k--;
            }
            a[i] += (sum % 10) + '0'; // 將當前位數的和轉回字元並追加至尾端
            carry = sum / 10;          // 計算下一次進位
        }
        // 核心格式修正：因為是從低位往高位追加，最終必須反轉字串才是正確的十進位表示法
        reverse(a[i].begin(), a[i].end());
    }
    int x;
    while (cin >> x) {
        // 以絕對常數時間 O(1) 直接查表並精確依照題目規格印出答案
        cout << "The Fibonacci number for " << x << " is " << a[x] << "\n";
    }
    return 0;
}
```


## 進階優化思考

### 空間優化與大數傳引用滾動（Buffer Optimization）
在目前的動態規劃實作中，預先建立了大小為 5001 的 `std::vector<std::string>` 陣列。雖然在 3 MB 的空間開銷下對於現代計算機來說微不足道，但如果從高階軟體工程的記憶體片段（Memory Fragmentation）與快取調優視角來檢視，每次在 `while` 迴圈內部執行 `a[i] += ...` 時，都會觸發字串物件底層的動態記憶體配置（Dynamic Allocation）。

* **優化作法**：如果想要完全抹除這種 Heap 區塊的分配開銷，可以在主程式開頭直接宣告三個長度固定為 1100 個位元組的 `std::vector<char>` 作為**原地快取緩衝區（In-place Buffer）**，分別代表 `prev2`、`prev1` 與 `current`。

* **技術精髓**：在大數相加時，直接利用傳引用（Pass-by-reference）的方式在這三個連續的字元緩衝區上進行代數覆蓋與進位計算，計算完畢後再將 `current` 複製給陣列。這能將記憶體配置次數直接降為 0，大幅提高 CPU 的 L1/L2 快取命中率，是在應對百萬級大數模擬或記憶體受限的嵌入式環境中非常強大的底層常數調優手段。
