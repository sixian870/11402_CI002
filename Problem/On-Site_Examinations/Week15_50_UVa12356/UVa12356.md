# UVa 12356 - Army Buddies

## 題目簡述

在一條戰線上，有 $S$ 名士兵（編號由 $1$ 到 $S$）排成一橫列。初始狀態下，每個士兵的左邊和右邊各自都有其原本的戰友（除 1 號左邊、 $S$ 號右邊沒有人以外）。<br>
接下來會連續發生 $B$ 次敵軍的轟炸事件，每次轟炸都會精確消滅一個閉區間 $[L, R]$ 之間的所有士兵（包含 $L$ 和 $R$）。

對於每次轟炸事件，請計算出：**在這批被消滅的士兵中，最左側士兵（即 $L$）新存活的左邊戰友是誰？以及最右側士兵（即 $R$）新存活的右邊戰友是誰？**<br>
如果某個方向已經沒有任何存活的士兵，則以星號字元 `*` 來代替輸出。每一組測試資料結束時，必須額外印出一個減號 `-`。

當輸入的總人數 $S = 0$ 且轟炸次數 $B = 0$ 時，代表整個輸入流結束。

**Sample Input**：

  **1 1** $\rightarrow$ 第一組測資：共有 $S = 1$ 名士兵，轟炸 $B = 1$ 次。<br>
  **1 1** $\rightarrow$ 轟炸區間 $[1, 1]$。<br>
  **10 4** $\rightarrow$ 第二組測資：共有 $S = 10$ 名士兵，轟炸 $B = 4$ 次。<br>
  **2 5** $\rightarrow$ 轟炸區間 $[2, 5]$。<br>
  **6 9**<br>
  **1 1**<br>
  **10 10**<br>
  **0 0** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **\* \*** $\rightarrow$ 第一組：唯一的一個人被炸死，左右皆無人生還。<br>
  **1 6** $\rightarrow$ 第二組第一次轟炸：消滅 2 到 5 號。2 號的左邊是 1，5 號的右邊是 6。<br>
  **1 10** $\rightarrow$ 第二次轟炸：消滅 6 到 9 號。此時 6 號右邊新串接至 10。<br>
  **\* 10** $\rightarrow$ 第三次轟炸：消滅 1 號。1 號左邊無人。<br>
  **\* \*** $\rightarrow$ 第四次轟炸：消滅 10 號。戰線全滅。<br>
  **-** $\rightarrow$ 每組 Scenario 結束必須印出一個減號。


## 解題思路與靜態雙向鏈結串列

### 核心觀念：靜態雙向鏈結串列與 $\mathcal{O}(1)$ 斷鏈串接（Static Doubly Linked List）
這道題目的本質是**雙向鏈結串列的動態節點抹除與指針重定向優化**。
題目給定的士兵人數上限高達 $S \le 100,000$，而轟炸次數也高達 $B \le 100,000$。

如果採用最直觀的「布林陣列標記法」，每次收到轟炸區間 $[L, R]$ 時，都用一個 `for` 迴圈從 $L$ 到 $R$ 逐一標記死亡，並在尋找剩餘戰友時再次向左、向右線性掃描。在最壞情況下（如每次都只炸幾個人，或者大範圍反覆掃描），時間複雜度會退化到 $\mathcal{O}(B \times S)$，這會直接導致 Time Limit Exceeded (TLE)。

為了解決頻繁「抹除中間連續區間」並能瞬間知道「殘留邊界指針」的需求，最佳的資料結構就是**雙向鏈結串列**。但不需要大費周章去宣告結構體（struct）與動態記憶體（new pointer）。我們可以直接開闢兩個一維整數陣列來扮演**靜態指針（Static Pointers）**：
* `left[i]`：儲存編號為 `i` 的士兵，其**左邊存活的戰友編號**。
* `right[i]`：儲存編號為 `i` 的士兵，其**右邊存活的戰友編號**。



### 核心操作與鏈結重組
當收到轟炸報告 $[L, R]$ 時，因為這個區間內的所有人即將從戰線上消失，我們完全不需要理會區間內部的人，**我們唯一需要修改的，是這個區間「最左端的左邊那個人」與「最右端的右邊那個人」的指針方向**：
1. **左邊那個人的右指針**：原本指向 $L$，現在必須直接跨過整個死亡區間，改為指向 $R$ 的右邊那個人。公式為：
   `right[left[L]] = right[R];`
2. **右邊那個人的左指針**：原本指向 $R$，現在必須直接跨過整個死亡區間，改為指向 $L$ 的左邊那個人。公式為：
   `left[right[R]] = left[L];`

完成這兩行代碼的指針重定向後，整個 $[L, R]$ 區間在幾何結構上就被徹底從鏈結中孤立並拔除。後續如果有其他轟炸波及到這個區間，指針在經過時會自動跳躍過去，從而達成了完美的常數時間調度。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(S + B)$ <br>
  在初始化階段，配置並填入 $S$ 名士兵的左右指針需要 $\mathcal{O}(S)$ 時間。後續處理 $B$ 次轟炸時，每次區間斷鏈與輸出控制皆為純粹的 $\mathcal{O}(1)$ 常數操作，耗時與區間長度 $|L - R|$ 完全無關。總體時間複雜度為線性 $\mathcal{O}(S + B)$，可在幾毫秒內極速通過評測。
* **空間複雜度**： $\mathcal{O}(S)$ <br>
  需要開闢兩個大小為 $S + 2$ 的一維 `std::vector<int>` 陣列來維護靜態雙向指針。當 $S = 100,000$ 時，記憶體開銷僅約 800 KB，空間配置極其精簡且快取友善（Cache-friendly）。


## 邊界條件與潛在陷阱

1. **邊界哨兵節點的設計（0 號防禦線）**：<br>
   當 1 號士兵被炸死時，其 `left[1]` 的值為 0。如果直接執行 `right[left[1]] = right[R]`，等價於去修改 `right[0]` 的值。

   * **原程式碼分析**：原實作在宣告 `vector` 時，刻意將大小指定為 `s + 2`（包含了 0 號與 `s + 1` 號）。這在資工中被稱為**哨兵節點（Sentinel Nodes）**。0 號扮演了左側的「虛無邊界」，`s + 1` 扮演了右側的「虛無邊界」。當指針修改到 `right[0]` 時，剛好安全的落在陣列合法記憶體內，絕不會引發記憶體區段錯誤（Segmentation Fault）。

2. **星號 `*` 的輸出控制**：<br>
   在輸出新戰友時，如果 `left[L] == 0`，代表左側已全數陣亡，必須精確印出 `*`；右側若 `right[R] == 0`（原程式碼初始化將最右側的結束符標記為 0），代表右側全滅，同樣印出 `*`。

3. **多組測資間的緩衝清空**：<br>
   由於有多組 Scenario，左右指針陣列 `left` 與 `right` 必須宣告在 `while (cin >> s >> b)` 迴圈的**內部**。這樣每組新 Case 開始時，整個戰線都會被重新初始化，不會發生跨測資的歷史污染。


## 程式碼實作

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int s, b;
    // 連續讀入士兵數 s 與轟炸次數 b，當兩者皆為 0 時安全終止程式
    while (cin >> s >> b && (s != 0 || b != 0)) {
        
        // 分配 s + 2 大小的靜態指針陣列，0 號與 s+1 號自動作為邊界哨兵節點
        vector<int> left(s + 2);
        vector<int> right(s + 2);
        
        // 初始化雙向鏈結：每個人的左邊是 i-1，右邊是 i+1
        for (int i = 1; i <= s; i++) {
            left[i] = i - 1;
            right[i] = i + 1;
        }
        // 邊界防禦線：1 號左邊無人 (設為 0)，s 號右邊無人 (設為 0)
        left[1] = 0;
        right[s] = 0;

        // 開始依序處理 b 次轟炸事件
        while (b--) {
            int l, r;
            cin >> l >> r;
            
            // 核心斷鏈公式：
            // 讓死亡區間左邊那個人的右指針，直接跳過災區，指向右邊那個人的右邊
            right[left[l]] = right[r];
            // 讓死亡區間右邊那個人的左指針，直接跳過災區，指向左邊那個人的左邊
            left[right[r]] = left[l];
            
            // 格式化輸出最左側新存活的左戰友
            if (left[l] == 0) {
                cout << "* ";
            }
            else {
                cout << left[l] << " ";
            }
            
            // 格式化輸出最右側新存活的右戰友
            if (right[r] == 0) {
                cout << "*\n";
            }
            else {
                cout << right[r] << "\n";
            }
        }
        // 嚴格依照題目規範：每組 Scenario 結束後必須印出一個減號
        cout << "-\n";
    }
    return 0;
}
```


## 進階優化思考
**記憶體連續性與常數效能極致調優**

如果我們想進一步將時間壓縮到物理極限，可以注意到在主迴圈內部有大量的 `cout << ...` 格式化輸出。在高吞吐量的數據流下，频繁調用標準輸出會產生不小的 I/O 阻礙。

* **優化做法**：除了已經加上了 `ios::sync_with_stdio(false); cin.tie(0);` 外，在輸出的時候，盡可能使用 `\n` 來替代 `endl`。

* **底層效益**：`\n` 屬於純字元寫入，不會強迫系統去刷新底層的硬體緩衝區（Flush Buffer），能將系統底層的輸出流寫入開銷直接降低一個數量級，是資工在高併發、高性能系統開發中非常核心的常數優化習慣。
