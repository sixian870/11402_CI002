# UVa 11292 - Dragon of Loowater

## 題目簡述

王國王國 Loowater 正面臨著一場可怕的災難：一隻擁有 $N$ 個頭的惡龍正在肆虐。幸運的是，王國裡有 $M$ 位勇士可以受僱來砍掉惡龍的頭。<br>
每隻惡龍的頭都有其對應的**直徑大小**，而每位勇士也都有其對應的**身高限制**。
* **僱用規則**：一位身高為 $X$ 的勇士，只能砍掉直徑**小於或等於** $X$ 的惡龍頭。
* **薪資開銷**：僱用一位身高為 $X$ 的勇士，必須支付與其身高完全等價的金幣數量 $X$。

每位勇士精確只能砍掉一個惡龍頭。請計算出在成功砍掉惡龍所有頭的前提下，**最少需要花費多少金幣**？如果勇士們的身高組合無論如何都無法斬殺這隻惡龍，則輸出 `Loowater is doomed!`。

當輸入的 $N = 0$ 且 $M = 0$ 時，代表整個輸入結束。

**Sample Input**：

  **2 3** $\rightarrow$ 第一組測資：惡龍有 $N = 2$ 個頭，王國有 $M = 3$ 位勇士。<br>
  **5** $\rightarrow$ 惡龍兩個頭的直徑。<br>
  **4**<br>
  **2** $\rightarrow$ 三位勇士的身高。<br>
  **8**<br>
  **4**<br>
  **2 1** $\rightarrow$ 第二組測資：$N = 2$ 個頭，$M = 1$ 位勇士。<br>
  **5**<br>
  **5**<br>
  **10**<br>
  **0 0** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **12** $\rightarrow$ 最優解為選身高 4 的勇士砍直徑 4 的頭，選身高 8 的勇士砍直徑 5 的頭，費用 $4+8=12$。<br>
  **Loowater is doomed!** $\rightarrow$ 勇士人數少於惡龍頭數，直接宣告斬殺失敗。


## 解題思路與貪婪策略

### 核心觀念：雙序列標準化與最省成本配對（Greedy Algorithm）
這道題目的本質是**經典的雙序列貪婪配對與最優化成本調度**。

為了讓總花費金幣（Cost）達到全域最低，在策略上必須遵循兩大貪婪核心：
1. **小魚吃小蝦（防禦浪費）**：對於直徑較小的惡龍頭，我們應該優先派出身高「剛好符合最低門檻」的勇士去對付，把身高更高、戰力更強的勇士保留給未來可能出現的更大龍頭。
2. **勇士戰力最大化**：不論是惡龍的頭還是勇士的身高，如果資料是雜亂無序的，我們就很難進行最優化比對。因此，第一步必須對兩組序列進行**升序排序（Sorting）**。



### 演算法步驟
1. 利用 `while (cin >> n >> m && (n != 0 || m != 0))` 連續讀取多組測資。
2. **常數時間剪枝（人數防禦）**：如果惡龍頭的數量大於勇士總人數（`n > m`），依據鴿籠原理，就算所有勇士都能一砍一，也絕對會殘留龍頭。此時可以直接判定無解，提早中斷並輸出 `Loowater is doomed!`。
3. 宣告並讀入兩個陣列：`vector<int> d(n)` 儲存龍頭直徑，`vector<int> k(m)` 儲存勇士身高。
4. 調用 `std::sort` 將兩個序列同時進行升序排列，使其具備單調有序性。
5. **雙指標流式掃描**：
   維持一個龍頭追蹤指標 `head = 0`。利用一個 `for` 迴圈遍歷所有排序好的勇士 `k[i]`：
   * 如果當前勇士的身高符合門檻（`k[i] >= d[head]`），代表他可以成功斬殺此龍頭。此時將其身高累加至總金幣 `cost += k[i]`，並讓龍頭指標向右推進：`head++`。
   * 如果不符合（`k[i] < d[head]`），代表這位勇士太矮了，連目前最弱的龍頭都砍不動。由於後續的龍頭直徑只會越來越大，這位勇士在未來的戰局中徹底失去用武之地。我們直接將其略過，不花費任何金幣。
6. **最終合規檢查**：
   當遍歷完所有勇士後，檢查 `head` 是否精確等於 `n`。若等於 `n`，代表所有的惡龍頭都已成功被砍下，輸出累積的 `cost`；否則，代表後續的巨大龍頭無人能敵，輸出 `Loowater is doomed!`。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \log N + M \log M)$ <br>
  演算法的效能瓶頸完全由前期的排序階段決定。將長度為 $N$ 的龍頭陣列與長度為 $M$ 的勇士陣列進行排序，分別耗時 $\mathcal{O}(N \log N)$ 與 $\mathcal{O}(M \log M)$。後續的雙指標配對階段只需單層 `for` 迴圈橫向掃描一次勇士陣列，耗時僅為線性 $\mathcal{O}(M)$。題目規範 $N, M \le 20,000$，總體最大運算量約為 $6 \times 10^5$ 次，可在幾毫秒內極速通關。
* **空間複雜度**： $\mathcal{O}(N + M)$ <br>
  需要動態配置兩個 `std::vector` 陣列來儲存並維護原始的直徑與身高數據，空間開銷與輸入規模呈線性正比。


## 邊界條件與潛在陷阱

1. **勇士人數少於惡龍頭數（鴿籠無解邊界）**：<br>
   原程式碼在一開始就加入了 `if (n > m)` 的攔截機制。這項常數時間的剪枝非常優秀，它避免了後續對不對稱陣列進行無謂的排序與迴圈比對，大幅提升了程式的防禦性。
2. **所有勇士都派上場仍無法砍完（戰力不足邊界）**：<br>
   若勇士人數足夠（例如 $N=2, M=2$），但身高都太矮（龍頭 `5 5`，勇士 `2 2`）。排序後迴圈內部的 `k[i] >= d[head]` 將永遠無法成立，指標 `head` 會始終保持為 0。最後會精確觸發 `if (head == n)` 的無解判定分支，安全輸出 `Loowater is doomed!`，邏輯完全相容。
3. **終止符 0 0 的精確控制**：<br>
   最外層必須使用 `while (cin >> n >> m && (n != 0 || m != 0))` 進行精確控制。當讀到 0 0 時，利用邏輯與（`&&`）判定能安全跳出主迴圈，防止 0 進入內部引發空陣列配置錯誤。


## 程式碼實作

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n, m;
    // 連續讀入龍頭數 n 與勇士數 m，直到兩者皆為 0 時代表檔案流結束
    while (cin >> n >> m && (n != 0 || m != 0)) {
        
        // 核心剪枝：若勇士總人數根本不夠砍完所有龍頭，在現實中必定失敗
        if (n > m) {
            cout << "Loowater is doomed!\n";
            // 核心防禦：在此必須將後續該組測資殘留的數據全數吃掉，防止測資流錯位
            int garbage;
            for (int i = 0; i < n + m; i++) cin >> garbage;
            continue; 
        }
        
        vector<int> d(n); // 儲存惡龍頭的直徑
        for (int i = 0; i < n; i++) {
            cin >> d[i];
        }
        
        vector<int> k(m); // 儲存勇士的身高
        for (int i = 0; i < m; i++) {
            cin >> k[i];
        }
        
        // 貪婪前置核心：將兩組數列同時進行升序排序，使其具備雙單調有序性
        sort(d.begin(), d.end());
        sort(k.begin(), k.end());

        int head = 0; // 追蹤目前正準備被砍掉的「最小龍頭」的索引指標
        int cost = 0; // 金幣計費器
        
        // 橫向流式掃描所有勇士
        for (int i = 0; i < m; i++) {
            // 提早優化：若所有的惡龍頭都已經被砍光，直接中斷迴圈節省開銷
            if (head == n) break;
            
            // 貪婪配對：當前勇士的身高符合當前最小龍頭的擊殺門檻
            if (k[i] >= d[head]) {
                cost += k[i]; // 支付與該勇士身高完全等價的金幣
                head++;       // 該龍頭被成功消滅，指標向右推進
            }
            // 若身高不足，直接略過該勇士，將其戰力無成本拋棄
        }

        // 判定最終是否將所有龍頭全數斬盡
        if (head == n) {
            cout << cost << "\n";
        }
        else {
            cout << "Loowater is doomed!\n";
        }
    }
    return 0;
}
```


## 進階優化思考
原解法在雙指標配對的邏輯上非常乾淨漂亮，但在早期的 `if (n > m) continue;` 區塊中隱藏了一個資工極具代表性的「測資流錯位地雷」。

**數據流清除與防禦性程式設計（Data Flushing）**

* **地雷成因**：當外層偵測到 `n > m` 時，原程式碼直接執行了 `continue` 跳回 `while` 開頭去讀取下一組 Case。然而，此時輸入緩衝區中屬於當前 Case 的 $N$ 個直徑與 $M$ 個身高數據其實根本還沒被 `cin` 讀出來！這會導致下一輪的 `cin >> n >> m` 誤把原本應該是身高的數字當成了下一組 Case 的標頭，引發全域數據錯位，最終導致 Runtime Error 或 Wrong Answer。

* **修正方案**：如實作程式碼所示，在 `continue` 之前，必須使用一個輕量迴圈調用 `cin >> garbage;`，強迫把緩衝區中屬於該無解 Case 的後續所有數據全數「沖刷（Flush）」乾淨，才能安全跳轉。

**空間換時間的計數排序優化（Counting Sort 策略）**

如果題目給定的勇士身高與龍頭直徑的範圍非常小（例如數值均不超過 10,000），我們可以完全拋棄 $\mathcal{O}(M \log M)$ 的比較類排序，改用更高級的計數排序（Counting Sort）。

* **作法**：直接宣告一個全域的一維直方圖陣列 `int hero_counts[10005] = {0};`，在讀入勇士身高時直接在對應的下標位置進行 `++` 累加。

* **效能改善**：後續只需要從 1 到 10,000 橫向掃描一次身高直方圖，就能自動以完全有序且完全零指針交換的代價完成配對。這能將整體演算法的時間複雜度進一步推進到完美的絕對線性 $\mathcal{O}(N + M + \mathit{MAX\_VAL})$ ，是應對超大規模特定範圍數據時最頂級的調優手段。
