# UVa 1121 - Subsequence

## 題目簡述

給定一個含有 $N$ 個正整數的序列，以及一個正整數 $S$。<br>
請在序列中找到一個**連續子序列**（Subsequence / Subarray），使得該子序列內的所有元素之和**大於或等於 $S$**（ $\sum a_i \ge S$ ）。<br>
求滿足上述條件的連續子序列中，**最短的長度**是多少？若遍歷整個序列後發現所有元素總和仍小於 $S$，則輸出 0。

**Sample Input**：

  **10 15** $\rightarrow$ 序列長度 $N = 10$，目標連續和臨界值 $S = 15$。<br>
  **5 1 3 5 10 7 4 9 2 8** $\rightarrow$ 序列的實體內容。<br>
  **5 11** $\rightarrow$ 第二組測資，$N = 5, S = 11$。<br>
  **1 2 3 4 5**

**Sample Output**：

  **2** $\rightarrow$ 第一組最優連續區間為 [10, 7]，其和為 $17 \ge 15$，長度為 2。<br>
  **3** $\rightarrow$ 第二組最優連續區間為 [3, 4, 5]，其和為 $12 \ge 11$，長度為 3。


## 解題思路與滑動窗口

### 核心觀念：雙指標與滑動窗口（Sliding Window / Two Pointers）
這道題目的本質是**單調性區間的最值尋找**。如果採用雙層迴圈的暴力枚舉法，時間複雜度會退化到 $\mathcal{O}(N^2)$，在 $N = 100,000$ 的大測資規格下會直接超時。

由於序列中所有的數字**皆為正整數**，這代表著當右邊界向右擴張時，區間和必然單調遞增；當左邊界向右縮收時，區間和必然單調遞減。利用此單調性質，可以使用「滑動窗口」演算法：

1. **右指針擴張**：使用 `right` 迴圈逐一將新元素加入 `sum`，相當於將窗口右側不斷向右拉伸。
2. **左指針收縮與最佳化**：當窗口內的 `sum >= s` 成立時，代表當前區間已是一個合法解。此時執行以下動作：
   * 滾動更新最小長度：`d = min(d, right - left + 1)`。
   * 將窗口左側元素移出：`sum -= a[left]`，隨後 `left++`。
   * 重複檢查 `sum >= s` 是否依然成立，藉此將窗口壓榨到極致最短。
3. **終止與防禦**：當 `right` 抵達序列末尾且窗口無法再收縮時，計算結束。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N)$
  雖然程式碼外層有一個 `for` 迴圈（`right`），內層帶有一個 `while` 迴圈（`left`），但仔細觀察可以發現，`right` 指針與 `left` 指針在整個執行過程中，都**各自只會從 0 走到 $N-1$ 一次**。序列中的每個元素最多只會被移入窗口一次、移出窗口一次，因此總體時間複雜度為最優的線性時間。
* **空間複雜度**： $\mathcal{O}(N)$
  需要動態配置一個大小為 $N$ 的 `vector<int> a` 陣列來儲存序列的原始數值，空間開銷與輸入序列長度呈線性正比。


## 邊界條件與潛在陷阱 (Edge & Corner Cases)

1. **初始極值設定**：
   原程式碼將最短長度初始值設定為 `int d = 100000;`。雖然在此題目的輸入規模 $N \le 100,000$ 下剛好能過關，但這在工程設計上是一個危險的壞習慣（魔術數字）。如果題目將 $N$ 的上限放大到 $200,000$，這個初始化值就會失效。**更強健的作法是將初始極值設為 `N + 1` 或 `INT_MAX`**。
2. **完全無解的情況**：
   若整個序列的所有元素相加依然小於 $S$，則內層的 `while(sum >= s)` 永遠不會被觸發，`d` 會保持原始的初始值。最後必須透過 `if (d == 初始值)` 來捕捉這個狀態並輸出 `0`。
3. **單一元素即滿足條件（ $a_i \ge S$）**：
   若序列中存在某個數字自己本身就大於等於 $S$（例如 $S = 15$，序列中有一個數字為 20）。此時當 `right` 走到該點時，`while` 迴圈會立刻作動，將區間長度精確更新為 `right - left + 1 = 1`，隨後左指針前進。此雙指標架構能完美兼顧各種區間長度的極端狀況。


## 程式碼實作

以下為將原程式碼中的魔術數字進行強健性優化，並加入標準 I/O 加速後的正確實作版本：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n, s;
    // 連續讀入序列長度 n 與目標臨界值 s，直到檔案結束 (EOF)
    while (cin >> n >> s) {
        vector<int> a(n);
        for (int i = 0; i < n; i++) {
            cin >> a[i];
        }
        
        // 核心改進：將初始極值設為 n + 1 (即不可能達到的最大長度)，取代寫死的 100000
        int min_len = n + 1; 
        int left = 0;
        int sum = 0;
        
        // 滑動窗口右指針持續擴張
        for (int right = 0; right < n; right++) {
            sum += a[right]; // 累加當前右端元素
            
            // 當前窗口總和滿足大於等於目標 S 時，啟動左端收縮與極值更新機制
            while (sum >= s) {
                min_len = min(min_len, (right - left + 1)); // 更新目前找到的最短長度
                sum -= a[left]; // 將最左端元素移出窗口
                left++;         // 左指針向右縮減窗口
            }
        }
        
        // 最終判定：若長度標記仍為初始值，代表整個數列之和皆無法達到 S
        if (min_len == n + 1) {
            cout << "0\n";
        }
        else {
            cout << min_len << "\n";
        }
    }
    return 0;
}
```


## 進階優化思考
除了滑動窗口演算法之外，這道題目在資工思維中還存在另外一種經典的演算法設計，尤其當序列中包含負數（導致滑動窗口的單調性失效）時，就必須被迫改用該方法。

**延伸方法：前綴和與二分搜尋法（Prefix Sum & Binary Search）**

* **原理**：由於元素皆為正數，我們可以預處理出一個「前綴和陣列（Prefix Sum）」prefix[i]，代表前 $i$ 個元素的加總。因為元素為正，前綴和陣列必然是一個嚴格遞增的有序數列。

* **做法**：遍歷前綴和陣列中的每個起點 prefix[i]，若要尋找連續和 $\ge S$ 的終點，等價於要在右側的有序前綴和中，尋找第一個大於或等於 prefix[i] + S 的值。此時可以直接調用 std::lower_bound 二分搜尋。

* **效能對比**：此方法的時間複雜度為 $\mathcal{O}(N \log N)$。雖然在純正數序列下效率略輸滑動窗口的 $\mathcal{O}(N)$，但前綴和的抽象結構具備極高的擴充性，是解決區間和衍生考題時非常核心的必備工具。
