# UVa 1062 - Containers

## 題目簡述

有一艘貨櫃船即將進港，貨櫃會按照特定的字串順序一個個送達。每個貨櫃都用一個大寫英文字母（`A` 到 `Z`）來代表其種類與卸貨順序。
港口內部可以開闢多個垂直堆疊的「貨櫃堆（Stacks）」。當一個新貨櫃送達時，必須將其放到現有的某個貨櫃堆的最上方，或者為它開闢一個全新獨立的貨櫃堆。
**核心限制**：在隨後把貨櫃搬上船時，字母較小的貨櫃必須先被搬走。這代表**任何現有的貨櫃堆中，絕對不能發生「字母較大的貨櫃壓在字母較小的貨櫃上方」的情況**。
請計算出在最聰明的分配策略下，最少需要開闢多少個貨櫃堆，才能成功容納所有依序送達的貨櫃？

**Sample Input**：

  **A** $\rightarrow$ 第一組字串，只有一個貨櫃。<br>
  **CBACBA** $\rightarrow$ 第二組字串。<br>
  **cccc** $\rightarrow$ 第三組字串（實際題目皆為大寫字串，此處沿用原輸入結構）。<br>
  **end** $\rightarrow$ 當讀取到字串為 "end" 時，代表整個輸入結束。

**Sample Output**：

  **Case 1: 1** $\rightarrow$ 只有 A，只需 1 個貨櫃堆。<br>
  **Case 2: 3** $\rightarrow$ 最優解為開闢三個堆疊，依序將相同字母疊在一起，最終大小為 3。<br>
  **Case 3: 1**


## 解題思路與貪婪策略

### 核心觀念：最接近上界的貪婪分配法（Greedy Algorithm）
這道題目的本質是**經典的貪婪演算法與堆疊維護問題**（其數學模型也與 Dilworth 定理及尋找「最長遞增子序列 LIS」的 Patience Sorting 撲克牌演算法完全同構）。

為了讓總貨櫃堆的數量維持最少，每當一個新貨櫃 `s[i]` 抵達時，必須遵循以下貪婪決策原則：
1. **尋找可行堆疊**：遍歷目前所有已開闢的貨櫃堆，找出哪些堆疊的頂端字母**大於或等於**當前貨櫃 `s[i]`。若符合，代表當前貨櫃可以安全地疊在它上方，而不會違反「大不壓小」的規則。
2. **最優選擇（最接近上界）**：在所有可行的堆疊中，應該挑選那個 **頂端字母最小（也就是最接近 `s[i]`）** 的堆疊。這樣做能把字母更大的堆疊空間保留給未來可能出現的更大貨櫃，實現空間利用率的最大化。
3. **開闢新堆疊**：如果目前所有堆疊的頂端字母都小於 `s[i]`，代表沒有任何地方放得下它。此時沒有選擇，必須強迫在碼頭開闢一個全新的貨櫃堆，並將 `s[i]` 作為該堆疊的初始底部。

### 演算法步驟
1. 利用 `while (cin >> s && s != "end")` 讀取貨櫃抵達序列，並利用 `count` 維持 Case 編號。
2. 宣告一個 `vector<char> stack` 陣列。在這個陣列中，每個元素 `stack[j]` 僅用來儲存第 `j` 個貨櫃堆**當前最頂端的字元**。
3. 遍歷字串中的每個字元 `s[i]`：
   * 在第一步 `i == 0` 時，直接開闢第一個堆疊：`stack.push_back(s[0])`。
   * 對於後續字元，初始化 `which = -1` 與最優頂端值 `suitable = 'Z' + 1`。
   * 走訪 `stack` 陣列，若 `s[i] <= stack[j]` 且 `stack[j] < suitable`，則更新 `suitable = stack[j]` 並紀錄索引 `which = j`。
   * 遍歷完畢後，若 `which != -1`，直接更新該堆疊頂端：`stack[which] = s[i]`；否則，代表無處可放，配置新堆：`stack.push_back(s[i])`。
4. 最終，`stack.size()` 的長度即為該組 Case 的最少貨櫃堆數量。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \times M)$
  其中 $N$ 為字串的長度（貨櫃總數）， $M$ 為最終開闢的貨櫃堆數量。在最差情況下（字串完全嚴格遞增，如 `ABCDE`），每個字櫃都需要開闢新堆，此時 $M = N$，總比對次數為 $\frac{N(N+1)}{2}$，複雜度退化至 $\mathcal{O}(N^2)$ 。題目限制字串長度 $N \le 1000$ ，最大運算次數不超過 $10^6$ 次，可在幾毫秒內極速通過。
* **空間複雜度**： $\mathcal{O}(M)$
  需要一個 `vector<char> stack` 陣列來儲存每個貨櫃堆的頂端字母。由於大寫英文字母最多只有 26 種，即便字串極長，獨立的堆疊數量上限也絕對**不可能超過 26 個**。因此空間複雜度實質上為極小的固定常數 $\mathcal{O}(1)$ 。


## 邊界條件與潛在陷阱

1. **堆疊數量上限的數學定理（26 的絕對天花板）**：
   因為任何一個堆疊在更新頂端字母時，頂端值只會變得越來越小（例如從 `'K'` 變成 `'C'`）。如果出現了第 27 個貨櫃，依據鴿籠原理，它必然可以疊在現有 26 個字母中的某個大於等於它的字母上方。因此，**`stack` 陣列的最大長度絕對不可能超過 26**。原程式碼中的雙層迴圈在實務執行時，內層迴圈最多只會跑 26 次，效率極高。
2. **完全重複字串**：
   若輸入全為相同字母（如 Sample 3 中的 `cccc`），在第一步配置完 `stack[0] = 'C'` 後，後續的每個字母都會落入 `s[i] <= stack[j]` 的條件中，並精確覆蓋 `stack[0]`。最終大小保持為 1，邏輯完全正確。
3. **字串第 0 位的重複配置盲點**：
   原程式碼中有一行 `if (i == 0) stack.push_back(s[i]);`。這行在第 0 步時正確配置了第一個堆疊。然而，因為後續沒有加上 `continue`，程式會**繼續向下執行下方的比對迴圈**。在第 0 步時，下方迴圈內層會偵測到 `s[0] <= stack[0]` 成立，進而又執行了一次 `stack[0] = s[0]`。雖然這屬於冗餘計算，但在數值結果上完全不影響正確性，仍能順利拿到 Accepted (AC)。


## 程式碼實作

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    string s;
    int count = 1;
    
    // 持續讀入字串，直到讀取到 "end" 時終止程式
    while (cin >> s && s != "end") {
        
        // 陣列的每個元素代表一個獨立貨櫃堆「當前最頂端」的字母
        vector<char> containers_stack;
        
        for (int i = 0; i < (int)s.size(); i++) {
            // 在處理第一個貨櫃時，強迫開闢第一個獨立貨櫃堆
            if (i == 0) {
                containers_stack.push_back(s[i]);
                continue; // 優化補強：提早跳過當前輪的後續冗餘計算
            }
            
            int which = -1;
            int suitable = 'Z' + 1; // 初始化為超出大寫字母範圍的極大值
            
            // 遍歷現有的所有貨櫃堆頂端，尋找符合「大不壓小」且最接近當前字母的堆疊
            for (int j = 0; j < (int)containers_stack.size(); j++) {
                if (s[i] <= containers_stack[j]) {
                    // 貪婪核心：挑選頂端字母最小（最接近 s[i]）的那個堆疊
                    if (containers_stack[j] < suitable) {
                        suitable = containers_stack[j];
                        which = j;
                    }
                }
            }
            
            // 若找到合法的現成堆疊，則直接疊在該堆疊最上方（更新頂端字母）
            if (which != -1) {
                containers_stack[which] = s[i];
            }
            // 若所有現有堆疊的頂端字母都小於 s[i]，則必須開闢全新貨櫃堆
            else {
                containers_stack.push_back(s[i]);
            }
        }
        
        // 嚴格依照題目規範格式輸出
        cout << "Case " << count++ << ": " << containers_stack.size() << "\n";
    }
    return 0;
}
```


## 進階優化思考

原做法的時間複雜度 $\mathcal{O}(N \times M)$ 在最大長度 1000 且 $M \le 26$ 的條件下，實質上已經是極快的 $\mathcal{O}(26N)$ 線性時間。但如果從高階資料結構的視角出發，這題存在一個利用標準庫二分搜尋將程式碼精簡至極致的重構手段。

**利用 std::upper_bound 進行二分搜尋優化**

* **幾何特性**：根據我們的貪婪分配策略，當新貨櫃放不下時，我們才會在右側開闢新堆疊；而當放得下時，我們會選擇最左側第一個大於或等於 s[i] 的元素並更新它。這個運作模式會使得 containers_stack 陣列在整個維護過程中，天生就具備嚴格遞增的有序性（字母從左到右越來越大）。

* **做法**：既然陣列是有序的，我們不需要用 for 迴圈大費周章去尋找 suitable。可以直接調用 C++ 標準庫的 std::upper_bound（在數值完全相同時，由於要求是大於或等於，對於相同的字母可以直接疊在上面，因此實務上利用 std::lower_bound 鎖定第一個大於等於它的元素即可）。

* **效能改善**：此重構版本將單次尋找的代價從 $\mathcal{O}(M)$ 直接降到了對數時間 $\mathcal{O}(\log M)$（由於 $M \le 26$ ， $\log_2 26 \approx 4.7$ 次比對）。更重要的是，它完全省去了手動維護 suitable 與 which 的繁瑣代碼，大幅提升了程式結構的強健性與優雅度。

**優化程式碼片段：**
```cpp
vector<char> v;
for (char c : s) {
    // 在有序陣列中，利用二分搜尋在 O(log M) 內直接找出第一個大於或等於 c 的位置
    auto it = lower_bound(v.begin(), v.end(), c);
    
    if (it != v.end()) {
        *it = c; // 找到現成堆疊，直接更新頂端
    } else {
        v.push_back(c); // 找不到，在最右側配置新堆疊
    }
}
cout << "Case " << count++ << ": " << v.size() << "\n";
```
