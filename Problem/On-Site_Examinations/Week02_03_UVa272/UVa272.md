# UVa 272 - TEX Quotes

## 題目簡述

在排版軟體 $\text{T}_{\text{E}}\text{X}$ 中，雙引號有特殊的呈現方式，標準的雙引號 `"` 必須被交替替換：
* 第一次（奇數次）出現的雙引號 `"` 轉換為兩個反單引號（左引號）：` `` `
* 第二次（偶數次）出現的雙引號 `"` 轉換為兩個正單引號（右引號）：`''`

其餘字元（包含空白與換行）原樣輸出。

**Sample Input**：

  **"To be or not to be," quoth the Bard, "that** <br>
  **is the question".** <br>
  **The programming contestant replied: "I must disagree.** <br>
  **To \`C' or not to \`C', that is The Question!"**

**Sample Output**：

  **\`\`To be or not to be,'' quoth the Bard, \`\`that** <br>
  **is the question''.** <br>
  **The programming contestant replied: ``I must disagree.** <br>
  **To \`C' or not to \`C', that is The Question!''**


## 解題思路與狀態機模型

### 核心觀念：有限狀態機（Finite State Machine, FSM）
這道題目的本質是典型的**狀態二元切換**。我們可以將程式視為一個只有兩種狀態的微型狀態機：
1. **狀態 A（尋找左引號）**：當遇到 `"` 時，將其替換為 ` `` `，並切換到狀態 B。
2. **狀態 B（尋找右引號）**：當遇到 `"` 時，將其替換為 `''`，並切換回狀態 A。

因為狀態會跨行延續（前一行的左引號可能到下一行才配對到右引號），所以用來記錄狀態的變數必須放在主迴圈外部，不可每讀取新的一行就重設。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N)$
  其中 $N$ 為輸入檔案的總字元數。不論是使用 `getline` 讀取整行再遍歷，或是使用 `cin.get()` 逐字元讀取，每個字元都剛好被檢查與處理一次，時間複雜度達到理論最佳的線性時間。
* **空間複雜度**： $\mathcal{O}(1)$ 
  * **字元版**：僅需一個 `char` 變數空間，空間複雜度為絕對常數 $\mathcal{O}(1)$。
  * **字串版**：需要一個 `string` 儲存當前行的字串。若單行長度為 $L$，空間複雜度為 $\mathcal{O}(L)$。在記憶體極限優化考量下，字元版表現更佳。


## 邊界條件與潛在陷阱 (Edge & Corner Cases)

1. **跨行配對陷阱（Cross-line Quotes）**：
   段落中的左引號 `"` 出現在第一行末尾，而對應的右引號 `"` 出現在第二行開頭。在實作時，**狀態紀錄變數 `count` 必須宣告在 `while` 迴圈之外**，才能確保跨行時狀態不丟失。
2. **空白與換行字元保留**：
   標準的 `cin >> text` 會自動跳過空白、製表符（Tab）與換行符。因此必須使用 `cin.get(text)` 或 `getline(cin, text)` 才能完整保留原始文本的排版結構。
3. **跳脫字元與反單引號**：
   測資中可能本身就包含反單引號（如 Sample 中的 \`C'），但題目說明「除了雙引號外，其餘字元原樣輸出」，因此直接印出即可，不需做任何特殊轉義處理。


## 程式碼實作

### 方法一：字串處理版 (`getline`)
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    string text;
    int count = 0; // 記錄雙引號出現的次數狀態 (0 為偶數次，1 為奇數次)
    
    while (getline(cin, text)) {
        for (int i = 0; i < text.length(); i++) {
            if (text[i] == '"') {
                count = (count + 1) % 2;
                if (count == 1) {
                    cout << "``";
                } else {
                    cout << "''";
                }
            } else {
                cout << text[i];
            }
        }
        cout << "\n"; // getline 會吃掉換行符，故需手動補回（\n 效能優於 endl）
    }
    return 0;
}
```

### 方法二：逐字元處理版 (cin.get) - 不需動態配置字串記憶體且程式碼極簡，更推薦!
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    char ch;
    bool is_left = true; // 使用布林值取代整數模運算，語意更清晰
    
    // cin.get(ch) 可完整讀取包含空白與換行在內的任意字元
    while (cin.get(ch)) {
        if (ch == '"') {
            if (is_left) {
                cout << "``";
            } else {
                cout << "''";
            }
            is_left = !is_left; // 切換狀態
        } else {
            cout << ch;
        }
    }
    return 0;
}
```


## 進階優化思考

1. **狀態變數優化**
原程式碼使用 count = (count + 1) % 2; 來做二元切換。在計算機底層中，模運算（%）的開銷比邏輯運算大。
我們可以用布林旗標（bool）配合邏輯非運算（!）來優化：
```cpp
is_left = !is_left;
```
這不僅在底層執行速度更快（直接進行位元或邏輯取反），在程式碼語意上也更直觀。

2. **字元版與字串版的效能抉擇**
* `getline` 版本會在記憶體中開闢空間存放整行字串，若遇到極端巨大的單行文本，可能會造成記憶體局部負擔。
* `cin.get()` 則是建立一個緩衝流，逐個字元邊讀邊輸出，省去了字串拼接與長度計算，在處理大量文字檔案時效率較高。
