# UVa 11286 - Conformity

## 題目簡述

有很多大學生在選課，每位學生都必須精確選擇 5 門課程。每門課程都由一個獨一無二的課程代碼（正整數）來代表。
我們認為，如果兩位學生選擇的 5 門課程組合完全相同（不計較選課的先後填寫順序），那麼他們就屬於同一個「受歡迎組合」的陣營。
請幫忙統計出，**哪些組合是最受歡迎的組合（選取人數最多）**？並計算出**所有選擇了「最受歡迎組合」的學生總人數**。

當輸入的學生總數 $N = 0$ 時，代表輸入結束。

**Sample Input**：

  **3** $\rightarrow$ 第一組測試資料，共有 $N = 3$ 位學生。<br>
  **100 101 102 103 104** $\rightarrow$ 第一位學生選的 5 門課。<br>
  **104 103 102 101 100** $\rightarrow$ 第二位學生選的 5 門課（與第一位完全相同）。<br>
  **100 101 102 103 105** $\rightarrow$ 第三位學生選的 5 門課（另一種組合）。<br>
  **0** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **2** $\rightarrow$ 最熱門組合的選取人數為 2。共有 1 組熱門組合，故總人數為 $2 \times 1 = 2$。


## 解題思路與關聯式容器

### 核心觀念：排序去重與雜湊/關聯式映射計數（Map / Sorting）
這道題目的本質是**多維組合的頻率統計與全域最大值篩選**。
題目明確指出了「不計較選課順序」，這代表 `100 101 102 103 104` 與 `104 103 102 101 100` 在物理語意上是完全等價的。

為了讓相同組合能夠在程式中被歸類到同一個鍵（Key）上，我們需要對資料進行「標準化」預處理：
1. **序列標準化（Normalization）**：每讀入一位學生的 5 門課，先使用 `std::sort` 將這 5 個數字進行升序排序。如此一來，只要選課內容相同的學生，排序後的 `vector<int>` 內容就會完全一模一樣。
2. **組合計數（Frequency Mapping）**：利用 C++ 的關聯式容器 `std::map<vector<int>, int>`，將排序好的選課 `vector` 當作 Key，出現次數當作 Value。每當遇到相同的組合，就執行 `list[student]++`，並同步用 `most` 變數滾動更新當前的「最大熱門人數」。
3. **全域人數加總**：遍歷整個 `map`，只要發現某個組合的出現次數（`it.second`）剛好等於最高紀錄 `most`，就把這個次數累加到 `total` 中。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \times K \log K + N \log N)$
  其中 $N$ 為學生人數，$K$ 為選課數（固定為 5）。對於每位學生，排序 5 門課耗時 $5 \log 5$（常數時間）。隨後將 `vector` 插入 `std::map` 中，由於 `std::map` 底層是紅黑樹結構，單次插入與比對的代價為 $\mathcal{O}(\log N \times 5)$。因此，總體時間複雜度在平攤後為 $\mathcal{O}(N \log N)$。在題目給定的最大規模 $N \le 10,000$ 下，總比對次數在 $1.4 \times 10^5$ 左右，可在幾毫秒內極速通關。
* **空間複雜度**：$\mathcal{O}(N \times K)$
  `std::map` 中最多會儲存 $N$ 個相異的選課組合，每個組合包含 5 個 `int` 空間，空間開銷與學生總數呈線性正比。


## 邊界條件與潛在陷阱

1. **多個選課組合並列最熱門（並列第一地雷）**：
   這是本題最經典的 Wrong Answer 陷阱。最受歡迎的組合**可能不只一組**（例如：有兩組不同的選課組合，各自都有 3 位學生選擇，此時 `most = 3`）。

   * **錯誤邏輯**：直接輸出 `most`。
   * **正確邏輯**：題目要求輸出的是「選擇了最受歡迎組合的學生**總人數**」。既然有兩組組合並列第一，總人數就應該是 $3 + 3 = 6$ 人。原程式碼最後透過 `for` 迴圈檢查 `if (it.second == most) total += it.second;` 的累加設計，完全清除了這個潛在陷阱。
3. **全域變數清空與多組測資獨立性**：
   由於 UVa 是流式多組測資讀取，`map<vector<int>, int> list` 以及計數變數 `most`, `total` 必須宣告在 `while(cin >> n)` 迴圈的**內部**。這樣能確保每組新 Case 開始時，舊的數據緩衝會被徹底釋放清空，不會引發跨測資的數據污染。


## 程式碼實作

```cpp
#include <iostream>
#include <map>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n;
    // 連續讀入學生總數 n，當 n = 0 時安全結束程式
    while (cin >> n && n != 0) {
        int most = 0; // 紀錄單一組合出現的最高次數
        
        // 宣告紅黑樹關聯式容器，C++ 的 map 天然支援將 vector 當作 Key
        map<vector<int>, int> course_map;
        
        while (n--) {
            vector<int> student(5);
            for (int i = 0; i < 5; i++) {
                cin >> student[i];
            }
            
            // 核心步驟：將選課代碼升序排序，抹除填寫順序的差異
            sort(student.begin(), student.end());
            
            // 將標準化後的組合推入 map 進行計數
            course_map[student]++;
            
            // 動態更新全域最高人氣組合的人數
            most = max(most, course_map[student]);
        }
        
        int total_students = 0;
        // 走訪 map 中的所有組合紀錄 (it.first 為選課組合, it.second 為選擇人數)
        for (auto const& it : course_map) {
            // 只要當前組合的人數等於最高紀錄，就將人數全數累加
            if (it.second == most) {
                total_students += it.second;
            }
        }
        
        // 輸出符合熱門陣列的總學生人數
        cout << total_students << "\n";
    }
    return 0;
}
```


## 進階優化思考

雖然使用基於紅黑樹（平衡二元搜尋樹）的 `std::map` 在複雜度上已完全足夠，但在資工的高階記憶體與常數時間調優視角下，這題存在著另外兩種效能更卓越的進階寫法。

**方法一：改用雜湊映射（std::unordered_map）**

* **原理**： `std::map` 的查詢與插入耗時 $\mathcal{O}(\log N)$。如果改用基於雜湊表（Hash Table）的 `std::unordered_map` ，其尋找與插入的平攤時間複雜度能直接降到常數時間 $\mathcal{O}(1)$。

* **技術注意點**：由於 C++ 標準庫內部並未內建針對 `std::vector<int>` 的雜湊函數（Hash Function），如果想使用 `unordered_map` ，必須手動撰寫自定義的雜湊結構（如將 5 個課程代碼組合成一個唯一的 `string` ，或利用 `boost::hash_combine` 進行自訂雜湊），雖然語法較為繁瑣，但能換來更高的極速體驗。

**方法二：自定義字串映射（String-Key Mapping）**

* **做法**：在讀入 5 個選課數字並排序好後，不使用 vector 封裝，而是直接利用 `to_string()` 將這 5 個數字用特定的分隔符號（如底線）拼接成一個唯一的字串 Key（例如 `"100_101_102_103_104"` ）。

* **優點**：因為 C++ 標準庫對 `std::string` 內建了完美的雜湊支援。這樣做能直接套用 `unordered_map<string, int>` ，在免去繁瑣語法的同時，完美享受雜湊表帶來的全域 $\mathcal{O}(1)$ 常數時間壓制。
