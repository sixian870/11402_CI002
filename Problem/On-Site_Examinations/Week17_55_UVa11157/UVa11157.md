# UVa 11157 - Dynamic Frog

## 題目簡述

一隻青蛙想要跨越一條寬度為 $D$ 的河。河上有 $N$ 個石頭排成一線，每個石頭都有給定的座標，並且分為兩種：
1. **大石頭（Big Stones，以 'B' 表示）**：可以被踩無限次，且不會沉沒。
2. **小石頭（Small Stones，以 'S' 表示）**：被踩過一次之後就會沉入水中，無法再被踩第二次。

青蛙必須從左岸（座標 0）跳到右岸（座標 $D$），接著再從右岸**游/跳回**左岸。在來回的過程中，為了確保安全，青蛙希望**單次跳躍的最大距離（Max Leap）越小越好**。

請計算出在最優的來回跳躍策略下，青蛙所需的最小單次跳躍最大距離。

**Sample Input**：

  **3** $\rightarrow$ 共有 3 組測試資料。<br>
  **1 10** $\rightarrow$ 第一組：共有 1 個石頭，河寬為 10。<br>
  **B-5** $\rightarrow$ 石頭型態為大石頭，座標在 5。<br>
  **2 10** $\rightarrow$ 第二組：共有 2 個石頭，河寬為 10。<br>
  **S-2 S-7** $\rightarrow$ 座標 2 與 7 皆為小石頭。

**Sample Output**：

  **Case 1: 5** $\rightarrow$ 去程 0 -> 5 -> 10，回程 10 -> 5 -> 0，最大跳躍距離為 5。<br>
  **Case 2: 7** $\rightarrow$ 最優解為去程踩 S-2（0 -> 2 -> 10，最大跳 8？不，最優是去程 0 -> 7 -> 10，回程 10 -> 2 -> 0，最大跳為 7）。


## 解題思路與貪婪策略分析

### 核心觀念：首尾雙向對稱卡位與貪婪跳躍（Greedy Spacing Technique）
這道題目的本質是**貪婪演算法與序列分流優化**。

我們可以把去程與回程的路線，想像成「兩隻青蛙同時從左岸出發跳到右岸」，且兩隻青蛙走不同的路線。
* 對於**大石頭（B）**：兩隻青蛙都可以踩它，所以大石頭在去程與回程的路線中都可以被納入。
* 對於**小石頭（S）**：因為只能被踩一次，所以這兩隻青蛙必須**交替輪流踩**（例如：第一隻踩、第二隻不踩；接下來下一個小石頭由第二隻踩、第一隻不踩）。

為了讓兩條路線的「最大跨度」都盡可能地小，最均勻的分配方式就是將石頭序列展開，大石頭複製兩份（供兩隻青蛙各踩一次），小石頭只保留一份。此時，每一隻青蛙在面對連續的小石頭時，最優策略就是**隔一個跳一個**。

### 演算法步驟
1. 建立一個陣列 `pos`，並在起點放入兩個 `0`（代表去程與回程的起點都在左岸）。
2. 依序讀入石頭資訊。若是大石頭 `B`，因為可以踩無限次，我們就在 `pos` 中**連續推入兩次該座標**；若是小石頭 `S`，則只推入一次。
3. 在終點放入兩個 `D`（代表兩條路線的終點都在右岸）。
4. 既然每條路線都是「隔一個物件跳一次」，那麼對於任何一個位置 $i$，其下一站必定是 $i+2$。我們只需遍歷整個陣列，動態更新 `max_leap = max(max_leap, pos[i+2] - pos[i])` 即可找出答案。


## 複雜度分析

* **時間 Complexity**： $\mathcal{O}(N)$ <br>
  每組測試資料中，我們只需線性讀入 $N$ 個石頭。字串解析與陣列推入皆為 $\mathcal{O}(1)$。最後計算最大跳躍跨度時，只需要一條單層 `for` 迴圈掃描長度約為 $2N$ 的陣列。整體時間複雜度與石頭數量 $N$ 呈完全的線性正比，可在幾毫秒內極速通過。
* **空間 Complexity**： $\mathcal{O}(N)$ <br>
  動態陣列 `pos` 的最大長度不超過 $2N + 4$，記憶體開銷極小且與 $N$ 呈線性相關。


## 邊界條件與潛在陷阱

1. **大石頭與端點的雙重卡位（Endpoint Replication）**：<br>
   在起點（0）與終點（D），不論有沒有石頭，兩條路線都必須匯合在岸上。因此在陣列的首尾，我們必須手動、強制推入兩次 `0` 與兩次 `D`。這項機制能完美與中間「隔項跳躍 `pos[i+2] - pos[i]`」的代數模型完全對齊，不需要額外撰寫複雜的端點特判邏輯。
2. **數值解析細節（String Parsing）**：<br>
   輸入格式如 `B-5` 或 `S-100`。解析時利用 `stone.substr(2)` 擷取第二個字元以後的子字串，並透過 `stoll`（Stream to Long Long）將其轉化為數值。由於座標數字可能較大，使用 `long long` 承載可以完全杜絕潛在的整數溢位風險。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int T;
    if (!(cin >> T)) return 0;

    for (int t = 1; t <= T; ++t) {
        int N;
        long long D;
        cin >> N >> D;

        // 核心資料結構：存放所有有效落腳點的橫座標
        vector<long long> pos;
        
        // 邊界防禦：左岸起點可以被無限次使用，故推入兩個 0 供來回兩條路線使用
        pos.push_back(0);
        pos.push_back(0);

        for (int i = 0; i < N; ++i) {
            string stone;
            cin >> stone;
            
            // 解析字串，將 "B-5" 或 "S-12" 後半段的數字提取出來
            long long m = stoll(stone.substr(2));
            
            // 貪婪分流邏輯
            if (stone[0] == 'B') {
                // 大石頭可以踩無限次，等同於來回兩條路線都能踩，故推入兩次
                pos.push_back(m);
                pos.push_back(m);
            } else {
                // 小石頭只能踩一次，分流給其中一條路線，故只推入一次
                pos.push_back(m);
            }
        }

        // 邊界防禦：右岸終點同樣可以被無限次使用，故推入兩個 D
        pos.push_back(D);
        pos.push_back(D);

        long long max_leap = 0;
        
        // 由於兩條路線在最優分配下都是交替前進（隔項跳躍）
        // 任意落腳點 pos[i] 的下一站必然是 pos[i+2]
        for (size_t i = 0; i < pos.size() - 2; ++i) {
            max_leap = max(max_leap, pos[i+2] - pos[i]);
        }
        
        // 嚴格依照題目格式要求進行輸出
        cout << "Case " << t << ": " << max_leap << "\n";
    }
    return 0;
}
```


## 進階優化思考

**記憶體就地複用與快取行優化（Cache Line Tuning）**

雖然目前的實作在空間開銷上已經極低，但在高併發、海量多組測資反覆輸入的極限競賽環境下，動態在 `for` 迴圈內部重複執行 `vector<long long> pos` 會導致作業系統反覆在 Heap 區塊上進行記憶體的申請與銷毀（Allocation/Deallocation），這會產生零碎的記憶體片段。

* **優化做法**：由於題目中 $N$ 的範圍通常很小（一般 $N \le 100$），我們可以在全域或者 `main` 函式開頭直接宣告一個固定長度為 250 的原生靜態陣列 `long long pos[250]`。

* **技術精髓**：在每輪讀入新數據前，直接利用一個整型變數 `int idx = 0` 作為指針來就地覆寫（In-place Overwrite）陣列內容，完全抹除了動態配置的負擔。更重要的是，連續 250 個 `long long` 的物理空間只有約 2KB，能完美一次性塞進 CPU 的 L1 快取行（Cache Line）中。在進行雙跨度遍歷時，所有資料存取皆在極速暫存器與核心快取內完工，能將底層常數級的執行效能壓榨至物理極限。
