# UVa 10359 - Tiling

## 題目簡述

給定一個大小為 $2 \times N$ 的矩形網格。我們需要用兩種長方形磁磚將其完全鋪滿：
* 第一種磁磚的大小為 $2 \times 1$。
* 第二種磁磚的大小為 $2 \times 2$。

請計算出對於給定的網格長度 $N$，總共有多少種**相異的磁磚鋪法（Ways）**？

**輸入規範**：
連續讀入長度 $N$（ $0 \le N \le 250$ ），直到檔案結束（EOF）。

**Sample Input**：

  **2** $\rightarrow$ 第一組網格長度 $N = 2$。<br>
  **8** $\rightarrow$ 第二組網格長度 $N = 8$。<br>
  **12**

**Sample Output**：

  **3** $\rightarrow$ 長度為 2 時共有 3 種排法。<br>
  **171**<br>
  **2731**


## 解題思路與狀態轉移

### 核心觀念：動態規劃與高維動態鋪磚（Dynamic Programming / Tiling）
這道題目是經典的**二維條帶鋪磚與動態規劃**問題。

為了求出長度為 $N$ 的網格總方法數 $f(N)$，我們可以從網格的「最右側邊界」是如何被磁磚封口的來進行分治推導：
1. **狀況一（結尾垂直放置 $2 \times 1$ 磁磚）**：<br>
   如果最右側是由一塊垂直擺放的 $2 \times 1$ 磁磚填滿，那麼左邊剩下的網格長度剛好是 $N - 1$。這種擺法的組合數等價於長度為 $N - 1$ 的鋪法，即 **$f(N - 1)$**。
2. **狀況二（結尾水平放置 $2 \times 1$ 磁磚）**：<br>
   如果最右側包含了水平擺放的磁磚，由於網格高度為 2，為了將高度完全填滿，**必須強制上下平行疊放兩塊 $2 \times 1$ 的水平磁磚**。這兩塊磁磚共佔據了 2 格長度，因此左邊剩下的網格長度為 $N - 2$。這種擺法的組合數等價於 **$f(N - 2)$**。
3. **狀況三（結尾放置 $2 \times 2$ 磁磚）**：<br>
   如果最右側是由一塊 $2 \times 2$ 的正方形磁磚填滿，它同樣佔據了 2 格長度，左邊剩下的網格長度也是 $N - 2$。這種擺法的組合數等價於 **$f(N - 2)$**。

由於狀況二與狀況三是完全獨立且平行的幾何事件，在結尾佔據 2 格長度的總方法數實際上共有 $2 \times f(N - 2)$ 種。
結合狀況一，我們可以推導出長度為 $N$ 的全域狀態轉移方程：
$$f(N) = f(N - 1) + 2 \times f(N - 2)$$

### 初始邊界臨界值
* $f(0) = 1$（長度為 0 視為一種空狀態鋪法，可用於轉移基準）
* $f(1) = 1$（只能垂直放一塊 $2 \times 1$ 磁磚）
* $f(2) = f(1) + 2 \times f(0) = 1 + 2 \times 1 = 3$（全垂 `||`、全平 `=`、一塊 `2x2`）
* $f(3) = f(2) + 2 \times f(1) = 3 + 2 \times 1 = 5$


## 複雜度分析

* **時間複雜度**：

  * **預處理大數建表**： $\mathcal{O}(N_{\text{max}} \times L)$ <br>
    其中 $N_{\text{max}} = 250$， $L$ 為大數的平均字串長度（在第 250 項時約為 76 位數）。利用大數加法函式進行 250 次線性轉移，每次字串處理耗時 $\mathcal{O}(L)$。總體預處理時間在幾毫秒內即可完成。
  * **線上查詢階段**： $\mathcal{O}(1)$ <br>
    由於在前期已將 0 到 250 的所有字串解答預先計算完畢，隨後面對任何 $N$ 的查詢，直接透過下標查表 `f[n]` 輸出即可，查詢的時間複雜度為絕對常數時間。
* **空間複雜度**： $\mathcal{O}(N_{\text{max}} \times L)$ <br>
  `std::vector<string> f(251)` 需要保留 251 個大數字串。最大長度約為 76 個字元，內存總開銷不超過 20 KB，空間配置極其精簡。


## 邊界條件與潛在陷阱

1. **超高維大數溢位陷阱（大數加法強烈必要性）**：<br>
   這是本題最核心的技術考點。轉移方程中包含了 $2 \times f(N-2)$ 的倍數增長，這使得數值的增長速度甚至超越了常規費氏數列。當 $N = 250$ 時，最終答案高達 76 位數，已經遠遠彈出了 C++ 內建的 `unsigned long long`（最大僅能容納約 20 位數，即 $1.8 \times 10^{19}$）所能承載的極限。
   * **程式碼防禦**：實作中手寫了 `stringAdd` 函式。利用 `std::string` 來模擬小學老師教的直式加法（模擬從個位數向高位數進位），這完全打破了硬體 64 位元暫存器的物理限制，能完美且安全地處理任意長度的超大型數字。
2. **大數兩倍算術轉換（`two_times` 的實作技巧）**：<br>
   在公式中需要計算 $2 \times f(i-2)$。原程式碼採用了非常聰明的做法：`stringAdd(f[i - 2], f[i - 2])`。**透過自己加自己來代替複雜的大數乘法**，將乘 2 轉換成了常規的大數加法，大幅簡化了代碼的實作難度，這是一個非常驚艷且強健的工程技巧。
3. **字串反轉對齊（`reverse` 的必要性）**：<br>
   在 `stringAdd` 中，因為是從個位數開始計算並依序追加到 `result` 尾端，算出來的字串會呈現顛倒狀態（例如 123 會變成 `"321"`）。在函式回傳前調用 `reverse(result.begin(), result.end())` 將其翻轉回來，確保了輸出格式的絕對正確。


## 程式碼實作
```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
using namespace std;

// 輔助函式：利用直式進位模擬法，執行兩個超大正整數的字串加法 (a + b)
string stringAdd(string a, string b) {
    string result = "";
    int i = a.length() - 1;
    int j = b.length() - 1;
    int carry = 0; // 進位計數器
    
    // 由低位數 (個位數) 向高位數橫向流式掃描
    while (i >= 0 || j >= 0 || carry > 0) {
        int sum = carry;
        if (i >= 0) {
            sum += a[i] - '0'; // 字元轉整數
            i--;
        }
        if (j >= 0) {
            sum += b[j] - '0';
            j--;
        }
        result += (sum % 10) + '0'; // 將當前位數的結果轉回字元追加至尾端
        carry = sum / 10;            // 計算下一次的進位值
    }
    // 因為是從低位往高位追加，最終必須反轉字串才是正確的十進位表示法
    reverse(result.begin(), result.end());
    return result;
}

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    // 建立大數陣列表，最大支援到 N = 250
    vector<string> f(251);
    
    // 初始化動態規劃的幾何邊界
    f[0] = "1"; // 長度為 0 視為 1 種基礎空狀態
    f[1] = "1"; // 長度為 1 僅 1 種方法
    
    // 離線預建表：利用遞迴轉移方程 f(i) = f(i-1) + 2 * f(i-2) 推導出 250 項內所有大數解答
    for (int i = 2; i <= 250; i++) {
        // 優化技巧：透過自己加自己來完美實現乘 2 的代數效果，免除實作大數乘法的負擔
        string two_times_f_prev2 = stringAdd(f[i - 2], f[i - 2]);
        f[i] = stringAdd(f[i - 1], two_times_f_prev2);
    }
    
    int n;
    while (cin >> n) {
        // 以絕對常數時間 O(1) 直接查表並印出全域最優鋪磚組合數
        cout << f[n] << "\n";
    }
    return 0;
}
```


## 進階優化思考
**大數記憶體片段與字串原地優化（In-place Buffer Optimization）**

在目前的 `stringAdd` 實作中，每次調用都會宣告一個全新的 `string result`，這會引發作業系統在 Heap 區塊上頻繁申請與釋放記憶體記憶體。在進行大規模大數迭代時，這種記憶體片段（Memory Fragmentation）會帶來不小的常數時間開銷。

* **優化做法**：為了追求極致效能，我們可以改用一個固定的、長度足夠（例如 80 個位元組）的 `std::vector<char>` 或者是全域陣列來作為原地快取緩衝區（In-place Buffer）。

* **滾動覆蓋**：在執行大數加法時，直接在這個全域緩衝區上進行內容覆蓋，並透過傳入引用（Pass-by-reference）的方式更新 `f[i]`。這能完全抹除掉字串物件物件反覆配置與銷毀的物理代價，讓大數運算的常數速度壓榨到極致，是實現頂級高性能大數類別庫時非常正統的工程調優思維。
