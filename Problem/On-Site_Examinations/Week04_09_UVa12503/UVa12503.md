# UVa 12503 - Robot Instructions

## 題目簡述

有一個機器人初始位於座標軸的原點（位置 0），它可以接收並執行三種不同形式的指令：
* `LEFT`：向左移動一個單位（位置 $-1$）。
* `RIGHT`：向右移動一個單位（位置 $+1$）。
* `SAME AS i`：完全重複執行第 $i$ 步所做過的相同指令。

給定一系列指令的總數 $n$，請計算出機器人在完整執行完這 $n$ 個指令之後，最終停留的座標位置。

**Sample Input**：

  **2** $\rightarrow$ 測資組數 $t$。<br>
  **3** $\rightarrow$ 第一組測資包含 3 個指令。<br>
  **LEFT** $\rightarrow$ 第 1 步：向左（pos = -1）。<br>
  **RIGHT** $\rightarrow$ 第 2 步：向右（pos = 0）。<br>
  **SAME AS 2** $\rightarrow$ 第 3 步：同第 2 步，向右（pos = 1）。<br>
  **5** $\rightarrow$ 第二組測資包含 5 個指令。<br>
  **LEFT**<br>
  **SAME AS 1**<br>
  **SAME AS 2**<br>
  **SAME AS 1**<br>
  **SAME AS 4**

**Sample Output**：

  **1** $\rightarrow$ 第一組測資最終位置為 1。<br>
  **-5** $\rightarrow$ 第二組測資五步皆為 LEFT，最終位置為 -5。


## 解題思路與歷史紀錄狀態

### 核心觀念：動態陣列與指令歷史紀錄
這道題目的本質是**基礎陣列模擬（Simulation）與歷史狀態查詢**。
因為機器人可能會接收到 `SAME AS i` 這種指令，需要去複製並執行過去某一步的行為，所以必須使用一個一維陣列或 `vector`，將每一步實際產生的位移量（向左為 `-1`，向右為 `+1`）完整保存下來。當遇到 `SAME AS` 指令時，直接透過索引（Index）進行 $\mathcal{O}(1)$ 的查表取得位移值即可。

### 演算法步驟
1. 讀取測資組數 $t$，每組測資獨立調用 `solve()`。
2. 讀取當前測資的指令總數 $n$，並動態配置一個大小為 $n$ 的 `vector<int> ins` 陣列，用來記錄每一步的位移值。初始化機器人位置 `pos = 0`。
3. 依序執行 $n$ 次指令讀取：
   * 讀入指令字串 `cm`。
   * 若 `cm == "LEFT"`，則將當前步的位移記錄 `ins[i] = -1`。
   * 若 `cm == "RIGHT"`，則將當前步的位移記錄 `ins[i] = 1`。
   * 若 `cm == "SAME"`，則需要額外讀入多餘的 `AS` 字串與目標步數數字 `a`。由於題目給定的步數 $a$ 是從 1 開始計數（1-indexed），而陣列索引是從 0 開始（0-indexed），因此當前步的位移應複製自歷史紀錄：`ins[i] = ins[a - 1]`。
4. 每處理完一步指令，隨即將該步位移值累加至全域位置 `pos += ins[i]`。
5. 迴圈結束後，輸出最終的 `pos` 數值。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(n)$
  每組測資包含 $n$ 個指令，在遍歷迴圈中，無論是處理基礎移動還是執行 `SAME AS` 的歷史查表，皆只需花費 $\mathcal{O}(1)$ 的常數時間。因此，整體的執行時間與指令數量 $n$ 呈線性正比。題目規範 $n \le 100$，運算量極低，可於瞬間執行完畢。
* **空間複雜度**： $\mathcal{O}(n)$
  需要使用一個大小為 $n$ 的 `vector` 陣列來儲存歷史指令的位移量。在最差情況下（$n = 100$），佔用的記憶體空間極小，完全符合空間效能指標。


## 邊界條件與潛在陷阱 (Edge & Corner Cases)

1. **索引對應轉換（1-indexed 轉 0-indexed）**：
   這是本題最核心的細節地雷。題目輸入的 `SAME AS a` 隱含的 $a$ 是從 1 開始計算（例如 `SAME AS 1` 代表重複第一步）。但在 C++ 的 `vector` 陣列中，第一步的資料是被存放在索引 `0` 的位置。因此在複製歷史資料時，必須嚴格寫成 `ins[a - 1]`，否則會發生嚴重的陣列越界（Out of Bounds）或讀到錯誤欄位。
2. **多重嵌套查詢的連鎖傳遞（Chained SAME AS）**：
   測資中可能會出現「第 4 步相同於第 2 步，而第 5 步相同於第 4 步」的連續嵌套。因為在處理第 4 步時，`ins[3]` 已經被確實賦予了實體數值（而非保留 "SAME" 字串），當第 5 步去讀取 `ins[3]` 時，可以直接拿到最終轉換後的位移量。這種直接儲存「最終位移結果」的策略可以完美規避掉遞迴查詢的麻煩，維持 $\mathcal{O}(1)$ 查表效能。
3. **字串讀取處理**：
   當遇到 `SAME AS a` 時，輸入流中會依序出現三個獨立的分段（字串 `SAME`、字串 `AS`、整數 `a`）。利用 `cin >> cm` 讀到 `SAME` 後，必須緊接著再用 `cin >> AS >> a` 把後續的多餘字串和核心數字讀乾淨，避免干擾到下一輪迴圈的字串讀取。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

// 處理單一組測試資料的函式
void solve() {
    int n;
    cin >> n;
    vector<int> ins(n); // 用於紀錄每一步的位移歷史 (-1 代表向左，1 代表向右)
    int pos = 0;        // 機器人的初始位置
    
    for (int i = 0; i < n; i++) {
        string cm;
        cin >> cm;
        
        if (cm == "LEFT") {
            ins[i] = -1;
        }
        else if (cm == "RIGHT") {
            ins[i] = 1;
        }
        else if (cm == "SAME") {
            string AS;
            int a;
            cin >> AS >> a;   // 吃掉多餘的 "AS" 字串，並讀入核心目標步數
            ins[i] = ins[a - 1]; // 核心：將 1-indexed 轉為 0-indexed 進行歷史查表
        }
        
        pos += ins[i]; // 即時更新當前位置
    }
    cout << pos << "\n"; // 輸出每組測資最終的停駐點
}

int main() {
    // 提升標準 I/O 串流效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int t;
    if (cin >> t) {
        while (t--) {
            solve(); // 依序執行各組獨立測資
        }
    }
    return 0;
}
```


## 進階優化與延伸思考

**空間換時間的典範**

這道題是一個非常標準且直觀的「空間換時間」應用。如果我們不開闢 ins 陣列去記錄歷史，當遇到 SAME AS 時，就必須耗費額外的時間往前回溯搜尋原始指令，這會使時間複雜度退化到 $\mathcal{O}(n^2)$。藉由開闢一條長度為 $n$ 的小陣列，成功的將回溯成本徹底壓低至 $\mathcal{O}(1)$，這是處理競賽題目與工程實作時非常核心的基礎優化思維。
