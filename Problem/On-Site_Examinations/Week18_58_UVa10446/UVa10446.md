# UVa 10446 - The Marriage Interview

## 題目簡述

題目給定了一個看似單純的遞迴函式（如下所示），該函式的結構非常類似於費氏數列的變體，但在內部引入了一個迴圈控制項：

```cpp
int trib (int n, int back) {
    int sum = 0;
    int i;
    if (n <= 1) return 1;
    for (i = 1; i <= back; i++)
        sum += trib(n - i, back);
    return sum;
}
```
每次調用此遞迴函式時，函式本身的執行框架都需要耗費一定的運算資源。本題的目標並不是要求出 `trib(n, back)` 的數值結果，而是要精確計算出：在給定初始參數 `n` 與 `back` 的情況下，整個遞迴流程中「`trib` 函式總共被調用了多少次（包含最初始的那一次調用）」。

**輸入與輸出規範**：
* 每行輸入包含兩個整數 `n` 與 `back`（ $n \le 60, \text{back} \le 60$ ）。
* 當讀入的 `n > 60` 時，代表輸入流結束。
* 每組測試資料必須依序輸出對應的 `Case` 編號以及函式總調用次數。

**Sample Input**：

  **2 1** $\rightarrow$ 第一組參數：$n = 2, \text{back} = 1$。<br>
  **5 3** $\rightarrow$ 第二組參數：$n = 5, \text{back} = 3$。<br>
  **61 0** $\rightarrow$ 當 $n = 61 > 60$ 時，代表整個輸入結束。

**Sample Output**：

  **Case 1: 3** $\rightarrow$ 最初調用 $n=2$ (1次)，迴圈觸發 $n=1$ (1次)，共 3 次。<br>
  **Case 2: 21**


## 解題思路與狀態轉移

### 核心觀念：遞迴樹節點計數與動態規劃（Dynamic Programming）
這道題目的本質是遞迴調用樹（Recursion Tree）的節點總數統計與重疊子問題優化。

如果直接使用題目給定的程式碼進行暴力遞迴計數，由於內部 `for` 迴圈會導致嚴重的分支暴增，時間複雜度會呈現指數級（ $\mathcal{O}(\text{back}^n)$ ）的惡性膨脹。在 $n = 60$ 的極端測資下，程式會直接陷入永久超時（TLE）。

為了解決大量重複子樹的計算，我們可以使用動態規劃（Dynamic Programming）的二維表格來進行遞迴狀態的逆向推導。

### 狀態定義
宣告一個二維動態規劃陣列 `dp[n][back]`，其幾何語意定義為：當前初始參數為 `n` 且回溯步長為 `back` 時，所衍生出的遞迴總調用次數。

### 狀態轉移方程推導
當我們調用一次 `trib(n, back)` 時，不論內部迴圈是否執行，當前這一次調用本身就必須計為 1 次。隨後，我們根據 `n` 的數值進行邊界分支判定：

1. **基礎邊界（ $n \le 1$ ）**：
   觀察原程式碼的 `if (n <= 1) return 1;`。當 `n` 小於或等於 1 時，函式會立刻執行 `return` 煞車，內部根本不會觸發任何 `for` 迴圈。因此，這棵遞迴樹只有孤零零的根節點本身。
   $$\text{當 } n \le 1 \text{ 時，} dp[n][back] = 1$$
2. **狀態轉移（ $n > 1$ ）**：
   當 `n > 1` 時，函式會強行啟動一個執行 `back` 次的 `for` 迴圈。迴圈內部會依序調用 `trib(n - i, back)`。這代表當前的總調用次數，剛好精確等於「當前這 1 次」加上「所有子遞迴樹的節點總和」：
   $$dp[n][back] = 1 + \sum_{i=1}^{back} dp[\max(0, n - i)][back]$$

* **核心幾何修正**：在遞迴中，如果 $n - i \le 0$，其數值會直接跌落入基礎邊界。因為在我們的動態規劃陣列中，所有的負數或 0 狀態在轉移語意上都與 $n = 0$ 的表現完全同構（皆只耗費 1 次調用），所以當 $n - i \le 0$ 時，我們直接取 $dp[0][back]$ 的數值進行累加即可。


## 複雜度分析

* **時間複雜度**：

  * **離線預建表階段**： $\mathcal{O}(N \times B \times B)$ <br>
    其中 $N = 60$ 且 $B = 60$。我們需要透過兩層巢狀迴圈遍歷二維表格的所有狀態（ $60 \times 60 = 3600$ 個狀態）。對於每個狀態，需要使用第三層 `for` 迴圈執行 `back` 次的加法累加。總運算量約為 $60 \times 60 \times 60 \approx 2.16 \times 10^5$ 次，可在幾毫秒內極速建表完畢。
  * **線上查詢階段**： $\mathcal{O}(1)$ <br>
    由於在程式初始化階段已經將所有可能的 `n` 與 `back` 的組合答案全數算好，隨後面對任何多組測資的詢問，直接以絕對常數時間查表 `dp[n][back]` 輸出即可。
* **空間複雜度**： $\mathcal{O}(N \times B)$ <br>
  need配置一個固定大小為 $65 \times 65$ 的二維靜態陣列 `dp[65][65]` 來緩衝預算好的數據，佔用的記憶體空間極小（約數 KB），空間利用率極佳。


## 邊界條件與潛在陷阱

1. **極端大數與整數溢位防禦（Integer Overflow）**：<br>
   這是本題最致命的 Wrong Answer 地雷。隨著 `n` 的提升與 `back` 分支的層層疊加，遞迴調用總次數會呈現瘋狂的指數級暴增。當 $n = 60, \text{back} = 60$ 時，總調用次數會大幅度跨越標準 32 位元有號整數（`int`）的極限上限。

   * **原程式碼分析**：原實作具備極其敏銳的強健性，將二維 `dp` 表格的資料型態嚴格宣告為了 `unsigned long long`（64 位元無號整數，上限高達 $1.8 \times 10^{19}$），這成功防範了數值溢位截斷的致命風險。
2. **輸入下界 $n < 0$ 的非對稱攔截**：<br>
   題目雖然指出 $n > 60$ 代表結束，但並沒有保證輸入的 `n` 最小值是多少。如果輸入了負數（例如 `n = -5`），在主程式的 `while` 判定中，原程式碼加入了一行核心特判：`if (n < 0) cout << ... << 1;`。因為只要 $n \le 1$，函式調用次數固定就是 1。這項特判完美阻斷了負數下標去存取陣列而引發的 SegFault 崩潰。
3. **終止符的精確控制**：<br>
   最外層必須使用 `while (cin >> n >> back && n <= 60)` 進行精確卡位。當讀到大於 60 的數字時安全退出主迴圈。


## 程式碼實作
```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <cstring>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    // 核心防禦：調用次數呈現指數暴增，必須使用 unsigned long long 嚴格防範整數溢位
    unsigned long long dp[65][65];
    memset(dp, 0, sizeof(dp));
    
    // 初始基礎邊界填充：當 n = 0 或 n = 1 時，函式不會進入迴圈，調用次數固定為 1 次
    for (int b = 0; b <= 60; b++) {
        dp[0][b] = 1;
        dp[1][b] = 1;
    }
    
    // 離線預建表：利用三層遞迴累加，橫向推導出二維 DP 表格的所有狀態
    for (int n = 2; n <= 61; n++) {
        for (int b = 0; b <= 60; b++) {
            dp[n][b] = 1; // 當前狀態自體調用本身計為 1 次
            
            // 執行 back 次的回溯子樹節點累加
            for (int i = 1; i <= b; i++) {
                // 核心幾何修正：若跌入負數或0的深淵，其行為與常規 0 狀態完全同構
                if (n - i <= 0) {
                    dp[n][b] += dp[0][b];
                }
                else {
                    dp[n][b] += dp[n - i][b]; // 滾動累加子樹狀態
                }
            }
        }
    }

    int n, back;
    int case_num = 1;
    
    // 線上查詢流：當 n <= 60 時持續提供高效率查表服務
    while (cin >> n >> back && n <= 60) {
        // 邊界防禦：若輸入為負數，不走下標存取，直接回傳常數 1 次
        if (n < 0) {
            cout << "Case " << case_num++ << ": " << 1 << "\n";
        }
        else {
            // 以絕對常數時間 O(1) 秒殺輸出全域最優調用次數
            cout << "Case " << case_num++ << ": " << dp[n][back] << "\n";
        }
    }
    return 0;
}
```


## 進階優化思考

### 空間換時間的前綴和優化（Prefix Sum Optimization, $\mathcal{O}(1)$ 轉移）
在目前的實作中，三層巢狀迴圈的轉移時間複雜度為 $\mathcal{O}(N \times B^2)$。雖然因為 $N, B \le 60$ 規模極小而使得執行速度飛快，但如果從頂級演算法調優的視局出發，其最內層的 `for (int i = 1; i <= b; i++)` 累加操作，本質上是在對二維表格的「同一行（Row）」進行一段**連續區間的求和（Sum of continuous range）**。

* **優化做法**：我們可以為二維 DP 表格的每一行額外引入一個**前綴和陣列（Prefix Sum Array）**：<br>
  $$\text{sumDp}[n][x] = \sum_{k=0}^{x} dp[n][k]$$

* **效能改善**：有了前綴和的緩衝支持，最內層的整個 `for` 迴圈累加就可以在轉移時，直接被一條簡單的減法公式 `sum_dp[...][...] - sum_dp[...][...]` 完美取代。這能將狀態轉移的時間複雜度從 $\mathcal{O}(B)$ 直接降至絕對的 **$\mathcal{O}(1)$ 常數時間**，從而將全域建表總複雜度優化到極致的 **$\mathcal{O}(N \times B)$**。這種利用前綴和抹除內層迴圈的策略，是在面對大規模多維動態規劃（如區間 DP、數位 DP）時最核心的降維打法。
