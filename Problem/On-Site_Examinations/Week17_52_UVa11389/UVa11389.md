# UVa 11389 - The Bus Driver Problem

## 題目簡述

某間公車公司有 $N$ 位司機，每位司機每天都需要負責開一趟上午的路線與一趟下午的路線。
公司給定了一項**常規工時行駛距離限制 $D$**。如果某位司機一天之內上午與下午的路線總行駛距離超過了 $D$，超過的部分就必須按照**加班費率 $R$** 支付司機加班費（每單位距離需支付 $R$ 元）。

請計算出在最聰明的路線分配策略下，公司每天最少需要支付的**總加班費開銷**是多少？

當輸入的 $N = 0, D = 0, R = 0$ 時，代表整個輸入流結束。

**Sample Input**：

  **2 20 5** $\rightarrow$ 第一組測資：$N = 2$ 位司機，工時上限 $D = 20$，加班費率 $R = 5$。<br>
  **10 15** $\rightarrow$ 2 趟上午路線的行駛距離。<br>
  **10 15** $\rightarrow$ 2 趟下午路線的行駛距離。<br>
  **2 20 5** $\rightarrow$ 第二組測資。<br>
  **10 10**<br>
  **10 10**<br>
  **0 0 0** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **50** $\rightarrow$ 最優分配為 (10+15=25) 與 (15+10=25)，兩人都超時 5，總加班費 $(5+5) \times 5 = 50$。<br>
  **0** $\rightarrow$ 最優分配皆為 10+10=20，剛好對齊上限，不需支付加班費。


## 解題思路與貪婪策略

### 核心觀念：極值配對與總和均等化（Greedy Algorithm）
這道題目的本質是**經典的雙序列貪婪配對與排序不等式應用**。

為了讓所有人產生的總加班費最低，直觀上的貪婪決策是：**「不要讓任何人的總工時變得極端巨大」**。如果我們讓上午開最長路線的司機，下午又去開最長的路線，那他超時的部分會非常驚人，而其他開短路線的人工時又會大量浪費。
* **最優解配對法**：將「最長」的上午路線，配給「最短」的下午路線；而「最短」的上午路線，則配給「最長」的下午路線。這樣能讓每位司機的總行駛距離儘可能地平滑均等，實現整體超時量最低的成果。

為了達成這種「極值互補」的流式配對，前置處理手法非常簡單：
1. **上午路線升序排序**：將上午的路線從短到長排列。
2. **下午路線降序排序**：將下午的路線從長到短排列。
3. **橫向對齊相加**：完成排序後，直接用單層迴圈將對應索引 `i` 的上下游距離相加（`morning[i] + afternoon[i]`），此時第一組就是「最短 + 最長」，第二組就是「次短 + 次長」，天然實現了全域最優分配。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \log N)$ <br>
  演算法的運算效能完全由前期的排序階段決定。使用 `std::sort` 將兩個大小為 $N$ 的一維陣列分別進行升序與降序排列，耗時為 $\mathcal{O}(N \log N)$。後續的配對計費階段只需要跑一個單層的 `for` 迴圈枚舉一次，耗時僅為線性 $\mathcal{O}(N)$。題目規範司機人數 $N \le 100$，最大總運算量在數百次之內，可在幾微秒內瞬間通過。
* **空間複雜度**： $\mathcal{O}(N)$ <br>
  需要動態配置兩個大小為 $N$ 的 `std::vector<int>` 陣列來緩衝讀入的上下游行駛距離數據，空間開銷與司機人數呈完全的線性正比。


## 邊界條件與潛在陷阱

1. **未超時司機的過濾防禦（無負數加班費）**：<br>
   如果某位司機上午與下午加起來的總距離 `total_distance` 小於或等於常規上限 $D$，代表他今天完全沒有超時。在代數上，`total_distance - d` 會得到一個負數。如果無腦直接累加，會變成「負的加班費」，這在物理上是不合邏輯的（公司不可能從司機口袋裡倒扣薪水）。

   * **原程式碼分析**：原實作在迴圈內部加上了嚴密的 `if (total_distance > d)` 特判，只有在確定超時的情況下才計算超時費用，完美避開了負數污染的地雷。
2. **終止符 0 0 0 的精確攔截**：<br>
   最外層必須使用 `while (cin >> n >> d >> r && (n != 0 || d != 0 || r != 0))` 進行精確控制。只要其中一個變數不為 0 就要繼續服務，直到三者皆為 0 時安全退出主迴圈。
3. **資料型態與溢位分析**：<br>
   雖然總加班費可能累積得很高，但由於題目給定的 $N, D, R$ 規模通常非常小，標準 32 位元有號整數（`int`）高達 $2 \times 10^9$ 的容量已經具備了足夠安全的防禦力，使用 `int` 儲存 `total_overtime_pay` 是可以安全拿到 AC 的。


## 程式碼實作

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n, d, r;
    // 連續讀入司機數 n、常規限額 d、加班費率 r，當三者皆為 0 時終止程式
    while (cin >> n >> d >> r && (n != 0 || d != 0 || r != 0)) {
        vector<int> morning(n);
        vector<int> afternoon(n);

        for (int i = 0; i < n; i++) cin >> morning[i];
        for (int i = 0; i < n; i++) cin >> afternoon[i];

        // 貪婪核心：將上午路線進行升序排列 (由短到長)
        sort(morning.begin(), morning.end());
        // 貪婪核心：將下午路線進行降序排列 (由長到短)
        sort(afternoon.begin(), afternoon.end(), greater<int>());

        int total_overtime_pay = 0; // 總加班費計費器
        
        // 雙序列一對一精確配對
        for (int i = 0; i < n; i++) {
            int total_distance = morning[i] + afternoon[i]; // 極值互補加總
            
            // 安全防禦：只有當實際總距離跨過常規天花板時，才需要計費
            if (total_distance > d) {
                total_overtime_pay += (total_distance - d) * r;
            }
        }
        // 輸出當前 Case 的最省加班費總額
        cout << total_overtime_pay << "\n";
    }
    return 0;
}
```


## 進階優化思考
原做法利用兩個方向相反的排序進行對齊，在架構上非常直觀且漂亮。但如果從計算機底層硬體指令與代碼的精簡度出發，存在著另外一種不需要引入 `greater<int>()` 降序比較子、空間更省的經典重構手段。

**同向排序與逆向雙指標配對（Reverse Indexing 策略）**

* **原理**：我們不需要把下午的陣列大費周章倒過來排序。可以讓上午與下午的陣列同時進行常規的升序排序。

* **做法**：完成排序後，上午的指標 `i` 從左向右前進（`0` 到 `n-1`），而下午的指標則直接從右向左倒著抓取（`n - 1 - i`）。

* **效能改善**：此重構版本在底層完全沿用了最常規的單向小於比對，有助於編譯器在生成機器碼時進行更激進的流水線優化；且消除了額外引入 `greater` 函式庫的物件負擔，代碼結構更具備對稱與專業感。

**優化程式碼實作片段：**
```cpp
// 兩者皆採用最簡單的預設升序排序
sort(morning.begin(), morning.end());
sort(afternoon.begin(), afternoon.end());

int total_overtime_pay = 0;
for (int i = 0; i < n; i++) {
    // 上午抓最小 morning[i]，下午抓最大 afternoon[n - 1 - i]
    int total_distance = morning[i] + afternoon[n - 1 - i];
    if (total_distance > d) {
        total_overtime_pay += (total_distance - d) * r;
    }
}
```
