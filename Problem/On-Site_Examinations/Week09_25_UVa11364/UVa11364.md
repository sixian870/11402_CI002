# UVa 11364 - Parking

## 題目簡述

在一條筆直的單行道大街上，有 $n$ 家商店，各自位於不同的橫座標 $x_i$ 位置。<br>
麥可（Michael）想要開車到這條街上購物。他必須選擇在街上的「某個座標位置」將車停好，然後徒步走訪這 $n$ 家商店。在逛完所有商店後，他必須再徒步走回停車的位置開車。<br>
請幫麥可找一個最完美的停車位置，使得他**徒步步行的總距離為最短**，並輸出該最短總步程距離。

**Sample Input**：

  **2** $\rightarrow$ 測試資料組數 $t$。<br>
  **4** $\rightarrow$ 第一組 Case 的商店總數 $n$。<br>
  **24 13 89 37** $\rightarrow$ 這 4 家商店在街道上的座標位置。<br>
  **6** $\rightarrow$ 第二組 Case 的商店總數 $n$。<br>
  **7 30 3 11 56 75**

**Sample Output**：

  **152** $\rightarrow$ 排序後最小為 13，最大為 89。最優總距離為 $(89 - 13) \times 2 = 152$。<br>
  **144** $\rightarrow$ 排序後最小為 3，最大為 75。最優總距離為 $(75 - 3) \times 2 = 144$。


## 解題思路與一維幾何優化

### 核心觀念：幾何邊界與停車位無關性（Greedy/Math Bound）
這道題目的本質是**一維直線上的幾何模擬與極值尋找**。

在直覺上，我們可能會想要透過公式去計算所有商店的平均值、中位數或嘗試列舉每一個點來當作停車位。然而，透過幾何線段的延伸，我們可以發現一個極其美妙的數學物理性質：
1. **邊界鎖定**：不論車子停在這條街道上的任何一個地方（甚至是商店範圍之外），麥可只要想把所有的商店都逛完，他就**必須至少走到整條街上「最左邊（座標最小）」的那家商店，也必須走到「最右邊（座標最大）」的那家商店**。

2. **總路程恆定**：假設將所有商店排序後，最左邊的商店為 $A$，最右邊的商店為 $B$。
   * 如果麥可把車停在 $A$ 和 $B$ 之間的任意位置 $P$。他只要從 $P$ 出發，先一路向左走到 $A$，再調頭一路向右走到 $B$（途中順便逛完中間夾著的所有商店），最後再從 $B$ 往左走回停車位 $P$。
   * 這整趟來回的物理軌跡，在幾何線段上剛好就等同於：**「把線段 $\overline{AB}$ 完整走過兩遍」**。

3. **結論**：最完美的步行總距離，完全與你把車停在哪個特定的商店無關！只要停車位置夾在最左與最右商店的閉區間內，最短步行距離固定就是：（最大座標 $-$ 最小座標） $\times 2$ 。

### 演算法步驟
1. 讀取測試資料組數 $t$。
2. 針對每組測資，讀入商店總數 $n$，並動態配置陣列儲存所有座標。
3. 將陣列使用 `std::sort` 進行從小到大的升序排列。
4. 鎖定排序後的首項 `a[0]`（最小值）與末項 `a[n - 1]`（最大值）。
5. 直接計算 `(a[n - 1] - a[0]) * 2` 並輸出答案。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \log N)$
  每組測資中，主要的效能瓶頸在於對 $N$ 個商店座標進行排序（C++ `std::sort` 耗時 $\mathcal{O}(N \log N)$）。後續讀取極值與數學相乘皆為 $\mathcal{O}(1)$。題目規範 $N \le 20$，運算量極小，執行時間趨近於零，能以最快速度過關。
* **空間複雜度**： $\mathcal{O}(N)$
  需要動態配置一個大小為 $N$ 的 `vector<int> a` 陣列來儲存商店座標。由於 $N \le 20$，記憶體消耗可以忽略不計，空間效益極佳。


## 邊界條件與潛在陷阱

1. **一維區間的極端範圍防禦**：
   題目敘述規定商店座標 $x_i$ 的範圍在 $[0, 99]$ 之間。這代表兩頂點間的最大距離差絕不可能超過 100，最大可能輸出不超過 $100 \times 2 = 200$。因此，所有座標與計算結果完全在標準 32 位元有號整數（`int`）的安全區間內，絕無任何整數溢位（Integer Overflow）的風險。
2. **$N = 1$ 的單一商店情況**：
   如果整條街上只有 1 家商店（$N = 1$），則排序後 `a[0]` 與 `a[n - 1]` 為同一個數，相減得到 0，再乘以 2 輸出 0。這代表麥可直接把車停在該商店門口，徒步距離為 0，符合物理現實與幾何邊界。
3. **商店座標重複**：
   若有多家商店位於同一個座標位置，排序邏輯與極值挑選完全不受影響，依然適用此幾何公式。


## 程式碼實作

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int t;
    if (cin >> t) {
        while (t--) {
            int n;
            cin >> n;
            
            vector<int> a(n);
            for (int i = 0; i < n; i++) {
                cin >> a[i];
            }
            
            // 將商店座標從小到大進行升序排序
            sort(a.begin(), a.end());
            
            // 幾何核心：最左側頂點與最右側頂點
            int min_pos = a[0];
            int max_pos = a[n - 1];
            
            // 不管車停在 [min_pos, max_pos] 之間的任何地方，總徒步路程固定為該區間線段長度的兩倍
            cout << (max_pos - min_pos) * 2 << "\n";
        }
    }
    return 0;
}
```


## 進階優化思考
雖然目前使用 sort 進行預處理的 $\mathcal{O}(N \log N)$ 在此題的極小資料規模下已經快如閃電，但這題存在一個將時間複雜度優化到理論極限 $\mathcal{O}(N)$ 的極速解法。

**線性動態極值搜尋（一維滾動掃描， $\mathcal{O}(N)$ ）**

* **原理**：回顧核心思路，我們唯一需要的資訊只有「最大值」與「最小值」。將整個陣列完整排序好，其實做了很多多餘的排序功。

* **做法**：我們可以直接在讀入數據的同時，利用全域滾動更新的方式，動態抓出最大值與最小值。在 C++ 中，甚至不需要宣告 vector 陣列去配置任何記憶體，一邊讀一邊比對即可。

* **效能改善**：此重構版本的時間複雜度成功降低至最優的線性時間 $\mathcal{O}(N)$ ，且將空間複雜度直接壓低到絕對零陣列的 $\mathcal{O}(1)$。當未來資料規模放大到百萬級別時，這種動態掃描策略能展現出絕對性的效能壓制。

**優化程式碼片段：**
```cpp
while (t--) {
    int n;
    cin >> n;
    
    int min_pos = 101; // 初始化為大於題目範圍上限的值
    int max_pos = -1;  // 初始化為小於題目範圍下限的值
    
    for (int i = 0; i < n; i++) {
        int current_x;
        cin >> current_x;
        if (current_x < min_pos) min_pos = current_x;
        if (current_x > max_pos) max_pos = current_x;
    }
    cout << (max_pos - min_pos) * 2 << "\n";
}
```
