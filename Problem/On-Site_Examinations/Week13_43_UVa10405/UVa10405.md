# UVa 10405 - Longest Common Subsequence

## 題目簡述

給定兩個字串，請計算出這兩個字串的**「最長公共子序列（Longest Common Subsequence, LCS）」**的長度。<br>
子序列（Subsequence）是指從原字串中刪除零個或多個字元後，其餘字元保持原本相對順序所組成的新字串。子序列不要求在原字串中必須是連續的。

**Sample Input**：

  **a1b2c3d4e5** $\rightarrow$ 第一個字串 $S_1$。<br>
  **abcdefg** $\rightarrow$ 第二個字串 $S_2$。<br>
  **those**<br>
  **shun**

**Sample Output**：

  **5** $\rightarrow$ 最長公共子序列為 "abcde"，其長度為 5。<br>
  **1** $\rightarrow$ 最長公共子序列為 "h" 或 "s"，其長度為 1。


## 解題思路與動態規劃

### 核心觀念：二維動態規劃（Dynamic Programming）
這道題目是經典的**字串比對與字串對齊動態規劃問題**。如果採用簡單的窮舉法嘗試列舉所有子序列，時間複雜度會隨著字串長度呈指數型暴增，進而引發 TLE。

透過將大問題拆解為重疊子問題，可以建立二維狀態表格進行狀態轉移：

1. **狀態定義**：
   建立一個二維狀態陣列 `dp[i][j]`，其物理語意定義為：**「字串 $S_1$ 的前 $i$ 個字元與字串 $S_2$ 的前 $j$ 個字元，兩者的最長公共子序列長度」**。
2. **邊界初始化**：
   當任一字串的長度為 0 時（即 $i=0$ 或 $j=0$），其 LCS 長度必然為 0。因此 `dp[0][j]` 與 `dp[i][0]` 的所有格子一律初始化為 0。
3. **狀態轉移方程**：
   由左至右、由上至下遍歷網格（`i` 從 1 到 $S_1.\text{size}()$；`j` 從 1 到 $S_2.\text{size}()$）：

   * **狀況一（當前字元相同）**：若 $S_1[i-1] == S_2[j-1]$，代表這個字元可以被納入 LCS 中。此時狀態由左上方對角線延伸而來：
     $$dp[i][j] = dp[i-1][j-1] + 1$$
   * **狀況二（當前字元相異）**：若 $S_1[i-1] \neq S_2[j-1]$，代表此字元無法同時貢獻給當前的 LCS。此時必須退而求其次，從上方或左方的歷史紀錄中，繼承較大的那一邊最優解：
     $$dp[i][j] = \max(dp[i-1][j], dp[i][j-1])$$


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \times M)$
  其中 $N$ 為字串 $S_1$ 的長度，$M$ 為字串 $S_2$ 的長度。在二維網格的狀態轉移中，透過雙層 `for` 迴圈枚舉每個網格，而每個網格內的操作皆可在 $\mathcal{O}(1)$ 常數時間內完成。題目規範字串最大長度為 1000，最大總運算次數不超過 $1000 \times 1000 = 10^6$ 次，可在幾毫秒內極速通關。
* **空間複雜度**： $\mathcal{O}(N \times M)$
  需要動態配置一個大小為 $(N+1) \times (M+1)$ 的二維動態陣列 `dp`。當 $N, M = 1000$ 時，表格約需佔用 4 MB 的記憶體空間，在現今評測系統的空間限制內非常安全。


## 邊界條件與潛在陷阱 (Edge & Corner Cases)

1. **包含空格文字的讀取防禦（`getline` 的必要性）**：
   這是本題最經典的 Wrong Answer 陷阱。題目給定的輸入字串中，**極有可能包含空格字元（如 Sample 中的 `" those"`）**，甚至是完全沒有字元的空白行。如果無腦使用 `cin >> s1` 讀取，輸入流會在遇到空格時自動停止，導致後半段字串直接斷裂並干擾到下一輪的資料對齊。**因此，必須嚴格使用 `getline(cin, s1)` 逐行讀入完整文本**。
2. **0-indexed 與 1-indexed 的索引錯位**：
   在 `dp` 表格中，為了容納長度為 0 的邊界狀態，陣列維度被擴充為 `(s1.size() + 1) * (s2.size() + 1)`。這導致在進行字元比對時，`dp` 表格中的索引 `i` 與 `j`，其對應的實體字串字元索引必須退回一格，精確寫成 `s1[i-1]` 與 `s2[j-1]`，原實作的索引防禦線完全正確。
3. **EOF 的連續監聽**：
   由於題目未告知測資組數，使用 `while (getline(cin, s1) && getline(cin, s2))` 可以確保精確成對讀取，在遇到檔案流結束時能準確安全收線。


## 程式碼實作

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    string s1, s2;
    // 使用 getline 逐行讀取，完美相容包含空格的文本與空行
    while (getline(cin, s1) && getline(cin, s2)) {
        
        // 分配 (N+1) x (M+1) 的二維狀態矩陣，初始全數清零
        vector<vector<int>> dp(s1.size() + 1, vector<int>(s2.size() + 1, 0));
        
        // 開始進行多階段二維動態規劃轉移
        for (int i = 1; i <= (int)s1.size(); i++) {
            for (int j = 1; j <= (int)s2.size(); j++) {
                // 核心判定：當前比對的兩個字元相同 (注意字串索引要 -1)
                if (s1[i - 1] == s2[j - 1]) {
                    dp[i][j] = dp[i - 1][j - 1] + 1; // 繼承左上方狀態並累加 1
                }
                // 當前比對的兩個字元相異
                else {
                    dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]); // 從上方或左方繼承較佳解
                }
            }
        }
        // 矩陣右下角最後一個格子即為全域最長公共子序列長度
        cout << dp[s1.size()][s2.size()] << "\n";
    }
    return 0;
}
```


## 進階優化思考

原做法在時間與空間上已達到極佳的 AC 規格。但若從高階資工演算法的優化思維來審視，這個字串比對問題存在著一個將空間複雜度直接由 $\mathcal{O}(N \times M)$ 壓低至極限 $\mathcal{O}(\min(N, M))$ 的一維滾動優化手段。

**一維滾動陣列優化（Rolling Array / Space Compression）**

* **原理**：仔細觀察動態規劃的轉移方程，可以發現當我們在計算第 `i` 列的狀態時，我們唯一需要參考的只有相鄰的上一列 `i - 1` 的狀態。更早之前的歷史表格在記憶體中其實已經變成了死資料。

* **做法**：因此，不需要開闢 $N$ 列的二維巨大矩陣。只需要宣告兩個長度為 $M+1$ 的一維陣列 `prev_dp` 與 `curr_dp` 交替滾動更新。甚至可以只用單一條一維陣列，並在更新時利用一個暫存變數 `pre_diag` 鎖定左上角的歷史殘留，進行橫向覆蓋。

* **效能改善**：此重構版本將空間複雜度優化到了最優的 $\mathcal{O}(M)$。當字串長度放大到十萬級別時，一維滾動陣列優化技術能大幅提升 CPU 的快取命中率，避免發生高昂的記憶體頁面置換，是高性能後端與嵌入式演算法開發時的必備核心調優手法。

**優化程式碼實作片段：**
```cpp
// 選擇較短的字串作為行寬，可將空間最大程度壓縮
int m = s2.size();
vector<int> dp(m + 1, 0);

for (char c1 : s1) {
    int pre_diag = 0; // 用於模擬二維狀態中的左上方格子 dp[i-1][j-1]
    for (int j = 1; j <= m; j++) {
        int temp = dp[j]; // 緩衝上方格子的舊值 dp[i-1][j]
        if (c1 == s2[j - 1]) {
            dp[j] = pre_diag + 1;
        } else {
            dp[j] = max(dp[j], dp[j - 1]);
        }
        pre_diag = temp; // 將舊值轉遞為下一格的左上方交點
    }
}
cout << dp[m] << "\n";
```
