# UVa 10474 - Where is the Marble?

## 題目簡述

有一堆大理石，每個大理石上都寫著一個數字。首先需要將這些大理石上的數字按照從小到大（升序）的順序排列好。<br>
接著會進行若干次詢問，每次詢問給定一個目標數字，必須判斷該數字是否存在於這堆大理石中：
* 若存在，輸出該數字在排序後**第一次出現的「位置」（位置從 1 開始計算）**。
* 若不存在，輸出找不到該數字的訊息。

當輸入的大理石總數 $N$ 與詢問次數 $Q$ 皆為 0 時，代表輸入結束。

**Sample Input**：

  **4 1** $\rightarrow$ 大理石個數 $N = 4$，詢問次數 $Q = 1$。<br>
  **2 3 5 1** $\rightarrow$ 大理石上的數字。<br>
  **5** $\rightarrow$ 詢問數字 5。<br>
  **5 2** $\rightarrow$ 第二組測資，$N = 5, Q = 2$。<br>
  **1 3 3 3 6**<br>
  **3** $\rightarrow$ 詢問數字 3。<br>
  **2** $\rightarrow$ 詢問數字 2。<br>
  **0 0** $\rightarrow$ 當 $N=0, Q=0$ 時輸入結束。

**Sample Output**：

  **CASE# 1:**<br>
  **5 found at 4** $\rightarrow$ [1, 2, 3, 5] 中，5 位於第 4 個位置。<br>
  **CASE# 2:**<br>
  **3 found at 2** $\rightarrow$ [1, 3, 3, 3, 6] 中，3 第一次出現位於第 2 個位置。<br>
  **2 not found** $\rightarrow$ 2 不在序列中。


## 解題思路與二分搜尋

### 核心觀念：排序與下界二分搜尋（Lower Bound）
這道題目的本質是**陣列排序（Sorting）與有序序列的二分搜尋（Binary Search）**。
由於題目要求在多個重複數字存在時，必須回傳 **「第一次」** 出現的位置，因此不能使用一般的二分搜尋，而必須使用 **Lower Bound**。

1. **有序預處理**：先將大理石陣列讀入並使用 `std::sort` 進行升序排列，使數列具備二分搜尋所需的單調性。
2. **下界搜尋**：C++ 內建的 `std::lower_bound` 採用二分搜尋演算法，能在 $\mathcal{O}(\log N)$ 時間內回傳**大於或等於**目標值 $Q$ 的第一個元素的迭代器（Iterator）。
3. **有效性驗證**：
   * 必須先確認迭代器沒有指向陣列末尾（`it != s.end()`）。
   * 接著透過解引用（`*it == q`）確認該位置的實際數值是否剛好等於目標值。若不相等，代表陣列中只有大於該數的元素，目標值不存在。
   * 位置換算：C++ 的指標/迭代器相減（`it - s.begin()`）會得到 0-indexed 的陣列索引，題目要求位置從 1 開始，因此最終結果必須 **$+1$**。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \log N + Q \log N)$
  每組測資排序 $N$ 個大理石耗時 $\mathcal{O}(N \log N)$。後續共有 $Q$ 次詢問，每次詢問透過 `std::lower_bound` 執行二分搜尋耗時 $\mathcal{O}(\log N)$ ，總查詢開銷為 $\mathcal{O}(Q \log N)$。在題目規範的資料規模下（ $N, Q \le 10,000$ ），整體運算量極低。
* **空間複雜度**： $\mathcal{O}(N)$
  需要動態配置一個大小為 $N$ 的 `vector<int> s` 陣列來儲存大理石上的數值，空間開銷與大理石數量呈線性正比。


## 邊界條件與潛在陷阱

1. **重複數字的首次出現位置**：
   若數列中含有多個相同的數字（例如 `1 3 3 3 6`），詢問 `3` 時，`std::lower_bound` 會精確鎖定在第一個 `3` 的位置（即索引 1，換算位置為 2）。如果錯誤地使用 `std::binary_search`（只回傳是否存在）或一般的二分搜尋，可能會抓到中間或後面的 `3`，導致答案錯誤。
2. **查無此數的指針越界防禦**：
   當詢問的數字大於大理石中的所有數字時，`std::lower_bound` 會一路搜尋到邊界之外，最終回傳 `s.end()`。如果在防禦檢查中漏掉了 `it != s.end()`，直接進行 `*it` 解引用操作，將會引發**記憶體區段錯誤（Segment Fault / Runtime Error）**。
3. **格式字串細節（Whitespace & Colons）**：
   每組 Case 的開頭格式為 `CASE# X:`，注意 `CASE#` 與數字之間有一個空格，而冒號 `:` 後方**不留空格並直接換行**，這點在實作輸出時必須嚴格比對。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int m, n;
    int count = 1;
    
    // 當 m (大理石數) 與 n (詢問數) 不同時為 0 時持續讀取
    while (cin >> m >> n && (m != 0 || n != 0)) {
        vector<int> s(m);
        for (int i = 0; i < m; i++) {
            cin >> s[i];
        }
        
        // 將大理石由小到大排序，為二分搜尋做預處理
        sort(s.begin(), s.end());
        
        // 嚴格依照題目規範輸出 Case 標頭
        cout << "CASE# " << count++ << ":\n";
        
        // 處理 n 次詢問
        while (n--) {
            int q;
            cin >> q;
            
            // 使用二分搜尋尋找大於或等於 q 的第一個位置
            auto it = lower_bound(s.begin(), s.end(), q); 
            
            // 換算為從 1 開始計算的實體位置
            int pos = (it - s.begin()) + 1;
            
            // 安全防禦：確保指針未越界，且找到的數值與目標值完全相等
            if (it != s.end() && *it == q) { 
                cout << q << " found at " << pos << "\n";
            }
            else {
                cout << q << " not found\n";
            }
        }
    }
    return 0;
}
```


## 進階優化思考

雖然「排序 + 二分搜尋」的 $\mathcal{O}((N+Q) \log N)$ 已經非常快速，但如果遇到更高階的演算法場景（例如大理石數值範圍很小，但詢問數 $Q$ 極大時），存在另一種更高效的資工優化思維。

**計數排序與前綴位置映射**

* **原理**：如果大理石上的數字範圍已知且有限（例如數值 $\le 10000$ ），可以放棄常規的比較排序與二分搜尋。

* **做法**：宣告一個大小為 10005 的計數陣列 int counts[10005] = {0};，在讀入大理石時直接累加頻率。讀取完畢後，從頭遍歷計數陣列，將其轉換為「該數字第一次出現的位置映射表 int first_pos[10005];」。

* **效能改善**：這樣可以將預處理時間壓低至線性時間 $\mathcal{O}(N + \text{MaxVal})$。後續的每一次詢問 $Q$，都可以直接透過 first_pos[Q] 在 $\mathcal{O}(1)$ 常數時間 內直接查表得到答案。這將總時間複雜度優化至最佳的 $\mathcal{O}(N + Q)$，完全擺脫了對數（$\log$）的開銷。
