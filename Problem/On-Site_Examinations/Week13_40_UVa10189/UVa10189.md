# UVa 10189 - Minesweeper

## 題目簡述

給定一個 $N \times M$ 的網格地圖，代表踩地雷（Minesweeper）的遊戲盤面。
* 字元 `*` 代表該格子內藏有一顆地雷。
* 字元 `.` 代表該格子為安全區域。

請將所有安全區域（`.`）的字元替換成一個數字，該數字代表**與其相鄰的 8 個方向（上、下、左、右、以及 4 個對角線方向）中，總共包含多少顆地雷**。
當輸入的網格大小 $N = 0$ 且 $M = 0$ 時，代表輸入結束。每一組 Field 輸出之間必須精確以一個空行（Blank line）隔開。

**Sample Input**：

  **4 4** $\rightarrow$ 第一組網格列數 $N = 4$、行數 $M = 4$。<br>
  **\*...** $\rightarrow$ 網格內容。<br>
  **....**<br>
  **.\*..**<br>
  **....**<br>
  **3 5** $\rightarrow$ 第二組網格列數 $N = 3$、行數 $M = 5$。<br>
  **\*\*...**<br>
  **.....**<br>
  **.\*...**<br>
  **0 0** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **Field #1:**<br>
  **\*100** $\rightarrow$ 地雷維持原樣，安全格子填入周圍 8 格的地雷總數。<br>
  **2210**<br>
  **1\*10**<br>
  **1110**<br>
  <br> $\rightarrow$ **核心注意：兩組 Field 輸出之間必須精確夾帶一個空行。**
  **Field #2:**<br>
  **\*\*100**<br>
  **33200**<br>
  **1\*100**


## 解題思路與網格走訪

### 核心觀念：二維陣列邊界防禦與 8 方向位移向量
這道題目的本質是**二維地圖模擬與幾何周圍節點掃描**。

為了高效且優雅地檢查每個安全格子（`.`）周圍的 8 個相鄰位置，不需要寫 8 個冗長且獨立的 `if` 判斷式，最佳的資工實作手法是宣告**位移方向常數陣列（Direction Arrays）**：
* `dx[] = {-1, -1, -1,  0, 0,  1, 1, 1}`
* `dy[] = {-1,  0,  1, -1, 1, -1, 0, 1}`

當要掃描座標 `(j, k)` 時，只需利用一個執行 8 次的輕量迴圈，將新座標計算為 `x = j + dx[l]` 與 `y = k + dy[l]`。這種向量偏移思維能大幅精簡代碼結構。

### 演算法步驟
1. 利用 `while (cin >> n >> m && (n != 0 || m != 0))` 讀取網格尺寸，並利用 `cases` 變數累積當前的 Field 編號。
2. **空行精確控制**：若 `cases > 1`，在印出下一個 Field 標頭前，先輸出一個 `cout << "\n";`。這能確保兩組 Field 之間精確夾帶一個空行，且最後一組輸出的末尾不會有多餘空行。
3. 使用 `vector<string> arr(n)` 讀入整張地圖。
4. 使用雙層 `for` 迴圈遍歷每個網格 `(j, k)`：
   
   * 若 `arr[j][k] == '*'`，其本身即為地雷，直接輸出 `*`。
   * 若 `arr[j][k] == '.'`，初始化計數器 `count = 0`，調用 8 方向位移陣列進行掃描。
5. **邊界防禦**：在確認該相鄰格是否為地雷前，**必須優先驗證新座標是否越界**：即滿足 `x >= 0 && x < n && y >= 0 && y < m`。在界內的前提下，若 `arr[x][y] == '*'`，則 `count++`。
6. 掃描完畢後，直接輸出累積的 `count` 數值。每列掃描完輸出換行。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \times M)$
  地圖總共包含 $N \times M$ 個網格。在最壞情況下，每個格子都是安全區域，都需要對周圍 8 個方向進行常數次的邊界檢查與字元比對。因此，單組測資的運算量約為 $8 \times N \times M$ 次。題目規範 $N, M \le 100$，最大總運算次數不超過 $8 \times 10,000 = 80,000$ 次，可在 1 毫秒內極速通關。
* **空間複雜度**： $\mathcal{O}(N \times M)$
  需要動態配置一個大小為 $N$ 的 `vector<string>` 陣列來緩衝當前地圖的字元狀態。當 $N, M = 100$ 時，記憶體開銷低於 15 KB，空間效能極佳。


## 邊界條件與潛在陷阱

1. **多組測資間的空行格式要求（Presentation Error）**：
   這是本題最經典的格式陷阱。題目要求「每組 Field 的輸出之間」必須有一個空行。這意味著**最後一組 Field 的結尾後面絕對不能有多餘的空行**。
   原程式碼中採用的 `if (cases > 1) cout << endl;` 策略非常完美，它將換行的觸發時機移到了「第二組測資開始輸出前」，成功達成了去尾效果。
2. **矩陣四周邊緣座標的越界防禦**：
   當目標格子位於矩陣的邊角（例如 `(0, 0)`）時，其左上方的相鄰新座標 `x = -1, y = -1` 會直接脫離矩陣記憶體範疇。如果漏掉了 `x >= 0 && x < n && y >= 0 && y < m` 的安全防禦線，直接調用 `arr[-1][-1]` 會引發**記憶體區段錯誤（Segmentation Fault / Runtime Error）**。原程式碼的防禦邏輯嚴密且正確。
3. **輸入流對齊與地圖讀取**：
   由於使用 `cin >> arr[i]` 讀取字串，它會自動跳過領頭的換行符。因此在主迴圈外部不需要額外調用 `cin.ignore()`，輸入流在連續讀取多組測資時能保持完美的單字對齊。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n, m;
    int cases = 1; // 用於紀錄當前的 Field 編號
    
    // 持續讀入列數 n 與行數 m，直到讀取到 0 0 時終止程式
    while (cin >> n >> m && (n != 0 || m != 0)) {
        
        // 格式控制核心：從第二組 Field 開始，在輸出前幫前一組補換行，確保末尾無多餘空行
        if (cases > 1) {
            cout << "\n";
        }
        
        // 使用動態陣列儲存地圖
        vector<string> arr(n); 
        for (int i = 0; i < n; i++) {
            cin >> arr[i]; 
        }
        
        // 依照題目嚴格規範輸出 Field 標頭
        cout << "Field #" << cases << ":\n";
        
        // 幾何核心：定義 8 方向位移向量常數陣列
        int dx[] = {-1, -1, -1,  0, 0,  1, 1, 1};
        int dy[] = {-1,  0,  1, -1, 1, -1, 0, 1};
        
        // 開始遍歷二維地圖網格
        for (int j = 0; j < n; j++) {
            for (int k = 0; k < m; k++) {
                
                // 若當前格本身為地雷，維持原樣直接輸出
                if (arr[j][k] == '*') {
                    cout << "*";
                }
                // 若當前格為安全區域，掃描周圍 8 方向的地雷總數
                else {
                    int mine_count = 0;
                    for (int l = 0; l < 8; l++) {
                        int x = j + dx[l]; 
                        int y = k + dy[l]; 
                        
                        // 安全防禦：確保新座標絕不越界
                        if (x >= 0 && x < n && y >= 0 && y < m) {
                            if (arr[x][y] == '*') {
                                mine_count++;
                            }
                        }	
                    }
                    cout << mine_count; // 輸出周圍相鄰的地雷加總數
                }
            }
            cout << "\n"; // 每列格子處理完畢後輸出換行
        }
        cases++; // Field 編號遞增
    }
    return 0;
}
```


## 進階優化思考

原做法直接輸出結果（On-the-fly Output），在空間上達到了最極致的優化，其時間與空間複雜度在當前規格下已無可挑剔。但從更高階的平行運算與圖形學角度思考，本題存在著另一種極具資工思維的優化框架。

**逆向地雷輻射預處理（Mine-Radiation 策略）**

在原解法中，我們是以「安全格子」為主體，向外尋找地雷（每個安全格掃描 8 次）。如果一張地圖非常大，且地雷數量極其稀少（稀疏矩陣），這種做法會包含大量對空白區域的無謂掃描。

* **原理**：可以反過來以「地雷」為主體。

* **做法**：初始開闢一個與地圖等大的整數陣列 `int result[105][105] = {0};` 。在讀入地圖時，一旦發現某個座標 `(j, k)` 是地雷 `*` ，就立刻對其周圍 8 個合法格子在 `result` 陣列中的數值進行 `+1` 累加。

* **效能改善**：這樣做等同於讓地雷向外發射能量輻射。掃描次數直接與地雷的實體數量 $K$ 綁定。當 $K \ll N \times M$ 時，這種逆向預處理技術能抹除掉安全區周圍的大量重複邊界比對，是處理大規模圖形遮罩與稀疏矩陣時非常核心的優化策略。
