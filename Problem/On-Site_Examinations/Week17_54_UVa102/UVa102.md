# UVa 102 - Ecological Bin Packing

## 題目簡述

有三個回收箱（編號分別為 1, 2, 3），每個回收箱內原本都混雜著三種不同顏色的玻璃瓶：
* **B** (Brown，棕色)
* **G** (Green，綠色)
* **C** (Clear，透明)

為了落實環保分類，目標是移動最少數量的玻璃瓶，使得**每個回收箱內最後「精確只能留有一種顏色」的玻璃瓶**，且三個回收箱對應的顏色不能重複（例如：箱 1 留棕色、箱 2 留透明、箱 3 留綠色）。

**輸入規範**：
每行輸入包含 9 個整數。前 3 個數代表箱 1 的 (B, G, C) 數量；中間 3 個數代表箱 2 的 (B, G, C) 數量；最後 3 個數代表箱 3 的 (B, G, C) 數量。

**輸出規範與字典序限制**：
請輸出**搬動次數最少**的最終顏色配置字串（由 3 個大寫字母組成，分別代表箱 1、箱 2、箱 3 的留存顏色）以及**最少的搬動瓶數**。
如果有多種不同的配置方案都能達到相同的最少搬動次數，**必須嚴格依照「字典順序（Alphabetical Order）」最小的那個配置字串優先輸出**。

**Sample Input**：

  **1 2 3 4 5 6 7 8 9** $\rightarrow$ 代表 3 個箱子內 B, G, C 的初始分佈數量。<br>
  **5 10 5 20 10 5 10 20 10**

**Sample Output**：

  **BCG 30** $\rightarrow$ 箱 1 留 B、箱 2 留 C、箱 3 留 G，最少只需搬動 30 個瓶子。<br>
  **CBG 50**


## 解題思路與排列組合窮舉

### 核心觀念：逆向思維與全排列字典序固化（Permutation & Negative Greedy）
這道題目的本質是**有限狀態空間的完全窮舉與字典序最優化控制**。
由於只有 3 個箱子和 3 種顏色，最終的合法排列組合總共只有 $3! = 6$ 種可能性。面對如此微小的狀態邊界，直接進行全枚舉（Brute-force Enumeration）是最安全且最高效的解題策略。

1. **逆向思維優化（Stay vs Move）**：<br>
   要計算「需要搬走多少瓶子」，如果正面去模擬每個瓶子從哪個箱子搬到哪個箱子，邏輯會變得異常繁瑣。

   * **最優化轉換**：可以反過來計算**「有多少瓶子可以留在原地不動（`stay`）」**。一旦知道了原地不動的最大瓶數，那麼「最少搬動次數」公式即可直接逆向推導為：
     $$\text{Moves} = \text{Total（全域所有瓶子總和）} - \text{Stay（當前配置下留在原地的瓶子總和）}$$

2. **字典序地雷防禦線（固化排列陣列）**：<br>
   題目要求在搬動次數相同時，必須輸出「字典序最小」的字串。
   這 6 種合法的顏色組合按字典序由小到大精確排列如下：
   $$\text{"BCG"} < \text{"BGC"} < \text{"CBG"} < \text{"CGB"} < \text{"GBC"} < \text{"GCB"}$$
   * **策略**：在程式碼中，我們可以直接宣告一個**已經嚴格按字典序由小到大排好序的字串陣列** `configs[]`。隨後利用 `for` 迴圈依序遍歷這 6 種配置。在比較最少搬動次數時，只有在遇到「嚴格小於（`moves < min`）」的情況下才更新最優解。這樣做能天然確保當次數相同時，最先被錄入的、字典序較小的字串絕對不會被後續較大的字串覆蓋，完美規避了排序的代價。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(1)$ <br>
  每組測試資料僅需執行一次全域瓶數加總（9 次加法），隨後進入一個固定執行 6 次的常數迴圈。在迴圈內部僅執行基本的陣列查表與下標比對，不含任何深度遞迴或大規模資料迴圈。因此，時間複雜度為絕對常數時間，可在幾微秒內瞬間出解。
* **空間複雜度**： $\mathcal{O}(1)$ <br>
  僅開闢一個大小為 9 的靜態整數陣列 `b[9]` 儲存輸入，以及少數幾個純量變數與常數配置字串，沒有任何動態記憶體開銷。


## 邊界條件與潛在陷阱

1. **一維陣列索引映射錯位（下標指引地雷）**：<br>
   這是本題最容易寫錯的細節。輸入的 9 個數字平鋪在 `b[9]` 中，其幾何映射結構必須極度精確地與代碼對齊：

   * **箱 1**：B 位於 `b[0]`、G 位於 `b[1]`、C 位於 `b[2]`。
   * **箱 2**：B 位於 `b[3]`、G 位於 `b[4]`、C 位於 `b[5]`。
   * **箱 3**：B 位於 `b[6]`、G 位於 `b[7]`、C 位於 `b[8]`。
   在進行 `stay` 累加時，各個分支的 `if-else` 下標必須嚴格對齊上述規則（例如 `config[1] == 'G'` 必須對應 `b[4]`），稍有錯位便會引發邏輯崩潰。
2. **多組測資 EOF 連續讀取**：<br>
   題目沒有告知共有幾組資料。必須使用 `while (cin >> b[0] >> ...)` 這種連續抽離 9 個數字的語法來監聽檔案流是否結束（EOF）。


## 程式碼實作

```cpp
#include <iostream>
#include <string>
#include <algorithm>
#include <climits>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int b[9];
    // 連續讀入 9 個整數，直到檔案結束 (EOF) 爲止
    while (cin >> b[0] >> b[1] >> b[2] >> b[3] >> b[4] >> b[5] >> b[6] >> b[7] >> b[8]) {
        
        // 計算全域所有回收箱內的玻璃瓶總量天花板
        int total = 0;
        for (int i = 0; i < 9; i++) {
            total += b[i];
        }
        
        int min_moves = INT_MAX; // 初始化全域最小搬動次數為極大值
        string best_config = "";
        
        // 核心精髓：將 6 種合法配置直接按照「標準字典順序」由小到大固化在陣列中
        string configs[] = { "BCG", "BGC", "CBG", "CGB", "GBC", "GCB" };

        // 依字典序由小到大開始窮舉
        for (string config : configs) {
            int stay = 0; // 紀錄目前配置下，有多少瓶子可以保留在原地不動
            
            // 階段一：評估回收箱 1 的留存顏色與原地瓶數
            if (config[0] == 'B') stay += b[0];
            else if (config[0] == 'G') stay += b[1];
            else if (config[0] == 'C') stay += b[2];

            // 階段二：評估回收箱 2 的留存顏色與原地瓶數
            if (config[1] == 'B') stay += b[3];
            else if (config[1] == 'G') stay += b[4];
            else if (config[1] == 'C') stay += b[5];

            // 階段三：評估回收箱 3 的留存顏色與原地瓶數
            if (config[2] == 'B') stay += b[6];
            else if (config[2] == 'G') stay += b[7];
            else if (config[2] == 'C') stay += b[8];

            // 逆向公式：當前搬動瓶數 = 總數 - 原地留存數
            int moves = total - stay;
            
            // 核心格式防禦：使用「嚴格小於 (<)」，確保當 moves 相等時，
            // 最先被錄入的、字典序最小的組合絕對不會被後方字典序較大的組合覆蓋
            if (moves < min_moves) {
                min_moves = moves;
                best_config = config;
            }
        }   
        // 輸出最佳配置字串與對應的最少搬動次數
        cout << best_config << " " << min_moves << "\n";
    }
    return 0;
}
```


## 進階優化思考
雖然目前的純手動 `if-else` 分支枚舉在時間上已經達到了極致的常數效率，但如果在資工的高階代碼維護性與簡潔度（Code Elegance）視角下，這種硬編碼下標的寫法較容易在複製時手誤打錯。存在一種改用二維矩陣與下標代數換算的優化重構手段。

**二維顏色矩陣與配置常數下標化**

* **原理**：可以把 9 個輸入整數直接看成一個 $3 \times 3$ 的二維矩陣，其中橫列（Row）代表箱子編號 0, 1, 2；行（Column）代表顏色代碼。

* **做法**：為了方便程式直接利用字元換算成行索引，可以統一將字母映射為：`'B' -> 0`, `'C' -> 1`, `'G' -> 2`（注意此處的順序也是依據 `'B' < 'C' < 'G'` 的字典序進行平鋪）。

* **效能改善**：此重構版本利用二維矩陣的幾何結構，將原先 9 行臃腫且重複性高的 `if-else` 分支代碼，精簡壓縮成了一條只有 3 次迭代的微型 `for` 迴圈。這大幅降低了代碼硬編碼打錯的風險，且由於消除了大量的條件分支判定，能有效幫助 CPU 執行更流暢的指令流水線（Pipeline）排程，是提升軟體工程強健性時非常推薦的重構範式。

**優化程式碼實作片段：**
```cpp
// 建立字元對應二維行索引的解析對齊
int color_map[26];
color_map['B' - 'A'] = 0;
color_map['C' - 'A'] = 1;
color_map['G' - 'A'] = 2;

string configs[] = { "BCG", "BGC", "CBG", "CGB", "GBC", "GCB" };
// 主迴圈內部讀入 3x3 矩陣：int grid[3][3];

for (string config : configs) {
    // 直接利用一條簡單的迴圈完成 3 個箱子的 stay 累加，完全抹除冗長的 if-else 分支
    int current_stay = 0;
    for (int box = 0; box < 3; box++) {
        char color = config[box];
        current_stay += grid[box][color_map[color - 'A']];
    }
    
    int moves = total - current_stay;
    // ... 後續常規比對 ...
}
```
