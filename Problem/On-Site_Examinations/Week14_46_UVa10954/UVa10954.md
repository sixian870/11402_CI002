# UVa 10954 - Add All

## 題目簡述

給定 $N$ 個正整數，需要將它們全部加總成一個單一的數字。
每次加法運算都需要付出與「該次兩數相加之和」等價的**代價（Cost）**。不同的相加順序會直接導致最終累積的總代價不同。
請計算出將這 $N$ 個數字完全合併後，**最小的總代價**是多少。

**Sample Input**：

  **3** $\rightarrow$ 第一組數字個數 $N = 3$。<br>
  **1 2 3** $\rightarrow$ 這 3 個整數。<br>
  **4** $\rightarrow$ 第二組數字個數 $N = 4$。<br>
  **1 2 3 4**<br>
  **0** $\rightarrow$ 當 $N = 0$ 時，代表輸入結束。

**Sample Output**：

  **9** $\rightarrow$ 先加 1+2=3 (Cost=3)，再加 3+3=6 (Cost=6)，總代價 $3+6=9$ 最省。<br>
  **19** $\rightarrow$ 最優順序為：(1+2=3, Cost=3) $\rightarrow$ (3+3=6, Cost=6) $\rightarrow$ (6+4=10, Cost=10)，總代價 $3+6+10=19$。


## 解題思路與貪婪策略

### 核心觀念：霍夫曼編碼原理與最小堆疊（Greedy / Min-Heap）
這道題目的本質是經典的**貪婪演算法（Greedy Algorithm）**，其核心數學模型與資料結構中的**霍夫曼樹（Huffman Tree）**建構完全同構。

為了讓每次相加所產生的暫存和最小，進而使最終累加的總代價（Cost）達到全域最低，採用的貪婪策略非常直觀：**「每一次都合併當前所有數字中，數值最小的兩個數」**。



因為數字在不斷合併的過程中會產生新的和，我們需要一個能動態維護並隨時抽取最小值的資料結構。這完美的對應到了**優先佇列（Priority Queue / 最小堆疊 Min-Heap）**。

### 演算法步驟
1. 讀入數字個數 $N$。當 $N = 0$ 時安全結束程式。
2. 宣告一個最小堆疊 `min_heap`，並在讀入 $N$ 個整數時將它們全數推入（`push`）堆疊中。在 C++ 中，標準宣告格式為：
   `priority_queue<long long, vector<long long>, greater<long long>> min_heap;`
3. 只要堆疊內部的數字個數大於 1（`min_heap.size() > 1`），就重複進行以下流式合併：
   * 取出當前最小的數字：`a = min_heap.top()`; `min_heap.pop()`;
   * 取出當前次小的數字：`b = min_heap.top()`; `min_heap.pop()`;
   * 計算本次相加和：`sum = a + b`。
   * 將本次產生的代價累加至總開銷：`cost += sum`。
   * 將新產生的和重新推入堆疊：`min_heap.push(sum)`，使其重新參與下一輪的最小排位比對。
4. 當堆疊中僅剩最後一個唯一數字時，代表合併完成，直接輸出累積的 `cost`。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \log N)$
  初始將 $N$ 個數字推入堆疊需耗時 $\mathcal{O}(N \log N)$。隨後進行合併迴圈，每輪操作堆疊長度精確減少 1，因此共執行 $N-1$ 輪。在每輪中，對二元堆疊執行 `top`、`pop` 與 `push` 的時間複雜度皆為對數時間 $\mathcal{O}(\log N)$。總體平攤時間複雜度為 $\mathcal{O}(N \log N)$，即使在最大限制 $N \le 5,000$ 的大測資下，總運算次數也僅約 $6 \times 10^4$ 次，可在幾毫秒內極速通關。
* **空間複雜度**： $\mathcal{O}(N)$
  最小堆疊 `min_heap` 在初始狀態下需要配置儲存空間來存放這 $N$ 個整數，空間開銷與輸入數據規模呈線性正比。


## 邊界條件與潛在陷阱

1. **總代價整數溢位地雷（大數防禦）**：
   這是本題最致命的 Wrong Answer 陷阱。雖然輸入的單個數字可能符合標準 32 位元有號整數（`int`）的範圍。但因為較小的數字會被重複加總並層層向上疊加（例如在長度為 5000 且數值較大時），最終累積的 `cost` 總代價極有可能會跨越 $2 \times 10^9$ 的上限，引發**整數溢位（Integer Overflow）**。

   * **原程式碼漏洞**：原程式碼中，`min_heap` 的底層元素雖然宣告為 `long long`，但內部暫存的 `sum`、`a`、`b` 以及最核心的計費器 `cost` 卻全數宣告為了 `int`。這會導致數據在出堆疊相加後直接發生溢位截斷，算出的總代價變成不符合邏輯的負數。**必須將與計費、相加相關的所有變數全部升級為 `long long`**。
3. **$N = 1$ 的單一數字邊界**：
   若輸入 $N = 1$，牌堆中只有一個數字。此時 `while (min_heap.size() > 1)` 條件不成立，迴圈不執行，`cost` 保持初始值 0 並直接輸出。這符合物理邏輯，因為沒有發生任何加法運算，代價為 0。


## 程式碼實作

```cpp
#include <iostream>
#include <vector>
#include <queue>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n;
    // 連續讀入數字總數 n，當 n = 0 時終止
    while (cin >> n && n != 0) {
        
        // 宣告標準庫最小堆疊 (Min-Heap)，確保頂端永遠是全域最小值
        priority_queue<long long, vector<long long>, greater<long long>> min_heap;
        
        for (int i = 0; i < n; i++) {
            long long val;
            cin >> val;
            min_heap.push(val);
        }
        
        // 核心防禦：總代價與合併暫存變數一律使用 long long 嚴格防範溢位
        long long total_cost = 0; 
        
        // 持續合併，直到堆疊內只剩最後一個融合完畢的數字
        while (min_heap.size() > 1) {
            long long a = min_heap.top(); // 抽取出當前最小的數
            min_heap.pop();
            
            long long b = min_heap.top(); // 抽取出當前次小的數
            min_heap.pop();
            
            long long current_sum = a + b; // 執行貪婪合併
            total_cost += current_sum;     // 累加本次產生的代價開銷
            
            min_heap.push(current_sum);    // 將新產生的和推回堆疊重新排序
        }
        
        // 輸出全域最優合併總代價
        cout << total_cost << "\n";
    }
    return 0;
}
```


## 進階優化思考

**記憶體連續性與自定義堆疊容器**

在目前的 C++ 實作中， `std::priority_queue` 預設是基於 `std::vector` 來作為底層容器（透過 `std::make_heap` 等演算法在連續記憶體上建立二元樹結構）。這種連續記憶體排布對 CPU 的快取非常友好，執行效率極佳。

如果我們想進一步降低常數時間成本，可以注意避免在迴圈內部反覆進行零碎的變數重新配置。將 `a` , `b` , `current_sum` 宣告在 `while` 迴圈外部，能讓編譯器在生成組合語言時，直接將這些變數鎖定在 CPU 的核心暫存器（Registers）中進行滾動移位，免去記憶體堆疊框架（Stack Frame）的反覆讀寫，從而將常數級效能壓榨到極致。
