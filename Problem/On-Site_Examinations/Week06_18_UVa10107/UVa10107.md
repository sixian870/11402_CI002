# UVa 10107 - What Is the Median?

## 題目簡述

讀取一長串的整數序列。每當讀入一個全新的整數時，就必須立刻計算出到目前為止，所有已讀入數字的 **「中位數（Median）」** 並將其輸出。<br>
* 若當前讀入的總個數為**奇數**：中位數為排序後正中間的那個數。
* 若當前讀入的總個數為**偶數**：中位數為排序後正中間兩個數的**平均值**（題目規範此平均值直接無條件捨去小數點，以整數輸出）。

**Sample Input**：

  **1** $\rightarrow$ 第 1 個數字讀入，目前序列：[1]。<br>
  **3** $\rightarrow$ 第 2 個數字讀入，目前序列：[1, 3]。<br>
  **4** $\rightarrow$ 第 3 個數字讀入，目前序列：[1, 3, 4]。<br>
  **60** $\rightarrow$ 第 4 個數字讀入，目前序列：[1, 3, 4, 60]。<br>
  **70** $\rightarrow$ 第 5 個數字讀入，目前序列：[1, 3, 4, 60, 70]。<br>
  **50** $\rightarrow$ 第 6 個數字讀入，目前序列：[1, 3, 4, 50, 60, 70]。<br>
  **2** $\rightarrow$ 第 7 個數字讀入，目前序列：[1, 2, 3, 4, 50, 60, 70]。

**Sample Output**：

  **1** $\rightarrow$ [1] 的中位數為 1。<br>
  **2** $\rightarrow$ [1, 3] 的中位數為 $(1 + 3) / 2 = 2$。<br>
  **3** $\rightarrow$ [1, 3, 4] 的中位數為 3。<br>
  **3** $\rightarrow$ [1, 3, 4, 60] 的中位數為 $(3 + 4) / 2 = 3$。<br>
  **4** $\rightarrow$ [1, 3, 4, 60, 70] 的中位數為 4。<br>
  **27** $\rightarrow$ [1, 3, 4, 50, 60, 70] 的中位數為 $(4 + 50) / 2 = 27$。<br>
  **4** $\rightarrow$ [1, 2, 3, 4, 50, 60, 70] 的中位數為 4。


## 解題思路與中位數特性

### 核心觀念：動態維護有序數列
這道題目的本質是**動態串流資料（Data Stream）的中位數維護**。
在暴力模擬的邏輯下，每當透過 `cin >> n` 讀入一個新的數字，就將其放入陣列末尾（`push_back`），隨即對整個陣列調用 `std::sort` 重新進行從小到大的升序排列，接著依據資料總個數的奇偶性進行查表輸出：

* 假設總長度為 `size`：
  * 若 `size` 為奇數：中位數直接位於索引 `size / 2`。
  * 若 `size` 為偶數：中間的兩個數分別位於索引 `size / 2` 與 `size / 2 - 1`，將兩者相加後除以 2。由於 C++ 整數除法原本就會無條件捨去小數點，因此直接用 `/ 2` 即可符合題目規範。

### 演算法步驟
1. 建立一個 `vector<long long> arr` 來動態存放陸續讀入的整數。
2. 透過 `while (cin >> n)` 持續讀入數字直到輸入流結束（EOF）。
3. 將新數字推入 `arr`，並執行 `sort(arr.begin(), arr.end())` 以確保數列的遞增有序性。
4. 檢查 `arr.size()` 的奇偶狀態，計算對應的中位數並即時輸出。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N^2 \log N)$
  其中 $N$ 為輸入的整數總個數。在暴力法中，每讀入一個數字都要做一次完整的排序，而第 $i$ 次排序耗時 $\mathcal{O}(i \log i)$。將 $1$ 到 $N$ 次排序的開銷進行積分累加，總時間複雜度會退化到 $\mathcal{O}(N^2 \log N)$。
* **空間複雜度**： $\mathcal{O}(N)$
  需要動態配置一個大小為 $N$ 的 `vector` 陣列來容納流式輸入的所有整數，空間開銷與輸入長度呈線性正比。


## 邊界條件與潛在陷阱

1. **整數相加溢位陷阱**：
   題目規範輸入的數字可以高達 $2^{31}$，這已經逼近或等於標準 32 位元有號整數（`int`）的最大上限。如果兩個極大的數字在偶數狀態下相加（如 `m1 + m2`），將會直接觸發 **整數溢位（Integer Overflow）** 而變成負數，進而輸出錯誤的答案。**因此，儲存陣列、輸入變數以及中間的中位數變數，必須全數宣告為 `long long`。**
2. **偶數均值的整數截斷行為**：
   題目要求偶數長度時的平均值「直接取整數部分」。C++ 的整數除法（如 `5 / 2` 得到 `2`）之行為天生就是向零截斷（無條件捨去），這與題目要求完全不謀而合，不需額外調用 `floor()` 或進行浮點數轉換。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    long long n;
    vector<long long> arr; // 使用 long long 儲存，避免後續大數相加時發生溢位
    
    // 連續讀入整數直到檔案結束 (EOF)
    while (cin >> n) {
        arr.push_back(n); // 將新數字插入動態陣列末端
        
        // 暴力排序：維持陣列的升序排列
        sort(arr.begin(), arr.end());
        
        int size = arr.size();
        // 狀態一：當前總個數為奇數
        if (size % 2 != 0) {
            cout << arr[size / 2] << "\n"; // 正中間數字的索引剛好為 size/2
        } 
        // 狀態二：當前總個數為偶數
        else {
            long long m1 = arr[size / 2];     // 右側核心中位數
            long long m2 = arr[size / 2 - 1]; // 左側核心中位數
            cout << (m1 + m2) / 2 << "\n";    // 整數除法會自動無條件捨去小數
        }
    }
    return 0;
}
```


## 進階優化思考
原解法每次都進行完整排序（ $\mathcal{O}(N \log N)$ ），但在面試或高階演算法設計中，這是一個非常經典的優化場景。我們根本不需要將整個陣列完整排序，只需要能動態抓取中間的值即可。

**優化方法一：插入排序法（Insertion Sort, $\mathcal{O}(N^2)$）**

既然之前的陣列已經是有序的，每當新進來一個數字，不需要重新全面排序。只需利用 std::upper_bound 找到它該插入的位置，再用 vector::insert 把它塞進去。

* **效能改善**：單次插入耗時從 $\mathcal{O}(N \log N)$ 降至 $\mathcal{O}(N)$（主要花費在挪動記憶體），總複雜度降為 $\mathcal{O}(N^2)$。

**優化方法二：雙堆積機制（Dual Heaps / Max-Min Heap, $\mathcal{O}(N \log N)$）**

這是大數據串流處理中最優雅的標準解法。我們在記憶體中維護兩個優先佇列（Priority Queue / Heap）：

  1. **最大堆積（Max-Heap）**：用來儲存數列中「較小的那前半段」數字，堆積頂端為前半段的最大值。
  2. **最小堆積（Min-Heap）**：用來儲存數列中「較大的那後半段」數字，堆積頂端為後半段的最小值。
  
每當新數字進來：

  * 若小於最大堆積頂端，則推入最大堆積；反之則推入最小堆積。 
  * 動態平衡：確保兩邊的元素個數差不超過 1。
  * 計算中位數：若總數為奇數，中位數就是元素較多的那個堆積的頂端值；若為偶數，中位數就是兩邊堆積頂端值的平均值。
  * 效能改善：每一次插入與平衡均只需要 $\mathcal{O}(\log N)$，總複雜度成功被壓低至頂級的 $\mathcal{O}(N \log N)$，且單次查詢達到 $\mathcal{O}(1)$，這是處理海量資料串流時最優秀的演算法變體。
