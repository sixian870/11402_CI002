# UVa 410 - Station Balance

## 題目簡述

有 $C$ 個離心機艙室（Stations），以及 $S$ 個要進行分配的藥品標本（Species）。每個標本 $i$ 都有一個特定重量 $w_i$。我們的任務是將這 $S$ 個標本分配到這 $C$ 個艙室中，使得每個艙室最多只能容納 **2 個標本**。如果標本數量不夠，艙室也可以保持全空或只放 1 個標本。

為了讓離心機運轉平衡，我們希望每個艙室的總重量盡量接近所有艙室的「理論平均重量」$A$ 。
* **理論平均重量** $A$ 的計算公式為：
  $$A = \frac{\sum_{i=1}^{S} w_i}{C}$$
* **不平衡度（Imbalance）** 定義為每個艙室實體總重量與平均重量 $A$ 的絕對差值總和：
  $$\text{Imbalance} = \sum_{j=1}^{C} |X_j - A|$$
  其中 $X_j$ 為第 $j$ 個艙室分配到的標本總重量。

請設計一套分配策略，找出能使 **Imbalance 達到最小** 的方案，並依序輸出每個艙室的分配狀況與最終的不平衡度值。

**Sample Input**：

  **2 3** $\rightarrow$ 第一組測資： $C = 2$ 個艙室， $S = 3$ 個標本。<br>
  **1 2 3** $\rightarrow$ 這 3 個標本各自的重量。

**Sample Output**：

  **Set #1**<br>
  **_0: 1 3** $\rightarrow$ 第 0 個艙室放重量 1 與 3 的標本（總重 4）。<br>
  **_1: 2** $\rightarrow$ 第 1 個艙室只放重量 2 的標本。<br>
  **IMBALANCE = 1.00000** $\rightarrow$ 平均重為 (1+2+3)/2 = 3。不平衡度為 $|4-3| + |2-3| = 2.0$？不，注意此時有漏洞，最優分配其實是 $0: 1\ 2$ 與 $1: 3$，其 Imbalance 才是 1.00000。


## 解題思路與考點分析

### 核心觀念：貪婪演算法與庫底雙向卡位策略（Greedy Algorithm / Pairwise Matching）
這道題目的本質是經典的**貪婪策略分組優化**。
題目規定「每個艙室最多隻能放 2 個標本」，且總艙室數為 $C$。這意味著整台離心機最多隻能承載 $2C$ 個標本。

為了達成最完美的配對，我們可以採取以下貪婪步驟：
1. **補零對齊（Padding）**：
   如果實際的標本數 $S < 2C$，代表一定會有艙室處於「全空」或「只裝 1 個標本」的狀態。為了讓數學模型一律簡化為「每艙精確塞 2 個物件」，我們直接建立一個長度為 $2C$ 的陣列，將前 $S$ 個位置填入標本重量，其餘空缺位置一律補上 `0`。
2. **單調性排序（Sorting）**：
   將這包含虛擬零在內的 $2C$ 個元素進行升序排序。此時，最小的元素（可能是虛擬的 0）會被擠到最左端，最大的標本則會集中在最右端。
3. **首尾互補配對（Two-Pointer Matching）**：
   最優化分組的貪婪真理是：**讓當前最輕的物件與當前最重的物件鎖在同一個艙室。**
   利用雙指標從兩端向中間逼近，將第 $i$ 個元素（最輕）與第 $2C - 1 - i$ 個元素（最重）強制歸類到第 $i$ 個艙室。這種首尾對稱相加的組合，能讓每個艙室的實體重量最均勻地向平均值 $A$ 收斂，從而完美證明能導出最小的 Imbalance。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(C \log C)$ <br>
  主要的時間開銷集中在排序長度為 $2C$ 的一維陣列。使用 `std::sort` 耗時為 $\mathcal{O}(2C \log(2C)) = \mathcal{O}(C \log C)$。後續輸出與計算 Imbalance 只需要一條單層 `for` 迴圈跑 $C$ 次，耗時為 $\mathcal{O}(C)$。因此，總體執行時間完全由排序主導，在給定範圍內可在幾毫秒內極速通過。
* **空間複雜度**： $\mathcal{O}(C)$ <br>
  需要開闢一個長度固定為 $2C$ 的 `std::vector<int>` 陣列來存放標本與虛擬補零，記憶體開銷與艙室數量呈線性正比，對記憶體極度友善。


## 邊界條件與潛在陷阱

1. **格式對齊與雙重虛擬零隱藏（Output Formatting）**：
   題目要求在印出艙室內容時，虛擬補上去的 `0` **絕對不能被印出來**。

   * **程式碼防禦**：在內部遍歷時，利用 `if (a[i] != 0)` 與 `if (a[n - 1 - i] != 0)` 進行雙重過濾。只有當權重為正整數時才印出。這既達成了利用補零簡化核心演算法的目的，又確保了外部文本規格的純淨。此外，艙室編號必須使用 `setw(2)` 進行寬度為 2 的右對齊排版。
2. **多組測資計數器與空行隔離**：
   每組測試資料開頭必須印出 `Set #X`，且每組輸出的最尾端必須包含**兩個換行符**（即精確以一個空行隔開）。原實作在 `IMBALANCE = ...` 後方直接追加 `\n\n`，完美符合 UVa 評測系統對幾何空白的嚴格要求。


## 程式碼實作
```cpp
#include <iostream>
#include <vector>
#include <numeric>
#include <algorithm>
#include <cmath>
#include <iomanip>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int C, S;
    int TC = 0; // 追蹤當前的測試資料組數 (Test Case Counter)
    
    // 連續讀入艙室數 C 與標本數 S，直到檔案結束 (EOF)
    while (cin >> C >> S) {
        int n = 2 * C; // 每個艙室最多放 2 個，總共需要 2C 個卡位點
        vector<int> a(n, 0); // 初始化長度為 2C 的陣列，預設全部補零
        double sum = 0.0;
        // 讀入實體標本重量，並動態累加總重
        for (int i = 0; i < S; i++) {
            cin >> a[i];
            sum += a[i];
        }
        // 計算理論平均重量 A
        double avg = sum / C;
        // 進行升序排序，使最小者（含虛擬零）與最大者分別歸位在首尾兩端
        sort(a.begin(), a.end());
        
        double imbalance = 0.0;
        cout << "Set #" << ++TC << "\n";
        
        // 核心對稱貪婪流：走訪 C 個艙室
        for (int i = 0; i < C; i++) {
            // 嚴格依照題目規範：編號佔 2 格寬度右對齊
            cout << setw(2) << i << ":";
            
            // 貪婪配對：左端最輕者 a[i] 與 右端最重者 a[n - 1 - i] 鎖定在同一個艙室
            // 隱藏虛擬零：若數值為 0 代表該位置是我們補的空位，不予印出
            if (a[i] != 0) {
                cout << " " << a[i];
            }
            if (a[n - 1 - i] != 0) {
                cout << " " << a[n - 1 - i];
            }
            // 累加當前艙室實體總重與理論平均值的絕對差值
            imbalance += abs(a[i] + a[n - 1 - i] - avg);
            cout << "\n";
        }
        // 精確輸出不平衡度至小數點後 5 位，並在組別間保留一個空行
        cout << "IMBALANCE = " << fixed << setprecision(5) << imbalance << "\n\n";
    }
    return 0;
}
```


## 進階優化思考

**記憶體就地複用與快取行優化（Cache Line Tuning）**

雖然目前的實作在空間開銷上已經極低，但在高併發、海量多組測資反覆輸入的極限競賽環境下，動態在 `while` 迴圈內部重複執行 `vector<int> a(n, 0)` 會導致作業系統反覆在 Heap 區塊上進行記憶體的申請與銷毀（Allocation/Deallocation），這會產生零碎的記憶體片段。

* **優化做法**：由於題目中 $C$ 的範圍通常很小（一般 $C \le 10$），我們可以在全域或者 `main` 函式開頭直接宣告一個固定長度為 40 的原生靜態陣列 `int a[40]`。

* **技術精髓**：在每輪讀入新數據前，直接調用 `memset(a, 0, sizeof(a))` 或者用一條快速迴圈清除歷史資料。這種原地覆寫（In-place Overwrite）的方式完全抹除了動態配置的負擔。更重要的是，連續 40 個整數的物理空間只有 160 位元組，能完美一次性塞進 CPU 的 L1 快取行（Cache Line）中。排序與雙指標走訪時，所有資料存取皆在極速暫存器與核心快取內完工，能將底層常數級的執行效能壓榨至物理極限。
