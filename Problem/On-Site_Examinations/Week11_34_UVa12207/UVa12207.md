# UVa 12207 - That is Your Queue

## 題目簡述

在一個國家的某間大型公立醫院內，有 $P$ 位公民（編號由 $1$ 到 $P$）正在依序排隊等待看診。初始狀態下，隊伍完全按照編號 $1, 2, 3, \dots, P$ 的順序由前向後平鋪排列。<br>
整個排隊系統會連續接收到 $C$ 個指令，指令分為以下兩種核心運作模式：
1. **`N` (Next)**：代表目前隊伍中最前方的公民進入診間看診。程式必須**印出該公民的編號**。看診完畢後，該公民並不會離開系統，而是會被重新移至整個隊伍的**最後方**重新排隊。
2. **`E x` (Expedite)**：代表編號為 $x$ 的公民獲得了緊急綠色通道特權。如果該公民目前已經在隊伍中，他會**從目前的排隊位置被抽離**，並直接**插隊至整個隊伍的最前方（第一位）**；如果他目前不在隊伍中（例如他之前看過診或被擠出常規範圍），則會直接被建立並強行放置到隊伍的最前端。

當輸入的總人數 $P = 0$ 且指令數 $C = 0$ 時，代表整個輸入流結束。

**Sample Input**：

  **3 6** $\rightarrow$ 第一組測資：總人數 $P = 3$，指令數 $C = 6$。<br>
  **N** $\rightarrow$ 指令 1：第一位看診。<br>
  **N**<br>
  **E 1** $\rightarrow$ 指令 3：將編號 1 的公民插隊至最前面。<br>
  **N**<br>
  **N**<br>
  **N**<br>
  **0 0** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **Case 1:** $\rightarrow$ 每組測試資料必須依序輸出編號標頭。<br>
  **1** $\rightarrow$ 初始順序 `1 2 3`，第一個 'N' 輸出 1，順序變為 `2 3 1`。<br>
  **2** $\rightarrow$ 第二個 'N' 輸出 2，順序變為 `3 1 2`。<br>
  $\rightarrow$ `E 1` 執行，將 1 抽離並置頂，順序變為 `1 3 2`。<br>
  **1** $\rightarrow$ 第三個 'N' 輸出 1，順序變為 `3 2 1`。<br>
  **3** $\rightarrow$ 第四個 'N' 輸出 3，順序變為 `2 1 3`。<br>
  **2** $\rightarrow$ 第五個 'N' 輸出 2，順序變為 `1 3 2`。


## 解題思路與雙端佇列優化

### 核心觀念：動態隊列模擬與人口規模剪枝（Population-Capping Strategy）
這道題目的本質是**雙端佇列（Double-ended Queue）的靈活調度與大規模邊界剪枝優化**。
題目給定的人數上限高達 $P \le 1,000,000,000$（十億級別），而指令總數卻非常少（ $C \le 1000$ ）。

如果無腦宣告一個大小為十億的陣列或佇列去儲存所有公民，在初始化的第一步 `for` 迴圈就會直接引發**記憶體損耗破表（MLE）**與**時間超時（TLE）**。

為了破解十億人排隊的困境，需要引入資工非常核心的 **「上界約束剪枝」** 思維：
* **關鍵觀察**：雖然總共有十億人，但總指令數 $C$ 最大只有 1000 次。這代表即使每次指令都是 `N`，也最多只有前 1000 個人有機會看到診。編號大於 $C$ 的公民（例如第 1001 個人到第十億個人），在整個模擬過程中**永遠只會待在隊伍後半段當背景牆，絕對不可能滾動到隊伍前方**。
* **剪枝策略**：可以將初始放入隊伍的人數上限卡死在 `limit = min(P, (long long)C)`。這樣做能將佇列的實體體積從驚人的十億直接壓縮至最大不超過 1000 的極小規模。

### 數據結構：`std::deque` 的雙端操作
由於我們需要頻繁地在隊伍的**最前端**進行讀取（`front`）、刪除（`pop_front`）與強行插隊（`push_front`），同時需要在看診完後將人丟到**最尾端**（`push_back`），C++ 標準庫中的 **`std::deque`** 是完美契合此幾何結構的底層容器。

* **`N` 指令流程**：讀取 `dq.front()` 並輸出 $\rightarrow$ `dq.pop_front()` 移除 $\rightarrow$ `dq.push_back()` 丟到屁股。
* **`E x` 指令流程**：利用 `std::find` 在 `deque` 連續記憶體區塊中線性搜尋數值 `x`。若找到（`it != dq.end()`），則調用 `dq.erase(it)` 將其從陣列中抽空，最後調用 `dq.push_front(x)` 將其強行頂高至第一位。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(C \times \min(P, C))$ <br>
  經過上界剪枝後，`std::deque` 內部的最大長度被嚴格約束在 $M = \min(P, C)$ 內（最大為 1000）。<br>
  對於每次 `E x` 指令，`std::find` 搜尋與 `dq.erase` 節點移除在最壞情況下的代價皆為線性 $\mathcal{O}(M)$。因此，在經歷總共 $C$ 次指令後，整體的總時間複雜度上限為 $\mathcal{O}(C \times \min(P, C))$。代入最大值 $1000 \times 1000 = 10^6$ 次運算，可在 1 毫秒內瞬間收工。
* **空間複雜度**： $\mathcal{O}(\min(P, C))$ <br>
  `std::deque` 物件在記憶體中維護的節點數上限固定為 1000 個 `long long` 空間，空間開銷由原先的幾 GB 劇烈萎縮至不超過 8 KB，空間性能達到了極致優化。


## 邊界條件與潛在陷阱

1. **十億規模的整數溢位防禦（Integer Overflow）**：<br>
   因為總人數 $P$ 的最大限制為 $10^{9}$，這個數值已經逼近了標準 32 位元有號整數（`int`）的上限天花板（ $2.14 \times 10^9$ ）。如果在進行 `min(P, (long long)C)` 比對或在 `for` 迴圈遞增時稍有不慎，極易觸發整數溢位地雷。**因此，儲存人數與編號的所有關鍵變數（`P`, `limit`, `i`, `x`）必須嚴格宣告為 `long long`**。原程式碼的型態防禦做的非常到位。
2. **插隊元素已被移至後方的二重覆蓋判定**：<br>
   在處理 `E x` 指令時，利用 `find` 搜尋如果找到了，就將其移除再置頂。這種「先刪除再插隊」的邏輯，完美相容了「該特權公民原本究竟是處在初始隊伍中，還是之前看過診已經滾動到屁股後面」的所有複雜位置情境，邏輯完全無懈可擊。
3. **終止符 0 0 的控制**：<br>
   最外層必須使用 `while (cin >> P >> C && (P != 0 || C != 0))` 進行精確對齊攔截。


## 程式碼實作

```cpp
#include <iostream>
#include <deque>
#include <algorithm>
#include <string>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    long long P; // 總人數最大可達 10^9，必須指定為 long long
    int C;       // 指令數最大為 1000
    int count = 1;
    
    // 持續讀入 P 與 C，直到兩者皆為 0 時安全終止
    while (cin >> P >> C && (P != 0 || C != 0)) {
        cout << "Case " << count++ << ":\n";
        
        deque<long long> dq;
        // 因為最多只有 C 次看診機會，大於 C 的人永遠不可能排到前面，直接卡死上限
        long long limit = min(P, (long long)C);
        for (long long i = 1; i <= limit; i++) {
            dq.push_back(i);
        }
        
        // 開始依序處理 C 個指令
        while (C--) {
            char cmd;
            cin >> cmd;
            
            if (cmd == 'N') {
                // Next 決策：讀取目前隊伍第一人並印出
                long long current = dq.front();
                cout << current << "\n";
                
                // 移出前端並重新推入佇列的最末尾
                dq.pop_front();
                dq.push_back(current);
            }
            else if (cmd == 'E') {
                long long x;
                cin >> x; // 讀取獲得緊急特權的公民編號
                
                // 在雙端佇列中線性尋找該公民的實體位置
                auto it = find(dq.begin(), dq.end(), x);
                
                // 若找到，代表他在目前的有效縮減隊伍中，將其從原位置抽離抹除
                if (it != dq.end()) {
                    dq.erase(it);
                }
                dq.push_front(x);
            }
        }
    }
    return 0;
}
```


## 進階優化思考

雖然利用 `min(P, C)` 的限制將 `deque` 縮減至 1000 規模後， `std::find` 的線性搜尋開銷在實務上已經快如閃電。但如果從最頂尖的資工演算法架構來挑剔， `std::deque::erase` 在刪除中間節點時，會引發陣列元素的連續記憶體搬移（Memory Shifting）。

如果我們想完全抹除這個 $\mathcal{O}(M)$ 的搬移開銷，存在一種能將單次插隊與刪除優化到絕對 $\mathcal{O}(1)$ 常數時間 的高階複合資料結構。

**雙向鏈結串列配合雜湊映射指針（List + Unordered_Map 策略）**

* **原理**： `std::list`（雙向鏈結串列）在刪除任意節點與在最前端插入節點時，本質上都只需要修改左右指標的指向，耗時為純粹的 $\mathcal{O}(1)$。但鏈結串列不支援隨機存取，無法快速定位 `x`。

* **做法**：可以另外開闢一個雜湊表 `unordered_map<long long, list<long long>::iterator> pos_map;`。

  * **Key** 儲存公民的編號 `x`。

  * **Value** 直接儲存該公民在 `std::list` 內部所對應的實體記憶體節點指標（Iterator）。
 
  * 當遇到 `E x` 時，直接去雜湊表中花費 $\mathcal{O}(1)$ 查出他的記憶體地址指標，隨後調用 `dq.erase(it)`（鏈結串列的擦除是指標斷開，耗時 $\mathcal{O}(1)$），最後 `dq.push_front(x)` 並更新雜湊表中的指標。
 
* **效能改善**：此重構架構將整個排隊系統的單次查詢與插隊代價推向了完美的 $\mathcal{O}(1)$。它完全消除了 `std::vector` 或 `std::deque` 在記憶體中進行區塊位移的物理代價，是高階後端作業系統核心在處理大規模行程排程（Process Scheduling, 如 LRU Cache 機制）時最正統與最高階的標準設計範式。

* **優化程式碼改善：**
```cpp
  list<long long> competitors;
unordered_map<long long, list<long long>::iterator> pos_map;

// 遇到 E x 時：
auto map_it = pos_map.find(x);
if (map_it != pos_map.end()) {
    competitors.erase(map_it->second); // O(1) 指標斷開，零記憶體搬移開銷
}
competitors.push_front(x); // O(1) 置頂
pos_map[x] = competitors.begin(); // 更新雜湊映射位址
```
