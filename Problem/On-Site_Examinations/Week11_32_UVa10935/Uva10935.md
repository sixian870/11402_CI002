# UVa 10935 - Throwing cards away I

## 題目簡述

桌上有一疊編號從 $1$ 到 $N$ 的牌，牌堆由上到下依序為 $1, 2, 3, \dots, N$。<br>
只要牌堆中剩餘的牌數大於或等於 2 張，就必須重複執行以下兩項固定的洗牌動作：
1. **丟棄頂端牌**：將目前牌堆最上方的牌拿走並丟棄。
2. **移移底端牌**：將目前丟棄後新的最上方那張牌，移到整疊牌堆的最下方（底部）。

請依序輸出每次被丟棄的牌的編號序列（Discarded cards），以及最後留在牌堆中的那張唯一的牌的編號（Remaining card）。

**Sample Input**：

  **7** $\rightarrow$ 第一組測資 $N = 7$ 張牌。<br>
  **1** $\rightarrow$ 第二組測資 $N = 1$ 張牌。<br>
  **0** $\rightarrow$ 當讀取到 0 時，代表輸入結束。

**Sample Output**：

  **Discarded cards: 1, 3, 5, 7, 4, 2**<br>
  **Remaining card: 6** $\rightarrow$ 依規則操作後，7 張牌剩餘 6。<br>
  **Discarded cards:** $\rightarrow$ 只有 1 張牌時，沒有任何牌被丟棄（冒號後直接換行）。<br>
  **Remaining card: 1**


## 解題思路與先進先出模型

### 核心觀念：佇列（Queue）的先進先出（FIFO）特性
這道題目的本質是經典的**卡牌數據流模擬題**，其核心運作機制完美契合了資料結構中的**佇列（Queue）**模型。
牌堆的運作屬於「最先放進底部的牌，必須等前面的牌都處理完後才能輪到它」，這正是先進先出（First In, First Out）的幾何構造。

1. **初始建構**：將數字 $1$ 到 $N$ 依序推入（`push`）佇列 `r` 中，模擬初始的卡牌排列。
2. **模擬迴圈**：只要佇列內部的元素個數大於 1（`r.size() > 1`），就持續執行雙重流式操作：
   
   * **步驟一**：讀取佇列前端的丟棄牌（`r.front()`），將其推入記錄陣列 `d` 中，隨後調用 `r.pop()` 將其從牌堆中徹底移除。
   * **步驟二**：此時牌堆有了新的頂端牌。讀取此時的 `r.front()`，先將其推入佇列末尾 `r.push(r.front())`，隨後再執行 `r.pop()` 將頂端的舊分身抹除。這樣就成功完成了「移到最下方」的物理位移。
3. **格式化輸出**：依照題目要求的標點符號與空格規範，將丟棄序列與殘留牌印出。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N)$
  每執行一輪洗牌動作，佇列的長度就會精確減少 1。因此，對於 $N$ 張牌，內層的 `while` 迴圈剛好會執行 $N-1$ 次。在迴圈內部，無論是 `front`、`push` 還是 `pop`，皆為 `std::queue` 在常數時間 $\mathcal{O}(1)$ 內完成的核心操作。總體時間複雜度與卡牌總數 $N$ 呈完全的線性正比。題目限制 $N \le 50$，可在微秒級別內瞬間收工。
* **空間複雜度**： $\mathcal{O}(N)$
  需要一個 `std::queue<int> r` 來儲存當前的牌堆狀態，以及一個 `vector<int> d` 陣列來緩衝被丟棄的序列。這兩個資料結構的最大長度皆不超過 $N$，空間開銷極低。


## 邊界條件與潛在陷阱

1. **$N = 1$ 的極端臨界情況**：
   這是本題最容易踩到的 Wrong Answer 格式地雷。當輸入 $N = 1$ 時，由於 `r.size() > 1` 條件直接不成立，內部洗牌迴圈完全不會執行，`d` 陣列保持為空。

   * **格式要求**：此時必須輸出 `Discarded cards:`，注意**冒號後方不接任何空格，且必須直接換行**。原程式碼中的輸出邏輯利用了迴圈 `j < d.size()`，當長度為 0 時迴圈不走，完美避免了多餘空格的產生，格式完全過關。
3. **逗號分隔格式控制**：
   丟棄的數列之間必須以 `, `（一個逗號加上一個空格）來進行分隔，且**最後一個數字的後面絕對不能殘留多餘的逗號**。原程式碼中利用 `if (j == 0)` 的特判機制，在印第一個數字時不加逗號，從第二個數字開始才在前方補上 `, `，這是一項非常穩健且乾淨的去尾技巧。
4. **輸入終止符 0 的攔截**：
   最外層必須使用 `while (cin >> n && n != 0)` 進行精確控制，確保讀到 0 時能立即收線，防止其進入內層配置引發錯誤。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n;
    // 連續讀入牌數 n，當 n = 0 時代表整個輸入流結束
    while (cin >> n && n != 0) {
        queue<int> r;  // 模擬先進先出的卡牌牌堆
        vector<int> d; // 儲存依序被丟棄的卡牌序列
        
        // 初始化：由上至下填入 1 到 n 的卡牌編號
        for (int i = 1; i <= n; i++) {
            r.push(i);
        }
        
        // 核心洗牌機制：只要牌堆剩餘張數大於 1，就持續執行模擬
        while (r.size() > 1) {
            // 動作一：將最上方的牌推入丟棄紀錄，並從牌堆移除
            d.push_back(r.front());
            r.pop();
            
            // 動作二：將此時新的最上方牌，複製推入整疊牌的最底部，隨後抹除頂端舊值
            r.push(r.front());
            r.pop();
        }
        
        // 格式化輸出：印出被丟棄的數列
        cout << "Discarded cards:";
        for (int j = 0; j < (int)d.size(); j++) {
            if (j == 0) {
                cout << " " << d[0]; // 第一個數字前僅補一個常規空格
            }
            else {
                cout << ", " << d[j]; // 後續數字前方皆需精確對齊 ", "
            }
        }
        cout << "\n";
        
        // 印出最終唯一殘留的卡牌編號
        cout << "Remaining card: " << r.front() << "\n";
    }
    return 0;
}
```


## 進階優化思考

原做法利用 std::queue 進行流式模擬，在解題直觀度上達到了完美的效果。但在資工的高階記憶體優化考量下，由於 $N \le 50$ 規模極小，我們其實可以完全不用高階的 STL 佇列容器，改用另一種非常有趣的環形陣列（Circular Array）思維。

**靜態雙指針與環形陣列模擬（Circular Buffer）**

* **原理**：我們可以直接宣告一個固定大小為 100 的一維陣列，並開闢 front_ptr = 0 與 rear_ptr = n 兩個整數變數。
  
* **作法**：
  
  * 丟棄牌： `d.push_back(arr[front_ptr++])`
  * 移到最下方： `arr[rear_ptr++] = arr[front_ptr++]`
  * 為了防止陣列無限向右延伸，可以用模數運算 `ptr = (ptr + 1) % MAX_SIZE` 將其約束成一個首尾相連的環形跑道。
 
* **優點**：這樣做能將所有的動態記憶體開銷（如 deque 的分段配置）徹底消除，全數轉化為 CPU 暫存器級別的整數加減法與陣列查表，是實現極致常數時間調優的核心優化手段。
