# UVa 900 - Brick Wall Patterns

## 題目簡述

有一種長方形的磚塊，其尺寸固定為 $1 \times 2$。現在想要用這種磚塊拼出一面高度固定為 2、長度為 $N$ 的磚牆。<br>
請計算出對於給定的牆壁長度 $N$，總共能組合出多少種**完全相異的排磚圖案（Patterns）**？

當輸入的長度 $N = 0$ 時，代表整個輸入結束。

**Sample Input**：

  **1** $\rightarrow$ 第一組牆壁長度 $N = 1$。<br>
  **2** $\rightarrow$ 第二組牆壁長度 $N = 2$。<br>
  **3** $\rightarrow$ 第三組牆壁長度 $N = 3$。<br>
  **0** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **1** $\rightarrow$ 長度為 1 時，只能垂直放置 1 塊磚，共 1 種方法。<br>
  **2** $\rightarrow$ 長度為 2 時，可全垂直（||）或全水平（=），共 2 種方法。<br>
  **3** $\rightarrow$ 長度為 3 時，共 3 種方法。


## 解題思路與組合遞迴

### 核心觀念：動態規劃與費氏數列模型的幾何同構（Fibonacci Sequence）
這道題目的本質是**經典的二維條帶鋪磚（Tiling Problem）與組合遞迴關係**。

為了求出長度為 $N$ 的牆壁總方法數 $f(N)$，我們可以使用**動態規劃（Dynamic Programming）**的分治視角，從牆壁的「最後一塊磚」是如何擺放的來進行邊界推導：
1. **狀況一（結尾垂直放置）**：
   如果牆壁的最右側末尾是垂直擺放一塊 $1 \times 2$ 的磚塊，那麼左邊剩下的牆壁長度剛好是 $N - 1$。這種擺法的組合數等價於長度為 $N - 1$ 的牆壁排法，即 **$f(N - 1)$**。
2. **狀況二（結尾水平放置）**：
   如果牆壁的最右側末尾包含了水平擺放的磚塊，由於牆壁高度固定為 2，為了將高度填滿，**必須強制成對地上下平行疊放兩塊 $1 \times 2$ 的水平磚**。此時這兩塊磚佔據的總長度為 2，左邊剩下的牆壁長度剛好是 $N - 2$。這種擺法的組合數等價於長度為 $N - 2$ 的牆壁排法，即 **$f(N - 2)$**。

因為末尾只可能由這兩種獨立事件組成，根據加法原理，長度為 $N$ 的全域轉移方程必為：
$$f(N) = f(N - 1) + f(N - 2)$$
這完美的與著名的 **費氏數列（Fibonacci Sequence）** 達成了幾何同構。其初始邊界臨界值為：
* $f(1) = 1$
* $f(2) = 2$
* $f(3) = f(2) + f(1) = 3$
* $f(4) = f(3) + f(2) = 5$

### 演算法步驟
1. 由於題目會反覆查詢多組不同的長度 $N$，最佳的實作手法是採用**離線建表（Pre-computation）**。
2. 宣告一個全域或主程式開頭的一維陣列 `fib[55]`。
3. 初始設定邊界：`fib[1] = 1; fib[2] = 2;`。
4. 利用一條簡單的 `for` 迴圈從 3 迭代到 50，依據遞迴公式 `fib[i] = fib[i - 1] + fib[i - 2]` 將整條軌道的所有答案預先填滿。
5. 隨後進入 `while (cin >> n && n != 0)` 監聽迴圈，每次收到長度詢問 `n`，不需要執行任何多餘的算術演算法，直接在 $\mathcal{O}(1)$ 時間內查表輸出 `fib[n]` 即可。


## 複雜度分析

* **時間複雜度**：

  * **預處理階段**： $\mathcal{O}(N_{\text{max}})$ <br>
    初始只需要跑一趟從 3 到 50 的線性迴圈，運算量固定為 48 次基本加法，耗時可忽略不計。
  * **線上查詢階段**： $\mathcal{O}(1)$ <br>
    每組讀入的長度 $N$ 都是直接透過下標查表 `fib[n]` 輸出，不含任何迴圈、乘除法或遞迴，因此查詢時間複雜度為絕對常數時間。總體效能極快，能在微秒內瞬間通關。
* **空間複雜度**： $\mathcal{O}(N_{\text{max}})$ <br>
  需要配置一個固定大小為 55 的 `long long fib[55]` 靜態陣列來儲存歷史預算表格，空間開銷僅為數百個位元組，內存利用率達到了完美的常數級別。


## 邊界條件與潛在陷阱

1. **大數增長與整數溢位防禦（Integer Overflow）**：<br>
   這是本題唯一的數值陷阱。費氏數列在代數上呈現指數級別（黃金比例 $\phi^N$）的暴增。題目規範牆壁的最大長度 $N$ 可達到 $50$。

   * 當 $N = 46$ 時，數值已經會跨越標準 32 位元有號整數（`int`）高達 $2 \times 10^9$ 的最大上限天花板。如果無腦宣告為 `int`，表格後半段的數據會直接發生溢位截斷，算出的圖案種數會變成荒謬的負數。
   * **原程式碼分析**：原實作具備極其敏銳的防禦性，將 `fib` 陣列的資料型態嚴格指定為了 **`long long`**（64 位元有號整數，上限高達 $9 \times 10^{18}$），這足夠安全且完美的容納 $f(50)$ 的極端值（約為 $2.03 \times 10^{10}$），成功拿到 AC。
2. **終止符 0 的精確攔截**：<br>
   最外層使用 `while (cin >> n && n != 0)` 進行流控制。當讀到 0 時安全煞車，防止 0 誤入內層引發陣列越界。


## 程式碼實作

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    // 核心防禦：由於費氏數列超過 45 項後會突破 int 上限，必須宣告為 long long 防範溢位
    long long fib[55];
    
    // 幾何邊界初始化
    fib[1] = 1; // 長度為 1：僅 1 種排法 (垂直)
    fib[2] = 2; // 長度為 2：共 2 種排法 (全垂 || 或 全平 =)
    
    // 離線預建表：利用動態規劃一維表格，在 O(1) 內橫向遞迴推導出前 50 項所有解答
    for (int i = 3; i <= 50; i++) {
        fib[i] = fib[i - 1] + fib[i - 2];
    }
    
    int n;
    // 線上查詢流：連續讀入牆壁長度 n，當 n = 0 時安全終止程式
    while (cin >> n && n != 0) {
        // 以絕對常數時間 O(1) 直接查表並印出全域最優組合種數
        cout << fib[n] << "\n";
    }
    return 0;
}
```


## 進階優化思考
**空間極致壓縮（常數空間動態規劃，$\mathcal{O}(1)$ 空間）**

目前的離線建表法開闢了大小為 55 的一維陣列，這在實務上已經足夠精簡。但如果從頂級嵌入式系統或極限常數優化的資工視角出發，這題其實可以完全不用任何陣列，改用動態規劃空間壓縮（Space Compression）技術。

* **原理**：不論 $N$ 有多大，當我們在計算 `fib[n]` 時，我們在記憶體中唯一需要參考的歷史紀錄，永遠只有緊鄰在其前方的 `fib[n-1]` 與 `fib[n-2]` 這兩項。

* **做法**：如果我們不在前期進行全域預建表，而是改在每次線上讀入 `n` 的當下，利用三個變數 `prev2`, `prev1`, `current` 在一條微型滾動跑道上進行代數交替覆蓋（滾動變數），就能將空間進一步逼低。雖然這樣會讓單次查詢的時間變為 $\mathcal{O}(N)$，但在 $N \le 50$ 的常數極小規模下，CPU 暫存器的滾動速度同樣快如閃電，是一種能將空間優化到絕對極限 $\mathcal{O}(1)$ 的優雅重構。
