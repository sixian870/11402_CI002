# UVa 11450 - Wedding Shopping

## 題目簡述

一個人有一筆固定預算 $M$ 元，計畫去購買 $C$ 種不同類別的衣服（例如：襯衫、褲子、鞋子等）。<br>
每一種衣服種類都有若干種不同的款式與其對應的定價。**規則規定：每一種衣服種類都「必須且只能」精確購買其中一種款式**。<br>
請計算出在不超過預算 $M$ 的前提下，購買完所有 $C$ 種衣服後，**最大可以花費的總金額是多少**？若無論如何分配都必定會超出預算，則輸出 `no solution`。

**Sample Input**：

  **3** $\rightarrow$ 測試資料組數 $T$。<br>
  **20 3** $\rightarrow$ 預算 $M = 20$，衣服種類數 $C = 3$。<br>
  **3 6 4 8** $\rightarrow$ 第一種衣服有 3 種款式，定價分別為 6, 4, 8。<br>
  **2 5 1** $\rightarrow$ 第二種衣服有 2 種款式，定價分別為 5, 1。<br>
  **4 1 5 3 5** $\rightarrow$ 第三種衣服有 4 種款式，定價分別為 1, 5, 3, 5。

**Sample Output**：

  **19** $\rightarrow$ 第一組最優購買組合為 $4 + 5 + 10$（實際最大可能花費和 $8+5+5 = 18$ 或 $6+5+5 = 16$ 等，最接近預算 20 的合法最大組合為 $8+1+5 = 14$ 等，以此類推找出全域最佳解為 19）。


## 解題思路與動態規劃

### 核心觀念：多階段決策與背包型動態規劃（Dynamic Programming）
這道題目的本質是**多階段背包型動態規劃**。如果採用簡單的窮舉法（DFS / 暴力搜索）嘗試枚舉每種類別的每一種衣服，其時間複雜度會隨著種類 $C$ 的增加呈指數型暴增（$\mathcal{O}(K^C)$），導致 Time Limit Exceeded (TLE)。

由於每一種類別的購買狀態只與「上一種類別購買完後所殘留（或累積）的金額」有關，因此這是一個完美的**重疊子問題**結構，可建立二維狀態表格進行轉移：

1. **狀態定義**：
   建立一個二維布林表格 `price[i][k]`，其物理語意定義為：**「在考慮完前 `i` 種類別的衣服後，總花費金額是否可能剛好等於 `k` 元？」**（`true` 代表可能，`false` 代表不可能）。
2. **第一階段初始化**：
   對於第 0 種類別的衣服，遍歷其所有款式定價 `p`。只要 `p <= money`（未超支），就直接將其可行性激活：`price[0][p] = true`。
3. **動態規劃轉移方程**：
   對於後續的第 `i` 種類別（`i` 從 1 到 `kind - 1`），讀入當前類別的所有款式定價 `p`。隨後橫向掃描上一階段 `i - 1` 的所有可能花費金額 `k`：
   * 若 `price[i - 1][k] == true`（代表前一階段累積花費 `k` 元是可行的）。
   * 且當前款式相加後 `k + p <= money`（未超出預算上限）。
   * **狀態轉移**：激活當前階段的新花費狀態：
$$\text{price}[i][k + p] = \text{true}$$

### 最終解搜尋
當所有的衣服類別都處理完畢後，最後一列 `price[kind - 1][m]` 就完整的儲存了購買完全部衣服後的「全域所有可能總花費分布」。由於要尋找的是「最大金額」，只需讓 `m` 從 `money`（預算上限）反向遞減搜查到 0。第一個遇到的 `true` 格子，其索引 `m` 即為不超支的最大總花費。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(T \times C \times K \times M)$
  其中 $T$ 為組數，$C$ 為衣服種類數（`kind`），$K$ 為每種類別中款式的最大數量，$M$ 為總預算（`money`）。
  在轉移過程中，外層迴圈跑 $C$ 次，內層針對每個款式（$K$ 次）去遍歷整個預算表格（$M$ 次）。因此，單組測資的最大運算次數約為 $C \times K \times M$。代入題目上限（$C \le 20, K \le 20, M \le 200$），最大總運算量為 $20 \times 20 \times 200 = 80,000$ 次，可在幾毫秒內極速通關。
* **空間複雜度**： $\mathcal{O}(C \times M)$
  需要開闢一個大小為 $C \times (M + 1)$ 的二維布林動態陣列表格 `price`。當 $C = 20, M = 200$ 時，表格僅需佔用約 4 KB 的記憶體空間，配置效率極高。


## 邊界條件與潛在陷阱

1. **無解條件的攔截（`no solution`）**：
   若預算過低，導致在某一種類別中不論怎麼選都會超出預算，那麼該列 `price[i]` 的所有格子將會全數保持為 `false`。這會引發後續的狀態鏈全面斷裂。最後在反向搜尋答案時，若遍歷完 `m` 發現沒有任何一格為 `true`，`ans` 將保持為初始值 `-1`，此時必須嚴格精確輸出全小寫的 **`no solution`**。
2. **衣服款式定價大於預算**：
   在讀入第 0 階段時，程式碼包含了一行 `if (p <= money)` 的安全檢查，確保不會因為單件衣服價格破表而導致陣列索引發生越界（Out of Bounds）。
3. **二維表格長度防禦（1-indexed 預算長度）**：
   由於花費總金額可以剛好等於預算上限 `money`，因此在宣告 `vector` 表格行寬時，大小必須指定為 `money + 1`，如此才能安全存取到索引 `price[i][money]`，原實作的空間配置極其嚴密。


## 程式碼實作

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    // 提升標準 I/O 串流效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int t;
    if (cin >> t) {
        while (t--) {
            int money, kind;
            cin >> money >> kind;
            
            // 狀態定義：price[i][k] 代表考慮完前 i 類衣服後，總花費能否剛好等於 k 元
            // 欄位大小配置為 money + 1 以防範索引邊界越界
            vector<vector<bool>> price(kind, vector<bool>(money + 1, false));
            
            int n;
            // 處理第 0 類衣服的初始化階段
            cin >> n;
            for (int i = 0; i < n; i++) {
                int p;
                cin >> p;
                if (p <= money) {
                    price[0][p] = true; // 激活初始可行花費
                }
            }
            
            // 進入多階段動態規劃轉移
            for (int i = 1; i < kind; i++) {
                cin >> n;
                for (int j = 0; j < n; j++) {
                    int p;
                    cin >> p;
                    // 核心轉移：遍歷前一類衣服的所有可能花費 k
                    for (int k = 0; k <= money; k++) { 
                        // 若前一階段花費 k 可行，且加上當前款式定價 p 後未超支
                        if (price[i - 1][k] == true && k + p <= money) {
                            price[i][k + p] = true; // 狀態轉移：激活當前階段新花費
                        }
                    }
                }
            }
            
            int ans = -1;
            // 貪婪反向搜尋：從最大預算 money 開始遞減尋找最優解
            for (int m = money; m >= 0; m--) {
                if (price[kind - 1][m] == true) {
                    ans = m;
                    break; // 找到全域最大可行花費，立即中斷
                }
            }
            
            // 依據判定結果輸出
            if (ans == -1) {
                cout << "no solution\n";
            }
            else {
                cout << ans << "\n";
            }
        }
    }
    return 0;
}
```


## 進階優化思考

原做法在時間與空間上已完美達到 AC 的規格。但若從高階資工演算法的優化思維來審視，這個背包問題存在著一個將空間複雜度直接由 $\mathcal{O}(C \times M)$ 壓縮至極限 $\mathcal{O}(M)$ 的一維滾動優化手段。

**滾動陣列優化（Rolling Array / Space Compression）**

* **原理**：仔細觀察動態規劃的轉移方程，可以發現當我們在計算第 `i` 層的狀態時，我們唯一需要參考的只有相鄰的上一層 `i - 1` 的狀態。更早之前的第 `i - 2` 層及更早的歷史表格，在記憶體中其實已經變成了永遠不會再被讀取的「死資料」。

* **做法**：因此，不需要開闢 $C$ 列的巨大二維矩陣。只需要宣告兩列一維陣列 `vector<bool> dp(money + 1, false);` 與 `vector<bool> next_dp(money + 1, false);`（或者直接利用單一陣列配合反向掃描技術，如同經典 0/1 背包問題）。

* **效能改善**：此重構版本將空間複雜度優化到了最佳的 $\mathcal{O}(M)$。當種類 $C$ 放大到上千、預算 $M$ 放大到數萬的大數據極端情境下，滾動陣列優化技術能大幅提升 CPU 快取命中率（Cache Hit Rate），避免發生記憶體分頁置換（Page Fault），是嵌入式系統與高吞吐量後端開發時的核心核心調優手法。

**優化程式碼實作片段：**
```cpp
vector<bool> dp(money + 1, false);
dp[0] = true; // 初始沒買衣服時，花費 0 元是可行的

for (int i = 0; i < kind; i++) {
    vector<bool> next_dp(money + 1, false); // 配置臨時快取列
    int n;
    cin >> n;
    while (n--) {
        int p;
        cin >> p;
        for (int k = 0; k <= money; k++) {
            if (dp[k] && k + p <= money) {
                next_dp[k + p] = true;
            }
        }
    }
    dp = move(next_dp); // 利用 C++11 右值引用極速交換指針，省去記憶體複製開銷
}
```
