# UVa 10420 - List of Conquests

## 題目簡述

唐璜（Don Giovanni）在各個國家中有許多愛慕者。給定一份包含多行數據的愛慕者名冊，每一行代表一位女性的紀錄，格式為「國家名稱 女性名字（包含姓氏）」。<br>
請統計唐璜在各個國家中擁有的愛慕者總人數，並將統計結果按照國家名稱的「字典順序（字母順序）」由小到大排列輸出。

**Sample Input**：

  **3** $\rightarrow$ 總共有 $N$ 行紀錄。<br>
  **Spain Donna Elvira** $\rightarrow$ 第一個單字為國家名稱（不含空格），後續為女性名字。<br>
  **England Donna Anna**<br>
  **Spain Leporello**

**Sample Output**：

  **England 1** $\rightarrow$ 依據國家字母順序由小到大排列。<br>
  **Spain 2** $\rightarrow$ 國家名稱後方輸出該國愛慕者的加總人數。


## 解題思路與關聯式容器

### 核心觀念：平衡二元搜尋樹與自動排序（std::map）
這道題目的本質是**字串解析（Parsing）與頻率統計（Frequency Counting）**，並要求結果具備**有序性**。

在 C++ 中，`std::map` 是解決此類問題的完美工具：
1. **結構特性**：`std::map` 在底層是由紅黑樹（Red-Black Tree，一種自平衡二元搜尋樹）所實現。
2. **自動排序**：當我們使用國家名稱（`string`）作為鍵值（Key）插入時，`map` 會自動依據 Key 的字串字典順序進行內部排序。
3. **字串解析技巧**：每行資料中，國家名稱與女性名字之間以空格分隔。由於我們**只需要統計各國人數，女性的名字完全不影響答案**，因此可以使用 `cin >> country` 先行抽離出第一個單字（國家），再利用 `getline(cin, text)` 將該行殘留的名字讀取並丟棄。

### 演算法步驟
1. 讀入整數 $N$ 代表總紀錄行數。
2. 建立一個 `map<string, int> countrys` 用來動態儲存「國家 $\rightarrow$ 人數」的映射。
3. 執行 $N$ 次迴圈：
   * 使用 `cin >> country` 讀取每行的第一個單字（即國家名稱）。
   * 使用 `getline(cin, text)` 讀完並吃掉該行剩下的女性名字與換行符。
   * 執行 `countrys[country]++`，若該國家首次出現會自動初始化為 0 再加 1，若已存在則人數直接累加。
4. 使用基於範圍的 `for` 迴圈遍歷 `map`，依序印出排序好的國家名稱（`it.first`）與對應人數（`it.second`）。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \times L \log M)$
  其中 $N$ 為總紀錄筆數，$L$ 為國家名稱字串的平均長度，$M$ 為相異的國家總數（ $M \le N$ ）。每一次將國家插入 `map` 或更新數值，都需要在紅黑樹中進行字串比對與尋找，耗時 $\mathcal{O}(L \log M)$。由於題目規範 $N \le 2000$，總運算量極小，可在幾毫秒內迅速收工。
* **空間複雜度**： $\mathcal{O}(M \times L + K)$
  需要記憶體空間來存放 $M$ 個相異國家的字串與人數。另外，`getline` 讀取的 `text` 變數會佔用單行名字的最大字串緩衝空間 $K$。整體記憶體開銷低於數百 KB，在空間效能上非常優異。


## 邊界條件與潛在陷阱 (Edge & Corner Cases)

1. **同一個國家重複出現**：
   名冊中同一個國家可能分散在不同行出現（如 Sample 中的 Spain 夾在第 1 行與第 3 行）。使用 `map` 的計數機制可以確保無論出現順序為何，同一個鍵值的人數都能正確被集中累加。
2. **名字中包含多個空格**：
   女性的名字可能包含複姓或中間名（例如 `Donna Anna` 包含空格）。因為使用 `getline(cin, text)` 能夠一口氣將該行接下來的所有字元（包含空格與尾端的換行符）全部讀入，因此不論名字結構多複雜，都不會干擾到下一輪迴圈讀取新的國家。
3. **多餘換行符的吸收**：
   在執行 `cin >> country` 時，它會自動跳過領頭的換行或空格，並在遇到下一個空格時停止。隨後的 `getline` 會從該空格處往後讀到行末的 `\n`。這樣的交替組合可以確保每一行的換行結構被正確清理，不會發生緩衝區殘留而導致漏讀的情況。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n;
    if (cin >> n) {
        map<string, int> countrys; // 利用紅黑樹特性的 map，Key (國家) 會自動依字典順序排序
        string country, text;
        
        for (int i = 0; i < n; i++) {
            cin >> country;       // 讀取每行開頭的國家名稱（遇到空格即停止）
            getline(cin, text);   // 核心：吃掉該行後續的多餘女性名字與結尾換行符
            countrys[country]++;  // 該國家的愛慕者人數累加 1
        }
        
        // 遍歷已自動按國家字母排序完畢的 map
        // 使用 const& 可以避免複製結構體，並以常數唯讀形式提高效能
        for (auto const& it : countrys) { 
            cout << it.first << " " << it.second << "\n"; // it.first 是國家，it.second 是總人數
        }
    }
    return 0;
}
```


## 進階優化思考

如果在相異國家數量 $M$ 極大、或是對時間極致要求的競賽場景中，存在著另一種微幅提升效率的架構。

**雜湊表與手動排序（std::unordered_map + std::vector）**

* **原理**：std::unordered_map 的底層是雜湊表（Hash Table），其插入與查詢的平均時間複雜度為更優秀的 $\mathcal{O}(1)$。我們可以先用它在線性時間內完成人數統計。
* **做法**：統計完畢後，將雜湊表中的所有節點倒進一個 std::vector<pair<string, int>> 中，最後再對 vector 調用一次 std::sort 進行手動排序。
* **效能對比**：這樣做可以將總體的時間複雜度從 $\mathcal{O}(N \log M)$ 優化到 $\mathcal{O}(N + M \log M)$。當相異國家總數 $M$ 遠小於資料筆數 $N$ 時，這種架構能減少紅黑樹頻繁調整平衡的開銷，是處理海量數據時常用的進階調優手段。
