# UVa 11413 - Fill the Containers

## 題目簡述

有 $N$ 個牛奶瓶（依序編號為 $1$ 到 $N$），每個瓶子裡裝有特定容量的牛奶。現在我們有 $M$ 個完全相同的容器，必須把這 $N$ 個牛奶瓶**依據原始順序**連續地倒入這 $M$ 個容器中。

**倒入規則**：
1. 必須按照牛奶瓶的編號順序（ $1, 2, 3, \dots, N$ ）連續倒入容器，不可以任意打亂或跳過。
2. 一個牛奶瓶的牛奶必須**全部**倒進同一個容器中，不能拆分裝入不同容器。
3. 容器的數量上限為 $M$ 個，且允許有容器最後保持完全全空。

請計算出在最聰明的分配策略下，這些容器所需要的 **最小容量（Capacity）** 是多少？（即求出所有可能分配方案中，容器最大負載容量的最小值）。

**輸入規範**：
連續讀入牛奶瓶數量 $N$ 與容器數量 $M$（ $1 \le N \le 1000, 1 \le M \le 1000$ ），接著讀入 $N$ 個牛奶瓶各自的容量。直到檔案結束（EOF）。

**Sample Input**：

  **5 3** $\rightarrow$ 第一組測資：$N = 5$ 瓶牛奶，最多用 $M = 3$ 個容器。<br>
  **1 2 3 4 5** $\rightarrow$ 各瓶牛奶容量。<br>
  **3 2** $\rightarrow$ 第二組測資：$N = 3$ 瓶牛奶，最多用 $M = 2$ 個容器。<br>
  **4 78 28**

**Sample Output**：

  **6** $\rightarrow$ 分配成 [1, 2, 3], [4], [5]，各容器內總量為 6, 4, 5，最大容量為 6。<br>
  **78** $\rightarrow$ 分配成 [4], [78], [28]，因為裝 78 的容器容量至少要 78。


## 解題思路與二分搜尋答案法

### 核心觀念：對答案進行二分搜尋（Binary Search on Answer / 二分答案）
這道題目的本質是**單調性區間判定與二分答案優化**。
如果直接從牛奶瓶出發去嘗試排列組合出所有可能的分組，會面臨高昂的指數級狀態空間。

然而，如果我們換個角度，直接去猜測 **「容器的容量 $C$」**：
* 如果容量 $C$ 太小，我們會發現即使把每個容器都裝到極限，用完了 $M$ 個容器也裝不完所有的牛奶（不合法）。
* 如果容量 $C$ 足夠大，我們就能在 $M$ 個容器的限制內順利把牛奶全數裝完（合法）。
這種「隨著容量增加，從不合法變為合法」的**單調性質（Monotonicity）**，就是完美的二分搜尋發揮場地。


### 演算法步驟
1. **確立二分搜尋上下界（`low` 與 `high`）**：

   * **下界 `low`**：容器的容量絕對不能小於「所有牛奶瓶中的最大單瓶容量（`max_milk`）」，因為一瓶牛奶不能被拆開。
   * **上界 `high`**：最保守的情況下，一個容器直接把所有牛奶全裝了，所以上界就是所有牛奶瓶的容量總和（`sum`）。
2. **區間收斂與合法性判定**：
   在 `[low, high]` 區間內取中點 `mid` 作為當前測試的容量，並調用 `check` 函式判定：

   * **`check` 模擬流程**：從左到右掃描牛奶瓶，嘗試把牛奶塞進同一個容器。如果加上當前瓶子會超過容量 `mid`，就必須啟用一個新容器來裝。最後檢查總共使用了多少個容器。
   * **分支一（`check` 回傳 `true`）**：代表容量 `mid` 是可行的。為了找出更小的可行容量，我們記錄當前答案 `ans = mid`，並向左半區限縮：`high = mid - 1`。
   * **分支二（`check` 回傳 `false`）**：代表容量 `mid` 太小裝不下。我們必須增加容量，因此向右半區限縮：`low = mid + 1`。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \times \log(\text{sum} - \mathit{max\_milk}))$ <br>
  每次二分搜尋都需要執行一次 `check` 函式。`check` 函式內部僅使用單層 `for` 迴圈線性掃描一次長度為 $N$ 的牛奶陣列，耗時為 $\mathcal{O}(N)$。整個二分搜尋的區間長度為全域總和（最大約 $10^9$），對數收斂次數最多不超過 $\log_2(10^9) \approx 30$ 次。因此，單組測資總時間複雜度為 $\mathcal{O}(30 \cdot N)$。代入 $N = 1000$，運算量在 $3 \times 10^4$ 次以內，可在 1 毫秒內極速AC。
* **空間複雜度**： $\mathcal{O}(N)$ <br>
  需要開闢一個一維 `std::vector<int>` 陣列來儲存這 $N$ 個牛奶瓶的容量數據，空間開銷與 $N$ 呈線性正比。


## 邊界條件與潛在陷阱

1. **單瓶大於容量的即時煞車（Out-of-Capacity 防禦）**：<br>
   在 `check` 函式內部，如果遇到某一瓶牛奶的實體容量大於當前測試的總容量 `C`（即 `milk[i] > C`），代表這個容量無論如何都不可能裝下這瓶牛奶。原程式碼在迴圈第一步就加入了 `if (milk[i] > C) return false;`。這項特判非常關鍵，能即時攔截並阻止後續迴圈產生錯誤的分配計數。
2. **容器數量與名額極值（ $M \ge N$ 的臨界 Case）**：<br>
   如果給定的容器數量 $M$ 大於或等於牛奶瓶數量 $N$（例如 5 瓶牛奶卻給了 10 個容器），最優解顯然就是讓每瓶牛奶獨佔一個容器，最終答案就是最大單瓶容量 `max_milk`。此時二分搜尋會一路收斂，直到 `low` 完美卡位在 `max_milk`，邏輯完全相容。
3. **二分搜尋中點防溢位語法（Middle Overflow Mitigation）**：<br>
   在計算中點時，原實作採用了 `int mid = low + (high - low) / 2;`。這是一項非常正統且安全的資工撰寫習慣，它避免了直接使用 `(low + high) / 2` 時，兩大數相加可能跨越 `int` 天花板而引發的整數溢位地雷。


## 程式碼實作

```cpp
#include <iostream>
#include <vector>
#include <numeric>
#include <algorithm>
using namespace std;

// 輔助判定函式：檢查在限制容器容量為 C 的前提下，能否在 M 個容器內裝完所有牛奶
bool check(int C, const vector<int>& milk, int m) {
    int count = 1;         // 當前正在使用的容器計數器 (初始使用第 1 個容器)
    int current_weight = 0; // 當前容器已累積的牛奶重量
    
    for (size_t i = 0; i < milk.size(); i++) {
        // 安全防禦：若單瓶牛奶容量就大於總容量限制 C，必定不合法
        if (milk[i] > C) return false;
        
        // 貪婪裝載：若當前容器還塞得下，就持續往裡面倒
        if (current_weight + milk[i] <= C) {
            current_weight += milk[i];
        }
        // 若塞不下了，必須強制啟用下一個新容器，並把當前牛奶倒入新容器中
        else {
            count++;
            current_weight = milk[i];
        }
    }
    // 檢查最終耗費的總容器數是否小於或等於規定的數量上限 m
    return count <= m;
}

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);

    int n, m;
    // 連續讀入牛奶瓶數 n 與容器上限 m，直到檔案結束 (EOF) 爲止
    while (cin >> n >> m) {
        vector<int> milk(n);
        int sum = 0;
        int max_milk = 0;
        
        // 讀入資料並動態統計全域總和與最大單瓶容量
        for (int i = 0; i < n; i++) {
            cin >> milk[i];
            sum += milk[i];
            max_milk = max(max_milk, milk[i]);
        }
        
        // 確立二分答案的單調邊界線
        int low = max_milk;  // 最小可行容量：絕對不可能小於最大單瓶牛奶量
        int high = sum;      // 最大可能容量：一箱裝完全部牛奶
        int ans = high;      // 紀錄最優解
        
        // 執行二分搜尋答案法
        while (low <= high) {
            // 安全中點計算公式，有效防止硬體溢位
            int mid = low + (high - low) / 2;
            
            // 若當前容量 mid 可行，嘗試尋找更小的可能，向左半區靠攏
            if (check(mid, milk, m)) {
                ans = mid;
                high = mid - 1;
            }
            // 若當前容量裝不下，代表必須放大容量，向右半區靠攏
            else {
                low = mid + 1;
            }
        }
        // 輸出最優化收斂後的容器最小容量
        cout << ans << "\n";
    }
    return 0;
}
```


## 進階優化思考

**二分極限剪枝與常數時間調優**

雖然目前的 $\mathcal{O}(30 \cdot N)$ 在實際評測中已經能拿到極速 AC，但如果從高性能演算法調優的視角來挑剔，最內層的 `check` 函式依然存在著減少 CPU 分支預測錯誤（Branch Misprediction）的優化空間。

* **優化做法**：原代碼在 `check` 中使用了兩層 `if` 判定（`milk[i] > C` 與 `current_weight + milk[i] <= C`）。由於我們在最外層已經將二分搜尋的起點下界 `low` 鎖死在 `max_milk`，這代表任何被送進 `check` 的容量 `C` 都絕對不可能小於任何一瓶單瓶牛奶量。

* **技術精髓**：因此，最內層的第一行 `if (milk[i] > C) return false;` 在邏輯上其實是**完全冗餘且永遠不會觸發的（Dead Code）**。直接將這行程式碼抹除，不僅能精簡結構，更能移除掉一條 CPU 條件跳轉指令。在多組密集測資的高併發情境下，這能完全消除分支預測失敗帶來的流水線中斷代價，讓線性掃描的純硬體執行速度逼近物理極限。
