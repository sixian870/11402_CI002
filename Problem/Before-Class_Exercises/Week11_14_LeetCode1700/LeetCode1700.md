# LeetCode 1700 - Number of Students Unable to Eat Lunch


## 題目簡述

學校食堂做好了三明治，並依據特定順序疊成了一個**三明治堆疊（Sandwiches Stack）**，頂端的三明治必須先被拿走。
學生們排成了一條**學生佇列（Students Queue）**。三明治與學生的類型皆分為兩種：
* `0`：圓形
* `1`：方形

當排在佇列最前面的學生面對堆疊頂端的三明治時：
* 如果學生喜歡這種類型，他會拿走三明治並離開隊伍。
* 如果學生不喜歡這種類型，他會**離開隊伍最前端，並重新排到隊伍的最尾端**。

這個過程會一直持續，直到**排在最前面的學生都不喜歡頂端的三明治**，此時隊伍陷入死鎖（無法前進），剩下沒吃到午餐的學生只能挨餓。請計算最後**有多少名學生無法吃到午餐**？

**Sample Input & Output**：

* **Example 1 :**
  * **Input :** `students = [1,1,0,0]`, `sandwiches = [0,1,0,1]`
  * **Output :** `0`
  * **解釋 :**
    * 學生隊伍轉幾圈後，圓形學生會拿走 0，方形會拿走 1，所有人都能吃到。

* **Example 2 :**
  * **Input :** `students = [1,1,1,0,0,1]`, `sandwiches = [1,0,0,0,1,1]`
  * **Output :** `3`
  * **解釋 :**
    * 拿走前兩個三明治後，剩下的三明治堆疊頂端是 0。
    * 但此時隊伍裡只剩下 3 個喜歡 1 的方形學生。沒有人要拿 0，隊伍陷入死鎖，因此有 3 人吃不到。


## 程式碼

1. **直覺模擬法的盲點**：如果真的開 `std::queue` 和 `std::stack` 去慢慢搬移學生和移除三明治，雖然可行，但頻繁的 `push` 與 `pop` 會造成不必要的效能損耗。

2. **跳脫順序的「扣額度」思維**：
   - 仔細觀察規則，喜歡圓形（0）或方形（1）的學生人數其實是固定的。不論隊伍怎麼輪轉，只要隊伍裡「還有任何一個學生」喜歡頂端的三明治，他早晚都會輪到最前端把三明治拿走。
   - 換句話說，三明治能不能被消耗掉，**只取決於全場還剩多少個喜歡該類型的學生**，跟學生的排隊順序完全無關！

3. **死鎖的判定條件**：
   - 我們只需要先統計出喜歡 0 的學生總數與喜歡 1 的學生總數。
   - 接著，逐一檢查三明治堆疊。如果頂端是圓形（0）且還有圓形學生額度，圓形學生額度減 1；頂端是方形（1）且還有方形學生額度，方形學生額度減 1。
   - 萬一遇到頂端是某種類型（例如 1），但全場**已經沒有任何一個學生喜歡 1 了**。這意味著不論隊伍怎麼轉，也絕對沒有人能拿走這個三明治。這時遊戲立刻結束（死鎖），剩下的三明治數量（即剩餘的三明治與學生人數）就是答案。

4. **時間與空間複雜度**：時間複雜度優化至極致的 $O(N)$，且空間複雜度只需要大小為 2 的計數陣列，達到完美的 $O(1)$！

```cpp
class Solution {
public:
    int countStudents(vector<int>& students, vector<int>& sandwiches) {
        // count[0] 記錄喜歡圓形的學生人數，count[1] 記錄喜歡方形的學生人數
        int count[2] = {0, 0};
        for (int student : students) {
            count[student]++;
        }
        
        // 依序檢查每個三明治是否能被消耗
        for (int sandwich : sandwiches) {
            if (count[sandwich] == 0) {
                break;
            }
            // 還有學生想要，該類型的學生扣除一名額
            count[sandwich]--;
        }
        
        // 剩餘還沒被拿走的三明治總數等於吃不到飯的學生人數
        return count[0] + count[1];
    }
};
```
