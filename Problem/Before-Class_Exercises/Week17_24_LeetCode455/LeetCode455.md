# LeetCode 455 - Assign Cookies


## 題目簡述

假設你是一位很棒的家長，想要給你的孩子們一些餅乾。但是，每個孩子最多只能給一塊餅乾。<br>
每個孩子 $i$ 都有一個**胃口值（Greed Factor）** `g[i]`，這是能讓孩子們滿足的餅乾最小尺寸。每塊餅乾 $j$ 都有一個**尺寸（Size）** `s[j]`。如果 `s[j] >= g[i]`，我們就可以將這塊餅乾 $j$ 分配給孩子 $i$，這個孩子就會得到滿足。<br>
目標是影響最多數量的孩子，並回傳**最大能滿足的孩子數量**。

**Sample Input & Output**：

* **Example 1 :**
  * **Input :** `g = [1,2,3]`, `s = [1,1]`
  * **Output :** `1`
  * **解釋 :** 你有三個孩子和兩塊餅乾，孩子的胃口值分別是 1, 2, 3。你擁有的兩塊餅乾尺寸都是 1。你只能讓胃口值是 1 的孩子滿足。所以回傳 1。

* **Example 2 :**
  * **Input :** `g = [1,2]`, `s = [1,2,3]`
  * **Output :** `2`
  * **解釋 :** 你有兩個孩子和三塊餅乾，孩子的胃口值分別是 1, 2。你擁有的餅乾尺寸分別是 1, 2, 3。兩位孩子都可以被滿足，回傳 2。


## 程式碼

1. **貪心思考方向**：為了滿足「最多」的孩子，我們應該採取什麼策略？
   - **優先滿足胃口小的孩子**：胃口小的孩子最容易被取悅，消耗的餅乾資源最少，把大餅乾留給後面胃口大的人才是明智之舉。
   - **用最小且符合條件的餅乾餵孩子**：不要大材小用。如果一個孩子胃口是 2，手上有尺寸 2 和 5 的餅乾，我們應該優先塞給他尺寸 2 的餅乾，把 5 留給胃口更大的孩子。

2. **雙指針比對破局法**：
   - 先將孩子胃口陣列 `g` 與餅乾尺寸陣列 `s` 通通進行**從小到大（升序）排序**。
   - 宣告兩個指針：`child` 指向目前最小胃口的孩子，`cookie` 指向目前最小尺寸的餅乾。
   - 從頭開始巡邏：如果當前餅乾分量夠大（`s[cookie] >= g[child]`），代表這個孩子被成功滿足了！此時孩子指針往前推一步（`child++`），同時這塊餅乾被消耗掉（`cookie++`）。
   - 如果餅乾太小（`s[cookie] < g[child]`），代表這個餅乾連全場胃口最小的孩子都餵不飽，後面的人更不可能吃得飽。這塊餅乾徹底沒用，我們直接拋棄它，指針前推進去尋找下一塊更大的餅乾（`cookie++`），而孩子則待在原地等待。

3. **時間與空間複雜度**：兩次排序耗費 $O(N \log N + M \log M)$，後續雙指針單向掃描僅需 $O(N + M)$。整體時間複雜度由排序決定，空間複雜度在排除原地排序的輔助外為極致的 $O(1)$！
   
```cpp
#include <vector>
#include <algorithm>

class Solution {
public:
    int findContentChildren(std::vector<int>& g, std::vector<int>& s) {
        // 將孩子胃口與餅乾尺寸皆由小到大排序
        std::sort(g.begin(), g.end());
        std::sort(s.begin(), s.end());
        int child = 0;  // 指向目前正在考慮的孩子
        int cookie = 0; // 指向目前正在考慮的餅乾
        while (child < g.size() && cookie < s.size()) {
            // 如果當前餅乾尺寸大於或等於孩子胃口，代表可以滿足
            if (s[cookie] >= g[child]) {
                child++; // 成功取悅一個孩子，換下一個胃口更大的孩子
            }
            // 不論這塊餅乾有沒有成功餵飽孩子，它在這一輪後都會被消耗，必須去看下一塊
            cookie++; 
        }
        // 最終被滿足的孩子數量，剛好等同於 child 指針前進的步伐數
        return child;
    }
};
```
