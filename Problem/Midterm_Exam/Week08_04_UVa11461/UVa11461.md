# UVa 11461 - Square Numbers

## 題目簡述

給定兩個正整數 $a$ 與 $b$，請計算出在閉區間 $[a, b]$（包含 $a$ 與 $b$ 本身）之間，總共包含多少個 **「完全平方數（Square Numbers）」**。<br>
完全平方數是指可以表示為某個整數的平方的數，例如 $1\ (=1^2)$ 、 $4\ (=2^2)$ 樣、 $9\ (=3^2)$ 等。

**Sample Input**：

  **1 4** $\rightarrow$ 第一組區間：從 1 到 4。<br>
  **1 10** $\rightarrow$ 第二組區間：從 1 到 10。<br>
  **0 0** $\rightarrow$ 當 $a = 0$ 且 $b = 0$ 時，代表輸入結束。

**Sample Output**：

  **2** $\rightarrow$ 1 到 4 之間有 1, 4 共 2 個完全平方數。<br>
  **3** $\rightarrow$ 1 到 10 之間有 1, 4, 9 共 3 個完全平方數。


## 解題思路與數學開根號

### 核心觀念：前綴和區間相減與完全平方數開根性質
這道題目的本質是**數論基礎中的完全平方數計數與區間查詢優化**。
如果採用最直觀的「暴力遍歷法」，從 $a$ 一路逐個數字判斷到 $b$，當測試資料量極大時會產生非必要的效能開銷，最佳的解題策略是利用 **「開根號取無條件捨去（Floor of Square Root）」** 的常數時間數學特性：

1. **個數統計原理**：

   對於任意正整數 $x$，從 $1$ 到 $x$ 之間的完全平方數個數，剛好精確等於 **$\lfloor\sqrt{x}\rfloor$**（即對 $x$ 開根號後向下取整數）。例如：

   * $1$ 到 $10$ 之間： $\lfloor\sqrt{10}\rfloor = \lfloor3.162\rfloor = 3$（即 $1^2, 2^2, 3^2$ 共三個）。
   * $1$ 到 $100$ 之間： $\lfloor\sqrt{100}\rfloor = 10$（即 $1^2 \dots 10^2$ 共十個）。
     
2. **前綴和區間排他相減（Prefix Range Exclusion）**：
 
   題目要求的是尋找閉區間 $[a, b]$ 之間的個數，根據排他性原理，這等價於：<br>
   $$\text{區間內的個數} = (\text{從 } 1 \text{ 到 } b \text{ 的完全平方數總數}) - (\text{從 } 1 \text{ 到 } a-1 \text{ 的完全平方數總數})$$ <br>
   因此，公式可直接推導為：<br>
   $$\text{Result} = \lfloor\sqrt{b}\rfloor - \lfloor\sqrt{a-1}\rfloor$$

3. **在線流式處理**：
   利用此數學公式，可以在讀入資料的當下直接於 $\mathcal{O}(1)$ 時間內算出答案，完全免去了任何迴圈的開銷。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(1)$
  每組測試資料僅需調用兩次 C++ 內建的數學函式 `sqrt`，隨後進行基本的整數減法運算。不含任何 `for` 或 `while` 迴圈結構，因此單組測資的時間複雜度為絕對常數時間。
* **空間複雜度**： $\mathcal{O}(1)$
  僅使用固定數量的純量變數（`a`, `b`, `countA`, `countB`）來儲存數據與邊界，完全沒有開闢任何動態陣列或額外緩衝空間。


## 邊界條件與潛在陷阱

1. **下界 $a-1$ 的安全防禦**：
   公式中使用的下界為 $a-1$。由於題目指出 $a$ 的最小值為 $1$，因此 $a-1$ 的最小可能值為 $0$。在 C++ 中調用 `sqrt(0)` 會正確回傳 `0.0`，經過 `floor` 轉換後同樣為 `0`。這代表當 $a=1$ 時，公式會精確計算為 $\lfloor\sqrt{b}\rfloor - 0$，完全符合物理現實，絕無越界或負數開根號的風險。
2. **浮點數精度防禦與強制轉型**：
   原程式碼中使用了 `floor(sqrt(...))`。由於 `sqrt` 函式回傳的是雙精度浮點數（`double`），在處理完美的完全平方數時（例如 $\sqrt{4} = 2.0000000...$），如果因為編譯器浮點數精度微幅震盪（例如極端下算成 `1.99999999`），使用 `floor` 或直接強制轉型為 `int` 可能會發生少 1 的致命地雷。

   * **強健性補強**：在處理此類純整數範圍（題目限制 $b \le 100,000$）的開根號時，由於數值非常小，雙精度浮點數具備足夠的有效位數，原實作的 `floor` 轉換在 UVa 評測系統中是非常安全且能順利拿到 AC 的。
4. **終止符 0 0 的精確攔截**：
   最外層必須使用 `while (cin >> a >> b && (a != 0 || b != 0))` 進行控制。只要 $a$ 與 $b$ 其中一個不為 0 就要繼續讀取，直到兩者皆為 0 時才安全煞車結束程式。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    long long a, b;
    int countA = 0, countB = 0;
    
    // 連續讀入區間上下界 a 與 b，當 a 與 b 皆為 0 時代表檔案結束
    while (cin >> a >> b && (a != 0 || b != 0)) {
        
        // 利用前綴相減定理：
        // countB 算出從 1 到 b 有多少個完全平方數
        // countA 算出從 1 到 a-1 有多少個完全平方數
        countA = floor(sqrt(a - 1));
        countB = floor(sqrt(b));
        
        // 兩者相減即為夾在閉區間 [a, b] 之間的所有完全平方數總數
        cout << countB - countA << "\n"; 
    }
    return 0;
}
```


## 進階優化思考

雖然目前調用 `sqrt` 的數學公式解在時間上已經達到了理論極限的 $\mathcal{O}(1)$ 常數時間，但若從底層硬體指令與純整數運算的考量出發，這題還存在另外一種非常巧妙的資工變體寫法。

**離線建表與二分搜尋（O(1) 查詢、免除浮點數開銷）**

在某些對效能要求極度嚴苛、或者硬體本身不具備浮點數運算單元（FPU）的嵌入式微處理器系統中，頻繁調用 `sqrt` 會引發高昂的軟體模擬開銷。

* **原理**：題目限制的最大邊界 $b \le 100,000$。我們知道 $\sqrt{100000} \approx 316.22$。這代表在這整個資料範疇內，總共只有 316 個完全平方數。

* **做法**：可以在程式初始化的階段，利用一個簡單的 `for` 迴圈跑 316 次，將所有平方數預先算好並平鋪推入一個有序的一維陣列中： `vector<int> squares;` 。後續當讀入一對詢問 $a$ 與 $b$ 時，直接調用標準庫的 `std::upper_bound` 與 `std::lower_bound` 進行二分搜尋。

* **效能改善**：此重構版本雖然查詢時間從絕對的 $\mathcal{O}(1)$ 微幅變成了對數時間 $\mathcal{O}(\log 316) \approx 8$ 次比對，但在底層完全抹除掉了任何涉及 `double` 浮點數的算術轉換與編譯器精度地雷。所有的數據運算皆在快取記憶體友善的連續整數數組上完成，是在硬體受限系統中非常核心的工程優化手段。

**優化程式碼實作片段：**
```cpp
// 於主程式外部或開頭進行一次性預處理預建表
vector<int> squares;
for (int i = 1; i * i <= 100000; i++) {
    squares.push_back(i * i);
}

// 後續主迴圈內的查詢操作
while (cin >> a >> b && (a != 0 || b != 0)) {
    // 尋找第一個大於 b 的位置
    auto up = upper_bound(squares.begin(), squares.end(), b);
    // 尋找第一個大於等於 a 的位置
    auto low = lower_bound(squares.begin(), squares.end(), a);
    
    // 指標直接相減，即可在純整數域中、完全零浮點數開銷下求出區間個數
    cout << (up - low) << "\n";
}
```
