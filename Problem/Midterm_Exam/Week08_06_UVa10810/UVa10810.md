# UVa 10810 - Ultra-QuickSort

## 題目簡述

給定一個長度為 $N$ 的正整數序列，我們只能使用**交換相鄰兩個元素**的操作來對該序列進行升序排序。<br>
請計算出：在最少的操作次數下，將整個序列完全排好序總共需要執行多少次相鄰元素的交換？

當輸入的序列長度 $N = 0$ 時，代表整個輸入流流向結束。

**Sample Input**：

  **5** $\rightarrow$ 第一組測資：序列長度 $N = 5$。<br>
  **9** $\rightarrow$ 序列的實體內容。<br>
  **1**<br>
  **0**<br>
  **5**<br>
  **4**<br>
  **0** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **6** $\rightarrow$ 透過最少 6 次相鄰交換可將該序列排好序。


## 解題思路與考點分析

### 核心觀念：逆序數對與合併排序（Inversion Pair & Merge Sort）
這道題目的題目名稱雖然叫 Ultra-QuickSort，但其本質是探討線性代數與資料結構中經典的 **逆序數對（Inversion Pair）** 統計問題。

在一個序列 $A$ 中，如果存在一組下標 $(i, j)$ 滿足 $i < j$ 且 $A[i] > A[j]$ ，這就構成了一個逆序數對。
* **演算法真理**：任何只能「交換相鄰元素」的排序演算法（如氣泡排序），每執行一次相鄰交換，在幾何本質上都**精確只能消除 1 個逆序數對**。因此，將序列排好序所需的最少相鄰交換次數，完全等價於該序列初始狀態下包含的**逆序數對總數**。

如果使用雙層 `for` 迴圈進行暴力計數，時間複雜度會退化到 $\mathcal{O}(N^2)$。在 $N \le 500,000$ 的大數據邊界下會直接引發 TLE。為此，我們必須借助 **分治法（Divide and Conquer）** 中的 **合併排序（Merge Sort）** 來將時間開銷壓縮至對數級別。



### 合併階段的逆序數對統計
在合併排序的 `merge` 階段，左半區子序列與右半區子序列都已經各自處於單調有序狀態。我們使用雙指標 `i`（指向左半區）與 `j`（指向右半區）進行流式掃描：

* 當遇到 `arr[i] <= arr[j]` 時：代表沒有發生逆序，直接移動 `i`。

* 當遇到 `arr[i] > arr[j]` 時：代表右半區的 `arr[j]` 比左半區當前指標 `arr[i]` 還要小。由於左半區已經是有序的，這意味著**從 `arr[i]` 開始到左半區中點 `mid` 的所有剩餘元素，在數值上都絕對大於 `arr[j]`**。
* **計數累積**：這些元素與 `arr[j]` 之間全部構成了逆序關係。因此，我們可以在常數時間內直接累積這批逆序對數量：<br>
  $$\text{invCount} += (\text{mid} - i + 1)$$


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \log N)$ <br>
  演算法完全沿用了合併排序（Merge Sort）的標準遞迴樹結構。整棵分治樹的深度為 $\log_2 N$，而每一層橫向合併（Merge）的總工作量固定為 $\mathcal{O}(N)$。因此，全域總時間複雜度被死死釘在高效的 $\mathcal{O}(N \log N)$，處理 50 萬筆資料可在幾十毫秒內瞬間完成。
* **空間複雜度**： $\mathcal{O}(N)$ <br>
  在合併過程中，需要配置一個與原序列等長的一維輔助陣列 `temp` 作為記憶體快取區，用於暫存排好序的元素，空間開銷與 $N$ 呈線性正比。


## 邊界條件與潛在陷阱

1. **大數據計數與整數溢位防禦（Integer Overflow）**：<br>
   這是本題最核心的 Wrong Answer 地雷。當序列長度 $N$ 達到 $500,000$ 且序列呈現完全降序（倒序）時，逆序數對的最大可能總數高達：
   $$\frac{N \times (N - 1)}{2} = \frac{500,000 \times 499,999}{2} \approx 1.25 \times 10^{11}$$
   這個數值已經大幅度彈出了標準 32 位元有號整數（`int`）最高 $2.14 \times 10^9$ 的承載天花板。

   * **程式碼防禦**：原程式碼在實作中非常優秀，將 `merge` 與 `mergeSort` 的回傳型態以及 `inv_count` 變數嚴格指定為了 **`long long`**（64 位元有號整數，上限高達 $9 \times 10^{18}$），完美且安全地防範了數值截斷的緻命風險。
2. **多組測資 EOF 連續讀取與動態配置**：<br>
   最外層使用 `while (cin >> n && n != 0)` 進行流控制，遇到 0 安全退出。在主迴圈內部動態宣告 `vector<int> arr(n)`，能確保每組測資都使用最精確的局部記憶體，不會產生跨 Case 的歷史數據污染。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

// 核心合併函式：在排序兩個有序子序列的同時，以 O(1) 常數時間累加跨區間的逆序數對
long long merge(vector<int>& arr, vector<int>& temp, int left, int mid, int right) {
    int i = left;    // 左半區子序列的起點指針 [left, mid]
    int j = mid + 1; // 右半區子序列的起點指針 [mid + 1, right]
    int k = left;    // 輔助快取陣列 temp 的寫入指針
    long long inv_count = 0; // 局部逆序對計數器

    // 雙指針流式橫向掃描比對
    while (i <= mid && j <= right) {
        if (arr[i] <= arr[j]) {
            temp[k++] = arr[i++];
        } else {
            // 貪婪計數：當左半區目前元素大於右半區目前元素時，
            // 由於左半區具備單調有序性，意味著左半區從 i 到 mid 的所有剩餘元素都大於 arr[j]
            temp[k++] = arr[j++];
            inv_count += (mid - i + 1); // 瞬間吃掉這批逆序對
        }
    }

    // 將左半區或右半區殘留的剩餘元素平鋪複製進 temp 中
    while (i <= mid) {
        temp[k++] = arr[i++];
    }
    while (j <= right) {
        temp[k++] = arr[j++];
    }

    // 將排好序的快取緩衝區內容原地覆蓋回原陣列中，確保上層遞迴結構有序
    for (i = left; i <= right; i++) {
        arr[i] = temp[i];
    }
    return inv_count;
}

// 分治遞迴主體
long long mergeSort(vector<int>& arr, vector<int>& temp, int left, int right) {
    long long inv_count = 0;
    if (left < right) {
        // 安全中點計算公式，有效防範硬體下標溢位
        int mid = left + (right - left) / 2;

        // 分而治之：全域逆序對 = 左子樹內部逆序對 + 右子樹內部逆序對 + 跨區間合併逆序對
        inv_count += mergeSort(arr, temp, left, mid);
        inv_count += mergeSort(arr, temp, mid + 1, right);
        inv_count += merge(arr, temp, left, mid, right);
    }
    return inv_count;
}

int main() {
    // 提升標準 I/O 串流之效能
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n;
    // 連續讀入序列長度 n，當 n = 0 時安全煞車終止
    while (cin >> n && n != 0) {
        vector<int> arr(n);
        vector<int> temp(n); // 預先開闢一塊等長的連續輔助記憶體

        for (int i = 0; i < n; ++i) {
            cin >> arr[i];
        }

        // 執行合併排序並秒殺輸出最終的總逆序數對（最少相鄰交換次數）
        cout << mergeSort(arr, temp, 0, n - 1) << "\n";
    }
    return 0;
}
```


## 進階優化思考

**空間極致壓縮與動態記憶體重用（In-place Allocation Optimization）**

在目前的實作中，我們在 `while` 迴圈內部每一輪新測資進來時，都動態宣告了 `vector<int> temp(n)`。雖然它的生命週期控管很健康，但在面對上百組密集資料的高頻率評測時，頻繁向作業系統核心申請 Heap 區塊記憶體配置仍會引發顯著的常數時間耗損與記憶體碎片化。

* **優化做法**：由於題目給定的最大總人數 $N \le 500,000$，我們可以直接在主程式的最外層（或者全域）一次性宣告一個最大上限的靜態快取陣列：
  ```cpp
  vector<int> temp(500005);
  ```
* **底層效益**：在後續的所有遞迴分治轉移中，不需要重複開闢新空間，直接共享並傳引用這塊早已配置好的全域連續內存。這能將整台程式的動態空間申請次數直接降為零，讓 CPU 能夠在完全連續的硬體軌道上執行高速快取預取（Cache Prefetching），是將合併排序常數效能壓榨至物理極限的頂規調優打法。
