# UVa 11321 - Sort! Sort!! and Sort!!!

## 題目簡述

給定 $N$ 個整數以及一個除數 $M$。請依照題目給定的特殊排序規則，將這 $N$ 個整數進行重新排列：
1. **餘數大小優先**：每個數字除以 $M$ 得到的「餘數」越小，該數字排在越前面（由小到大）。
2. **餘數相同時的碰撞規則**：
   
   * **一奇一偶**：若其中一個是奇數、另一個是偶數，則**奇數排在偶數前面**。
   * **皆為奇數**：若兩個數字都是奇數，則**數值較大者排在前面**（由大到小）。
   * **皆為偶數**：若兩個數字都是偶數，則**數值較小者排在前面**（由小到大）。

當輸入的 $N = 0$ 且 $M = 0$ 時，代表整個輸入流結束。

**Sample Input**：

  **12**<br>
  **13**<br>
  **14**<br>
  **15**<br>
  **0 0** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **15 3** $\rightarrow$ 輸出第一行必須印出當前 Case 的 $N$ 與 $M$。<br>
  **15** $\rightarrow$ 餘數 0 奇數大到小。<br>

## 解題思路與自定義排序

### 核心觀念：自定義比較函式與負數取模修正
這道題目的本質是**高階排序控制（Custom Sorting）與多重條件分支判定**。
在 C++ 中，最標準且優雅的實作方式是直接使用標準庫的 `std::sort`，並傳入一個自定義的比較函式（Comparator）`cmp(int a, int b)`。

自定義排序函式在設計上要嚴格依循多決策分支樹：

1. **分支一：餘數不同（`A != B`）**：
   這是最高優先級條件。直接回傳 `A < B`，確保餘數小的排在前面。
2. **分支二：餘數相同且一奇一偶**：
   
   * 若 `a` 是奇數、`b` 是偶數：回傳 `true`（`a` 應在 `b` 前）。
   * 若 `a` 是偶數、`b` 是奇數：回傳 `false`（`b` 應在 `a` 前）。
3. **分支三：餘數相同且皆為奇數**：
   題目要求大奇數在前。回傳 `a > b`。
4. **分支四：餘數相同且皆為偶數**：
   題目要求小偶數在前。回傳 `a < b`。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \log N)$
  演算法核心為 `std::sort` 進行全局重排。在自定義比較函式 `cmp` 內部，所有奇偶判斷、取模與代數比較皆為常數時間 $\mathcal{O}(1)$ 操作。因此，整體時間複雜度由排序模型決定，平攤後為最優的 $\mathcal{O}(N \log N)$。代入題目上限（ $N \le 10,000$ ），總運算次數約為 $1.4 \times 10^5$ 次，可在幾毫秒內極速通關。
* **空間複雜度**： $\mathcal{O}(N)$
  需要動態配置一個大小為 $N$ 的 `vector<int> nums` 陣列來儲存待排序的原始整數數據，空間開銷與輸入規模呈線性正比。


## 邊界條件與潛在陷阱

1. **負數取模（Negative Modulo）地雷**：
   這是本題最致命的 Wrong Answer 陷阱。在 C++ 語法中，負數取模會保留負號（例如：`-5 % 3` 的結果會是 `-2`，而非數學上的 `1`）。

   * **原程式碼分析**：在比較函式中，直接寫 `int A = a % M; int B = b % M;`。由於 C++ 內建的 `-2 < -1 < 0 < 1` 順序剛好與題目要求的「餘數由小到大」升序完全同構。因此在進行 `A != B` 的 `return A < B;` 比較時，負數餘數會被正確且安全地排在最前面。
3. **負奇數的絕對值防禦（奇偶判斷盲點）**：
   原程式碼中撰寫了一個輔助函式 `bool isOdd(int n)`，內部採用 `return abs(n % 2) == 1;`。這個設計非常厲害且正確！因為負奇數取模（如 `-5 % 2`）會得到 `-1`。如果只寫 `n % 2 == 1`，會漏掉所有的負奇數。套用 `abs()` 絕對值後，不論正負奇數都能被精確識別。
4. **結尾輸出規範（最後一行的 0 0）**：
   題目規範非常嚴格：「當讀到輸入終止符 $N=0, M=0$ 時，主迴圈應跳出，但**最後的輸出端也必須精確印出一行 `0 0`**」。原程式碼在主迴圈外部補上了 `cout << "0 0" << endl;`，格式完全正確，成功規避了 Presentation Error。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

// 全域變數，方便比較函式 cmp 直接存取除數 M
int N, M;

// 輔助函式：安全判斷奇偶性，套用 abs 防範負奇數取模得到 -1 的盲點
bool isOdd(int n) {
    return abs(n % 2) == 1;
}

// 自定義比較函式：嚴格實作題目規定的多重碰撞分支
bool cmp(int a, int b) {
    int A = a % M;
    int B = b % M;
    
    // 規則一：優先考量餘數大小，餘數小者排在前面 (由小到大)
    if (A != B) {
        return A < B;
    }
    
    // 當餘數完全相同時，進入多重條件碰撞排除
    bool aOdd = isOdd(a);
    bool bOdd = isOdd(b);
    
    // 規則二：一奇一偶，奇數必須排在偶數前面
    if (aOdd && !bOdd) return true;  // a為奇b為偶，a在前
    if (!aOdd && bOdd) return false; // a為偶b為奇，b在前
    
    // 規則三：兩者皆為奇數，數值大者排在前面 (由大到小)
    if (aOdd && bOdd) { 
        return a > b; 
    }
    
    // 規則四：兩者皆為偶數，數值小者排在前面 (由小到大)
    if (!aOdd && !bOdd) { 
        return a < b; 
    }
    return false;
}

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    // 持續讀入數字個數 N 與除數 M，當兩者皆為 0 時停止
    while (cin >> N >> M && (N != 0 || M != 0)) {
        vector<int> nums(N);
        for (int i = 0; i < N; i++) {
            cin >> nums[i];
        }
        
        // 套用標準庫 sort，並將自定義的比較邏輯 cmp 作為第三引數傳入
        sort(nums.begin(), nums.end(), cmp);
        
        // 依照題目規格精確輸出當前 Case 的標頭
        cout << N << " " << M << "\n";
        for (int j = 0; j < N; j++) {
            cout << nums[j] << "\n";
        }
    }
    // 邊界防禦：當輸入結束時，結尾必須精確印出一行 0 0
    cout << "0 0\n";
    return 0;
}
```


## 進階優化思考

原做法直接調用 std::sort，其內部的 IntroSort（混合了快速排序、堆疊排序與插入排序）已經做到了極致的常數優化。但在資工的高階系統設計與面試視角下，若想完全擺脫多重 if-else 分支所帶來的 CPU 分支預測失敗（Branch Misprediction）代價，存在著一種架構更清晰的優化策略。

**分桶穩定排序（Bucket-Grouping 策略）**

* **原理**：既然最高優先權是依據「除以 $M$ 的餘數」來進行歸類，且 $M$ 的範圍通常有限。

* **做法**：可以建立一個大小為 $M$ 的動態二維陣列（即數組的數組 `vector<vector<int>> buckets(M);` ）。

  * 讀入數據時，直接將數字推入對應餘數的桶子中： `buckets[num % M].push_back(num);` （若是負數，可透過 `(num % M + M) % M` 映射到正數域索引）。
  * 分流完畢後，只需對每個桶子內部的元素單獨進行排序。此時每個桶子內部所有的元素「餘數皆完全相同」，在排序時比較函式內部只需專心處理奇偶與數值大小比對，完全抹除了餘數比較的邏輯開銷。
 
* **效能改善**：這樣做能將單次全局排序的規模拆解為多個微型局部的排序，大幅減輕了資料移動的代價，且能有效提高 CPU 核心的快取命中率（Cache Locality），是應對超大規模資料重排時非常實用的分治架構調優手法。
