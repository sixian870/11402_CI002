# UVa 10226 - Hardwood Species

## 題目簡述

自然資源保護局需要統計衛星地圖中各個樹種（Species）的分布密度。
給定多個測試群組，每個群組包含一連串輸入的樹木名稱（每行代表一棵樹的樹種名稱）。
請統計出該群組中**所有相異樹種的總清單**、**每種樹木出現的絕對次數**，並計算出**每種樹木佔該測資總樹木數量的百分比（Percentage）**。

**核心輸出限制**：
1. 輸出的樹種清單必須嚴格按照 **字典順序（Alphabetical order）** 由小到大排列。
2. 計算出的百分比必須精確至**小數點後四位（浮點數格式化輸出）**。
3. 每組測試資料的輸出之間，必須精確以一個 **空行（Blank line）** 隔開。

**Sample Input**：

  **1** $\rightarrow$ 測試資料組數 $T$。<br>
  <br> $\rightarrow$ **注意：組數讀取完後，緊隨其後會包含一個關鍵的空行。**
  **Red Pine** $\rightarrow$ 樹木名稱（可能包含空格）。<br>
  **White Oak**<br>
  **Red Pine**<br>
  <br> $\rightarrow$ 當 getline 讀取到空行時，代表該組測試資料結束。

**Sample Output**：

  **Red Pine 66.6667** $\rightarrow$ 依字典序升序輸出名稱，後接百分比（精確至小數點後四位）。<br>
  **White Oak 33.3333**


## 解題思路與關聯式容器

### 核心觀念：平衡二元搜尋樹與流式文本計數（Map / String Stream）
這道題目的本質是**字串流的頻率統計、自動有序排序與浮點數格式化控制**。
由於題目要求最終輸出的樹種名稱必須「嚴格按字典順序排列」，這完美的對應到了 C++ 的標準關聯式容器——**`std::map<string, int>`**。

`std::map` 的底層是由**紅黑樹（Red-Black Tree）**這種平衡二元搜尋樹實作而成。每當執行 `tree[s]++` 插入或更新新字串時，容器內部會自動在 $\mathcal{O}(\log M)$ 時間內依據字串的字典序完成單調性維護。這使得在資料讀取完畢後，不需額外調用任何高昂的排序函式（如 `std::sort`），直接遍歷 `map` 即可天然獲得由小到大的有序輸出。

### 演算法步驟
1. 讀入測試組數 $T$，並利用 `cin.ignore()` 立即將其後方殘留的換行符抹除。
2. 利用一記單獨的 `getline(cin, s)`，把組數與首組測資之間夾帶的那行「空白過渡行」安全吃掉。
3. **內層數據抽離（以空行作為邊界）**：
   利用 `while (getline(cin, s) && !s.empty())` 持續讀入樹木名稱。只要讀到該行不為空，就執行 `tree[s]++` 進行計數，並讓全域累加器 `total++`。一旦遇到空行（`s.empty()`），迴圈安全跳出，代表當前區塊統計完畢。
4. **格式化佔比計算**：
   遍歷整個 `map` 容器。每種樹的佔比公式為：
   $$\text{Percentage} = \frac{\text{i.second}}{\text{total}} \times 100$$
   利用 `<iomanip>` 庫中的 `fixed` 與 `setprecision(4)` 強制控制輸出流，確保小數點精確度。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(T \times N \log M)$
  其中 $T$ 為總組數， $N$ 為單組測資中的樹木總總數， $M$ 為該組中相異的樹種數量（ $M \le 10,000$ ）。在數據讀入階段，每次將長度為 $L$ 的字串推入紅黑樹並進行字典序比對與節點調整，最大代價為 $\mathcal{O}(L \log M)$。總體平攤時間複雜度為 $\mathcal{O}(N \log M)$，在每組高達 10,000 棵樹的規模下，可在幾毫秒內極速通關。
* **空間複雜度**： $\mathcal{O}(M \times L)$
  `std::map` 內部需要開闢節點來儲存這 $M$ 個相異樹種的實體字串與出現頻率。記憶體空間消耗與相異樹種的總字元量呈線性正比，配置效率極高。


## 邊界條件與潛在陷阱

1. **包含空格的樹種名稱（`getline` 的核心必要性）**：
   
   樹種的名稱中**極有可能包含空格（例如 `"Red Pine"`, `"White Oak"`）**。如果習慣性地使用 `cin >> s` 讀取，輸入流會在遇到中間的空格時自動切斷，把 `"Red"` 和 `"Pine"` 當作兩棵獨立的樹來統計，引發嚴重的邏輯潰敗。**必須嚴格使用 `getline(cin, s)` 抓取包含空格的完整行**。

2. **多組測資間的空行控制（Presentation Error 防禦）**：
   
   題目要求「每組測資的輸出結果之間」必須精確夾帶一個空行。

   * **原本寫法漏洞**：若無腦在每組 Case 結尾都印 `cout << endl;`，會導致最後一組資料的屁股後面多出一個不該存在的空行，被評測系統直接退回 Presentation Error。
   * **最優去尾策略**：原程式碼中利用 `bool isFirst = true;` 配合 `if (!isFirst) cout << "\n";` 的置頂翻轉設計。在第一組 Case 輸出時不加空行，從第二組 Case 開始才在「標頭上方」補換行。這完美地達成了首尾無多餘空行的規範。

3. **浮點數整除截斷防禦**：
   
   在計算百分比時，`i.second` 與 `total` 皆為整數型態（`int`）。如果直接寫 `i.second / total`，會觸發 C++ 的整數除法機制，直接被截斷成 `0`。**必須將其中一個變數強制轉型為 `(double)`**，才能安全啟動浮點數精確除法。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int t;
    if (cin >> t) {
        cin.ignore(); // 核心防禦：清除讀取 t 後殘留在緩衝區的換行符 \n
        
        string s;
        getline(cin, s); // 核心防禦：吃掉組數與首組測資之間的過渡空白行
        
        bool isFirst = true;
        
        while (t--) {
            // 宣告平衡二元搜尋樹映射容器，底層紅黑樹天然保證 Key (樹名) 字典序升序
            map<string, int> tree_map;
            int total_count = 0; // 當前測試群組的樹木總累加器
            
            // 逐行讀入樹名，直到讀到空行（代表該組資料結束標界）
            while (getline(cin, s) && !s.empty()) {
                tree_map[s]++;
                total_count++;
            }
            
            // 格式控制：自第二組測資開始，在輸出標頭前幫前一組補換行，精確去尾
            if (!isFirst) {
                cout << "\n";
            }
            
            // 遍歷紅黑樹，此時 i.first (樹名) 已完全按照字典順序由小到大排列好
            for (auto const& i : tree_map) {
                // 強制轉型 (double) 避開整數整除截斷地雷，配合 fixed 與 setprecision(4) 鎖定小數後四位
                double percentage = (double)i.second / total_count * 100.0;
                cout << i.first << " " << fixed << setprecision(4) << percentage << "\n";
            }
            
            isFirst = false; // 翻轉首組標記
        }
    }
    return 0;
}
```


## 進階優化思考

雖然基於紅黑樹的 std::map 在語意對應與排序控制上非常直觀，但在資工的高階大數據調優考量下，它在處理海量重複數據時並非時間最優解。

**雜湊計數與離線排序分治（Hash-Map & Sort 策略）**

* **原理**： `std::map` 在每次插入新字串時，都需要跑一次 $\mathcal{O}(\log M)$ 的樹節點旋轉與字串比對。如果在實際衛星地圖中，樹木的數量極其龐大（如 $N = 10^7$），而樹種數量很少（如 $M = 100$），紅黑樹會反覆執行大量昂貴的平衡維護。

* **做法**：可以將主要計數容器替換為基於雜湊表（Hash Table）的 `std::unordered_map<string, int>` 。

  * **讀取階段**：每次插入與累加在雜湊表中的平攤時間複雜度為最優的 $\mathcal{O}(1)$。
  * **排序階段**：資料全數讀完後（此時只有少數 $M$ 個節點），再把這 $M$ 個相異樹種一次性推入一個一維 `vector` 中，單獨調用 `std::sort` 進行最終字典序重排。
  * **效能改善**：此重構版本將演算法的總體時間代價從 $\mathcal{O}(N \log M)$ 強制優化到了平攤的 $\mathcal{O}(N + M \log M)$。在面對真實世界中「高重複、高吞吐量」的文本數據流統計時，此策略能徹底釋放 CPU 的計算潛能，展現出高階後端系統架構特有的穩健與高效。

**優化程式碼實作片段：**
```cpp
unordered_map<string, int> hash_tree;
// ...在 O(1) 內極速完成所有文本讀入與累加 ...

// 讀完後，單獨將少數的相異樹種抽離到 vector 中
vector<pair<string, int>> sorted_trees(hash_tree.begin(), hash_tree.end());
// 僅對這極少數的 M 個元素進行一次性排序
sort(sorted_trees.begin(), sorted_trees.end());
```
