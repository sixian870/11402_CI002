# UVa 12250 - Language Detection

## 題目簡述

給定一個代表問候語的字串，請判斷該問候語屬於哪一種語言。本題預先定義了六種常見語言的問候語對應關係如下：
* **HELLO** $\rightarrow$ ENGLISH (英文)
* **HOLA** $\rightarrow$ SPANISH (西班牙文)
* **HALLO** $\rightarrow$ GERMAN (德文)
* **BONJOUR** $\rightarrow$ FRENCH (法文)
* **CIAO** $\rightarrow$ ITALIAN (義大利文)
* **ZDRAVSTVUJTE** $\rightarrow$ RUSSIAN (俄文)

**輸入規範**：
連續讀入字串，每行一個單字，直到讀入的字串為井字號 `"#"` 時代表輸入流結束。輸入的單字長度最多不超過 14 個字元，且皆為大寫字母。

**輸出規範**：
對於每組測試資料，請依序輸出對應的 Case 編號以及判定出的語言名稱。如果輸入的問候語不在上述六種已知的清單內，則一律輸出 `UNKNOWN`。

**Sample Input**：

  **HELLO** $\rightarrow$ 第一組輸入字串。<br>
  **HOLA**<br>
  **ALOHA**<br>
  **#** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **Case 1: ENGLISH** <br>
  **Case 2: SPANISH** <br>
  **Case 3: UNKNOWN** $\rightarrow$ "ALOHA" 不在定義的六種語言內。


## 解題思路與分支條件控制

### 核心觀念：字串精確比對與條件分支（String Matching & Conditional Branches）
這道題目的本質是基礎的**字串精確比對與多路條件分支控制**。

由於題目給定的語言對應規則是完全固定且有限的（僅有六種對應關係），不需要引入複雜的字串匹配演算法（如 KMP 或 Trie 樹），直接利用標準的字串流讀入，並透過多層的 `if - else if - else` 分支結構進行等值比對，即可在常數時間內完成決策。



### 演算法步驟
1. 初始化 Case 計數器 `count = 1`。
2. 利用 `while (cin >> s && s != "#")` 建立流式監聽迴圈，當讀入的字串不是 `"#"` 時，持續執行內部邏輯。
3. 進入多路分支判定：將讀入的字串 `s` 與定義好的六個大寫單字逐一比對。
   * 若精確吻合某個單字，則輸出該語言對應的正體名稱。
   * 若掃描完六種分支皆無法匹配，則自動跌落入最後的 `else` 收容分支，輸出 `UNKNOWN`。
4. 每處理完一組字串，計數器 `count` 自動遞增 1。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(T \times L)$ <br>
  其中 $T$ 為總測試字串的數量， $L$ 為單個輸入字串的長度（題目限制 $L \le 14$）。在 C++ 中，`std::string` 的 `==` 運算子比對時間與字串長度呈線性正比。由於分支數量固定為 6，單次判定的比對次數為常數級別，因此單組測資耗時為 $\mathcal{O}(L)$。在微秒級別內即可完成評測。
* **空間複雜度**： $\mathcal{O}(L)$ <br>
  僅開闢了一個標準字串變數 `s` 來動態緩衝當前輸入的單字，以及一個整型變數 `count` 記錄編號，未佔用額外的動態資料結構，空間配置極其精簡。


## 邊界條件與潛在陷阱

1. **終止符的精確攔截**：<br>
   結束標記 `"#"` 必須放在迴圈的起點進行短路攔截。如果將判定錯置在讀入之後、輸出 Case 編號之前，會導致程式在讀入 `"#"` 時依然多印出一行荒謬的 `Case X: UNKNOWN`。原程式碼採用 `while (cin >> s && s != "#")`，將讀入與終止判定進行原子化綁定，完美避免了多餘輸出的地雷。
2. **未知單字的容錯分流**：<br>
   對於如 `ALOHA` 或其他隨機雜湊字串，必須確保它們能安全滾入最後的 `else` 防線。原實作的分支覆蓋率非常健康，杜絕了邏輯死角的發生。
3. **字串大小寫對齊**：<br>
   題目保證輸入皆為大寫字母，因此不需要在讀入時手動進行 `tolower` 或 `toupper` 的字元轉換，直接比對即可保持代碼的輕量與高效。


## 程式碼實作

```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);

    string s;
    int count = 1;
    
    // 流式讀入字串 s，當偵測到 "#" 時立即安全跳出迴圈
    while (cin >> s && s != "#") {
        // 精確輸出 Case 編號標頭
        cout << "Case " << count++;
        
        // 核心字串多路分支精確比對
        if (s == "HELLO") {
            cout << ": ENGLISH\n";
        }
        else if (s == "HOLA") {
            cout << ": SPANISH\n";
        }
        else if (s == "HALLO") {
            cout << ": GERMAN\n";
        }
        else if (s == "BONJOUR") {
            cout << ": FRENCH\n";
        }
        else if (s == "CIAO") {
            cout << ": ITALIAN\n";
        }
        else if (s == "ZDRAVSTVUJTE") {
            cout << ": RUSSIAN\n";
        }
        else {
            // 處理所有未定義的未知問候語
            cout << ": UNKNOWN\n";
        }
    }
    return 0;
}
```


## 進階優化思考

**雜湊表映射優化與常數時間複雜度（Unordered_Map / Hash Table 策略）**

雖然目前的 `if-else` 線性分支在 6 個單字的超小規模下執行速度極快，但在高階軟體工程維護性或分支規模擴展（例如未來要擴大支援 100 種語言）的視角下，過多臃腫的條件分支會導致代碼可讀性劇烈下降，且會產生大量的 CPU 分支預測錯誤（Branch Misprediction）開銷。

* **優化做法**：我們可以拋棄繁瑣的 `if-else` 硬編碼，改用標準庫的雜湊對照表 `std::unordered_map<string, string>` 在初始化階段建立查表軌道。

* **效能改善**：將所有問候語與語言的對應關係預先寫入雜湊表中。隨後每當讀入字串 `s`，直接調用 `pos = lang_map.find(s)`。如果能在 $\mathcal{O}(1)$ 常數時間內找到對應指標，就直接輸出結果；若沒找到則輸出 `UNKNOWN`。

* **底層效益**：此重構版本將演算法的控制邏輯與底層數據進行了徹底的**解耦（Decoupling）**。不論未來語言清單擴充到多麼龐大，整體的查詢代價在雜湊函數的保護下將永遠被死死釘在絕對的 $\mathcal{O}(1)$ 常數時間，且代碼結構優雅洗練，是現代工程開發中非常正統的結構調優範式。

**優化程式碼實作片段：**
```cpp
// 在主程式開頭進行靜態綁定
unordered_map<string, string> lang_map = {
    {"HELLO", "ENGLISH"}, {"HOLA", "SPANISH"}, {"HALLO", "GERMAN"},
    {"BONJOUR", "FRENCH"}, {"CIAO", "ITALIAN"}, {"ZDRAVSTVUJTE", "RUSSIAN"}
};

// 迴圈內部流式查詢：
auto it = lang_map.find(s); // O(1) 雜湊尋址
if (it != lang_map.end()) {
    cout << "Case " << count++ << ": " << it->second << "\n";
} else {
    cout << "Case " << count++ << ": UNKNOWN\n";
}
```
