# UVa 10821 - Pure Trees

## 題目簡述

給定一組連續的正整數 $1$ 到 $N$，我們要將這些數字建立成一棵具有給定高度限制 $H$ 的**二元搜尋樹（Binary Search Tree, BST）**。
為了讓這棵樹在後續的資料檢索中擁有最優的效能，我們希望這棵樹建立好之後，對它進行**前序走訪（Pre-order Traversal）**所得到的序列，其**字典序（Lexicographical Order）是所有可行樹中最小的**。

如果給定的高度 $H$ 太小，以至於根本不可能容納 $N$ 個節點（即 $N > 2^H - 1$ ），則需要輸出 `Impossible.`。

**Sample Input**：

  **3 2** $\rightarrow$ 第一組測資： $N = 3$ 個節點，限制高度 $H = 2$。<br>
  **3 1** $\rightarrow$ 第二組測資： $N = 3$ 個節點，限制高度 $H = 1$。<br>
  **0 0** $\rightarrow$ 輸入結束標記。

**Sample Output**：

  **Case 1: 2 1 3** $\rightarrow$ 高度為 2 且字典序最小的前序序列。<br>
  **Case 2: Impossible.** $\rightarrow$ 高度為 1 最多只能放 1 個節點，無法容納 3 個節點。


## 解題思路與貪婪分治策略

### 核心觀念：BST 的性質與前序字典序最小化（Greedy & Divide and Conquer）
這道題目的本質是**利用分治法結合貪婪策略來構造特定二元搜尋樹**。

前序走訪的順序是：`根節點 -> 左子樹 -> 右子樹`。
為了讓輸出的前序序列字典序最小，我們在挑選當前子樹的「根節點 $K$」時，應該要**盡可能挑選越小的數字越好**。

然而，根節點 $K$ 不能無限小。因為一旦我們選了 $K$ 作為根節點，根據 BST 的性質：
* 比 $K$ 大的數字（共 $R - K$ 個）都必須被塞進 **右子樹**。
* 如果目前允許的總高度為 $H$，那麼右子樹能分配到的最大高度上限就只有 $H - 1$。
* 一棵高度為 $H - 1$ 的二元樹，最多只能容納 $2^{H-1} - 1$ 個節點。

因此，為了保證右邊剩餘的數字不至於「塞不下」，我們挑選的根節點 $K$ 必須滿足一條鋼體底線：**右邊剩下的數字量不能超過右子樹的容量天花板**。這就是一個完美的貪婪折衷策略。

### 演算法步驟
1. **可行性邊界檢查**：<br>
   在高度為 $H$ 的限制下，滿二元樹的總節點上限為 $2^H - 1$。如果 $N$ 超過這個數值，直接輸出 `Impossible.`。
2. **貪婪挑選根節點**：<br>
   在當前區間 $[L, R]$ 內，右子樹最多能承受的節點數為 `max_right = ` $(1 \ll (H - 1)) - 1$。
   因此，右側最少需要保留的起點界線為 `required_k = R - max_right`。我們貪婪地選擇 `K = max(L, required_k)` 作為根節點並輸出。
3. **分治遞迴**：<br>
   輸出根節點後，將問題切分為兩個獨立的子區間，並將可用高度減 1（`H - 1`），繼續遞迴建構：

   * 左子樹區間： $[L, K - 1]$
   * 右子樹區間： $[K + 1, R]$


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N)$ <br>
  每組測試資料在遞迴過程中，每個節點都精確被挑選並輸出一次。挑選根節點的幾何運算皆為 $\mathcal{O}(1)$ 常數位元操作。因此，總體時間複雜度與節點總數 $N$ 呈完全的線性正比，效率極高。
* **空間複雜度**： $\mathcal{O}(H)$ <br>
  演算法使用了分治遞迴，主要空間消耗來自於系統的函數呼叫堆疊（Function Call Stack）。遞迴的最大深度等於樹的高度 $H$，因此空間複雜度為 $\mathcal{O}(H)$。


## 邊界條件與潛在陷阱

1. **位元位移溢位防禦（Bit Shift Overflow）**：<br>
   當高度 $H \ge 60$ 時，如果直接寫 `1 << H`，會因為超出了標準 32 位元整數（`int`）的範圍而引發硬體截斷或未定義行為。

   * **程式碼防禦**：原實作非常聰明。首先加入 `if (H - 1 >= 30)` 的特判，當高度大於 30 時，代表右子樹的容量至少有 $2^{30} - 1$（遠大於題目要求的 $N$ 上限），此時右側容量絕對無限大，根節點可以直接放心地選最小值 `K = L`。而在計算位移時，採用了 `1LL << (H - 1)`，強行提升為 64 位元長整型，完全抹除了溢位風險。
2. **終止條件的精確對齊**：<br>
   最外層使用 `while (cin >> N >> H && (N != 0 || H != 0))` 進行監聽，當 $N$ 與 $H$ 同時為 0 時代表測資流結束。在遞迴函數內部，利用 `if (L > R) return;` 作為底端葉子節點的收容煞車線。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

// 核心分治遞迴函式：在區間 [L, R] 且可用高度為 H 的限制下，構造前序字典序最小的 BST
void build(long long L, long long R, int H) {
    // 遞迴終止條件：區間收縮完畢，直接返回
    if (L > R) return;
    
    long long K;
    // 安全防禦：若剩餘可用高度大於 30，代表右子樹容量無限，根節點可以直接貪婪地選最小值 L
    if (H - 1 >= 30) {
        K = L;
    } else {
        // 計算高度為 H - 1 的右子樹所能容納的極限節點數
        long long max_right = (1LL << (H - 1)) - 1;
        // 為了讓右邊剩餘的物件塞得下，根節點 K 至少必須達到的數值
        long long required_k = R - max_right;
        // 貪婪挑選：在合法的前提下，選取最小的數字作為根節點
        K = max(L, required_k);
    }
    
    // 依照前序走訪順序，優先輸出當前根節點
    cout << " " << K;
    
    // 分而治之：同步向左右子樹進行遞迴建構，高度皆扣減 1
    build(L, K - 1, H - 1); // 構造左子樹
    build(K + 1, R, H - 1); // 構造右子樹
}

int main() {
    // 提升標準 I/O 串流之效能
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    long long N;
    int H;
    int case_num = 1;
    
    // 連續讀入節點數 N 與高度限制 H，當兩者皆為 0 時安全煞車
    while (cin >> N >> H && (N != 0 || H != 0)) {
        cout << "Case " << case_num++ << ":";
        
        // 幾何剪枝：如果總節點數超過該高度所能承載的滿二元樹上限，必定無解
        if (H < 30 && N > (1LL << H) - 1) {
            cout << " Impossible.\n";
        } else {
            // 執行貪婪分治建樹
            build(1, N, H);
            cout << "\n";
        }
    }
    return 0;
}
```


## 進階優化思考

**尾端遞迴消除與非遞迴化改造（Tail-Recursion Elimination）**

雖然目前的遞迴實作在 $\mathcal{O}(N)$ 的時間表現下非常優秀，但每一次調用 `build` 函式都會在系統的棧記憶體（Stack）中壓入新的棧幀（Stack Frame）。在極限深度或資源極其受限的嵌入式硬體平台上，過深的遞迴仍有引發爆棧（Stack Overflow）的隱憂。

* **優化做法**：觀察 `build` 函式的結構，可以發現右子樹的呼叫 `build(K + 1, R, H - 1);` 處於整個函式的最末端，這符合標準的**尾端遞迴（Tail Recursion）**定義。

* **技術精髓**：我們可以手動將其改寫為 `while` 迴圈迭代結構，每次在處理完左子樹後，直接就地修改狀態變數 `L = K + 1; H = H - 1;` 並回到迴圈開頭。這項重構能直接砍掉一半的系統棧開銷，使其空間複雜度優化得更為穩健，同時也能免除函數調用時保護現場與恢復現場的暫存器切換成本，是極限壓榨演算法常數效能的高階手段。
