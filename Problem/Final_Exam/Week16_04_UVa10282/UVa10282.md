# UVa 10282 - Babelfish

## 題目簡述

我需要幫忙建立一個外語對照辭典。輸入包含兩個部分：
1. **辭典建立階段**：每行包含兩個字串，第一個字為英文單字，第二個字為對應的外語單字，兩字之間以空格隔開。當讀入一個 **完全空白行（Empty line）** 時，代表辭典建立結束。
2. **單字查詢階段**：接下來每行會輸入一個外語單字。我必須在辭典中尋找該外語單字對應的英文單字。

如果查詢的外語單字存在於辭典中，則印出對應的英文單字；如果辭典中查無此字，則統一印出 `eh`。

**Sample Input**：

  **dog ogday** $\rightarrow$ "ogday" 對應 "dog"。<br>
  **cat atcay** $\rightarrow$ "atcay" 對應 "cat"。<br>
  <br> $\rightarrow$ 空白行，代表辭典輸入結束。<br>
  **ogday** $\rightarrow$ 第一個查詢。<br>
  **fanyay** $\rightarrow$ 第二個查詢。

**Sample Output**：

  **dog** <br>
  **eh** $\rightarrow$ "fanyay" 不在辭典中，輸出 eh。


## 解題思路與關聯式容器應用

### 核心觀念：雜湊表映射與字串流解析（Hash Table Lookup & Stringstream）
這道題目的本質是典型的 **字串鍵值映射（Key-Value Mapping）** 與快速檢索問題。

由於查詢的次數可能非常多，如果每讀入一個單字都用線性搜尋（Linear Search）去遍歷整個辭典，時間複雜度會退化到 $\mathcal{O}(M \times N)$（ $N$ 為辭典大小，$M$ 為查詢次數），這會導致程式直接拿到 TLE。為了達成極速檢索，我使用 C++ 的標準關聯式容器 **`std::unordered_map`**。

`std::unordered_map` 底層是以雜湊表（Hash Table）來實作。我將外語單字作為鍵值（Key），將英文單字作為對應值（Value）。這樣一來，不論辭典規模多大，每次查詢都能在平均常數時間內直接命中答案。

### 演算法步驟
1. **空白行截斷讀取**：<br>
   我利用 `getline(cin, line)` 線性讀入整行字串。當偵測到 `line.empty()` 為真時，立刻切斷第一階段的讀取。

2. **字串切割（Tokenization）**：<br>
   對於辭典的每一行，我透過 `std::stringstream` 將原本用空格相連的一整行文字，精確拆分出兩個獨立字串 `english` 與 `foreign`，並將其塞入雜湊表中：`dictionary[foreign] = english;`。

3. **線上查詢與存在性判定**：<br>
   進入第二階段，連續讀入外語單字直到檔案結束（EOF）。我使用 `dictionary.count(query_word)` 來檢查該單字是否存在於雜湊表中。若存在則直接輸出，否則分流輸出 `eh`。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N \times L_1 + M \times L_2)$ 

  * **建立辭典階段**：共有 $N$ 筆對照資料。字串流拆分與雜湊表插入平均耗時均為常數時間。考慮到字串長度，耗時為 $\mathcal{O}(N \times L_1)$（ $L_1$ 為平均單字長度）。

  * **單字查詢階段**：總共執行 $M$ 次查詢。透過雜湊函數進行尋址，單次查詢的平均時間複雜度為 $\mathcal{O}(L_2)$（ $L_2$ 為查詢單字的長度）。
  * 全域總時間與資料規模呈完全的線性相關，可在時限內極速通關。

* **空間複雜度**： $\mathcal{O}(N \times L_1)$ <br>
  `std::unordered_map` 需要完整的記憶體空間來緩衝這 $N$ 組對照單字。空間開銷與辭典的大小呈線性正比。


## 邊界條件與潛在陷阱

1. **第一階段結束標記（空白行的精確擷取）**：
   這是本題最經典的實作陷阱。如果直接使用 `cin >> english >> foreign`，當讀到空白行時，`cin` 會自動忽略任何不可見的換行符或空格，並強行阻塞、等待下一組資料的輸入，這會導致程式無法正確切換到查詢階段。

   * **程式碼防禦**：我先使用 `getline` 抓取整行文本，再透過 `line.empty()` 進行短路攔截。這能精確抓到那個純粹的換行空白行，實現兩階段的無縫切換。
2. **未知單字的動態防禦（避免誤建預設值）**：
   在 C++ 的 `unordered_map` 中，如果直接呼叫 `if (dictionary[query_word] != "")` 來進行存在性檢查，**當該 Key 不存在時，雜湊表會自動在內部幫你新建一個帶有預設空字串的鍵值對**。這會造成嚴重的記憶體膨脹與邏輯錯誤。
   * **程式碼防禦**：我使用 `dictionary.count(query_word)` 或是 `dictionary.find(...)` 來做前置檢查，只查詢而不觸發任何副作用，確保了程式的健康與記憶體的純淨。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    unordered_map<string, string> dictionary;
    string line;
    
    // 第一階段：流式讀入整行字串，當抓到完全空白行時立刻煞車，結束辭典建置
    while (getline(cin, line) && !line.empty()) {
        stringstream ss(line);
        string english, foreign;

        // 利用字串流，以空格為界，將一整行切割出兩個獨立單字
        ss >> english >> foreign;
        
        // 外語作為 Key，英文作為 Value
        dictionary[foreign] = english;
    }
    
    string query_word;
    // 第二階段：線上查詢流，連續讀入要翻譯的外語單字，直到檔案結束 (EOF)
    while (cin >> query_word) {
        // 核心防禦：利用 count() 判定鍵值是否存在，避免直接使用 [] 導致雜湊表誤建空值
        if (dictionary.count(query_word)) {
            cout << dictionary[query_word] << "\n";
        } else {
            // 查無此字，輸出題目規定的錯誤回應
            cout << "eh\n";
        }
    }
    return 0;
}
```


## 進階優化思考

**雙指標就地解析與字串視窗優化（String_View Tuning）**

雖然目前的 `std::stringstream` 寫法非常輕量且直觀，但在底層物理運作上，`stringstream` 在解析 `line` 時，會將切出來的單字複製並配置到全新的 `std::string` 記憶體空間中（引發 Heap Allocation）。在海量辭典資料反覆讀入的情境下，這種頻繁的記憶體配置與銷毀會產生顯著的常數時間耗損。

* **優化做法**：由於 `line` 字串讀入後在當行迴圈結束前都是唯讀且結構穩定的，我可以拋棄重量級的 `stringstream`，改用 C++17 引入的 `std::string_view` 配合指針來進行零複製（Zero-copy）卡位。

* **技術精髓**：我只需用一條簡單的 `line.find(' ')` 找出空格的物理索引，就能直接利用雙指標劃定出兩個唯讀的字串視窗。這樣做完全免除了任何記憶體複製與分配的代價。再搭配將 `unordered_map` 的 Key 替換為高效的原生字元指標或 `string_view`（需自訂雜湊與比較函式），就能將字串流的常數吞吐效能壓榨至底層物理極限，非常適合用來應對大規模、高併發的字串資料庫系統。
