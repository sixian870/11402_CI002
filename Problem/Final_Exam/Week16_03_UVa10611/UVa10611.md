# UVa 10611 - The Playboy Chimp

## 題目簡述

有一隻黑猩猩想要尋找合適的母猩猩伴侶。現在給定一個長度為 $N$ 且已經按**升序排序**的母猩猩身高序列 $H$。
接著會有 $M$ 次查詢，每次查詢給定黑猩猩目前的身高 $T$。

對於每一次查詢，我們需要幫黑猩猩找出兩個身高代表：
1. **最矮的高猩猩**：在所有身高**嚴格大於** $T$ 的母猩猩中，身高最矮的那一隻。
2. **最高的矮猩猩**：在所有身高**嚴格小於** $T$ 的母猩猩中，身高最高的那一隻。

如果找不到符合條件的猩猩（例如所有母猩猩都比黑猩猩高，則找不到比牠矮的猩猩），則以大寫字母 `'X'` 代替輸出。

**Sample Input**：

  **4** $\rightarrow$ 共有 $N = 4$ 隻母猩猩。<br>
  **1 4 5 7** $\rightarrow$ 母猩猩的身高序列（已排序）。<br>
  **2** $\rightarrow$ 共有 $M = 2$ 次查詢。<br>
  **4 8** $\rightarrow$ 兩次查詢的身高 $T$ 分別為 4 與 8。

**Sample Output**：

  **1 5** $\rightarrow$ 查詢 4：比 4 小的最大值是 1，比 4 大的最小值是 5。<br>
  **7 X** $\rightarrow$ 查詢 8：比 8 小的最大值是 7，沒有比 8 大的母猩猩（輸出 X）。


## 解題思路與二分搜尋結構

### 核心觀念：邊界二分搜尋與標準庫應用（Binary Search / Lower Bound & Upper Bound）
這道題目的本質是利用 **二分搜尋（Binary Search）** 在一組有序序列中快速檢索出臨界邊界。

由於母猩猩身高序列 $H$ 已經具有單調遞增的特性，如果使用線性掃描（Linear Scan）來處理每次查詢，單次查詢時間複雜度為 $\mathcal{O}(N)$，全域總時間會達到 $\mathcal{O}(M \times N)$。在 $N \le 50,000, M \le 25,000$ 的資料規模下很容易逾時。因此，必須使用 $\mathcal{O}(\log N)$ 的二分搜尋法來快速卡位。

C++ 的標準模板庫（STL）提供了兩個極其強大且經過高度優化的二分搜尋工具：
1. `std::lower_bound`：在一指定有序區間內，尋找**第一個「大於或等於（ $\ge$ ）」** 目標值 $T$ 的元素迭代器（Iterator）。
2. `std::upper_bound`：在一指定有序區間內，尋找**第一個「嚴格大於（ $>$ ）」** 目標值 $T$ 的元素迭代器。


### 邊界卡位與指標對齊
我們透過這兩個工具來精確鎖定黑猩猩要尋找的伴侶範圍：
* **尋找最矮的高猩猩（嚴格大於 $T$）**：<br>
  這完美契合 `std::upper_bound` 的幾何語意。我們直接呼叫 `high = upper_bound(...)`。若 `high` 成功指向陣列內部的合法位置（`high != H.end()`），則該位置的數值 `*high` 就是答案；若指向了末端，代表場上沒有任何猩猩比牠高，輸出 `'X'`。

* **尋找最高的矮猩猩（嚴格小於 $T$）**：<br>
  我們首先呼叫 `low = lower_bound(...)`，這會帶領我們找到第一個 $\ge T$ 的邊界點。此時，**該邊界點左邊鄰接的前一個位置（即 `--low`），其數值就必定是序列中「嚴格小於 $T$」的最大元素**。
  * **臨界安全防禦**：在執行 `--low` 向前跨步之前，必須先確保 `low` 沒有停留在陣列的最前端（`low != H.begin()`）。如果 `low == H.begin()`，代表連陣列裡最小的第一隻猩猩都大於或等於 $T$，左側已經無路可退，此時直接宣告找不到，輸出 `'X'`。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(N + M \log N)$ <br>

  * **資料讀入階段**：線性讀入長度為 $N$ 的陣列，耗時 $\mathcal{O}(N)$。
  * **二分查詢階段**：總共執行 $M$ 次查詢。每次查詢調用 `lower_bound` 與 `upper_bound` 進行二分折半查找，單次耗時為對數時間 $\mathcal{O}(\log N)$。
  * 總時間複雜度為 $\mathcal{O}(N + M \log N)$，代入極限數據運算量約為 $4 \times 10^5$ 次，可在幾毫秒內極速通過。

* **空間複雜度**： $\mathcal{O}(N)$ <br>
  需要配置一個大小為 $N$ 的 `std::vector<int>` 陣列來存放母猩猩的身高數據。空間開銷與 $N$ 呈線性正比。


## 邊界條件與潛在陷阱

1. **迭代器越界與無解退化（Iterator Out of Bounds）**：
   當黑猩猩身高 $T$ 極端小（例如比場上所有猩猩都矮）或極端大（比所有猩猩都高）時，二分搜尋指標會移向區間的極端兩端。

   * **原程式碼防禦**：原實作非常嚴謹，在印出解之前，強行加入了 `if (low != H.begin())` 與 `if (high != H.end())` 的雙重安全柵欄。這阻止了無效指標對記憶體的非法存取（防止了令人頭疼的 Segmentation Fault 崩潰），並完美完成了 `'X'` 的分流置換。

2. **相同身高重複元素的卡位精確度**：
   如果身高序列中存在多個與 $T$ 相同的身高（例如序列中有好幾個 `4`，且 $T = 4$），`lower_bound` 會指向這群 `4` 的第一個位置。此時 `--low` 會安全地跨過這群相同的值，退到更前一個嚴格小於 4 的元素。這完美符合了題目要求「嚴格小於」與「嚴格大於」的代數邊界。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n;
    if (cin >> n) {
        vector<int> H(n);
        for (int i = 0; i < n; i++) {
            cin >> H[i];
        }
        
        int m;
        cin >> m;
        while (m--) {
            int t;
            cin >> t;
            
            // 使用 STL 二分搜尋：low 指向第一個「大於或等於 t」的迭代器位置
            auto low = lower_bound(H.begin(), H.end(), t);
            // 使用 STL 二分搜尋：high 指向第一個「嚴格大於 t」的迭代器位置
            auto high = upper_bound(H.begin(), H.end(), t);
            
            // 核心判定一：尋找嚴格小於 t 的最高猩猩
            // 若 low 沒有停在陣列的最起點，代表左邊還有更矮的猩猩存在
            if (low != H.begin()) {
                // 將指標向前退一格，該位置即為比 t 小的最大身高代表
                cout << *(--low) << " "; 
            }
            else {
                // 若 low 已經在起點，代表場上沒有任何母猩猩比黑猩猩矮
                cout << "X ";
            }
            
            // 核心判定二：尋找嚴格大於 t 的最矮猩猩
            // 若 high 沒有越過陣列的末端邊界，代表場上有比 t 高的猩猩存在
            if (high != H.end()) {
                cout << *high << "\n";
            }
            else {
                // 若已經移到末端，代表場上所有的母猩猩都比黑猩猩矮或一樣高
                cout << "X\n";
            }
        }
    }
    return 0;
}
```


## 進階優化思考

**陣列原地去重優化（Array Unique-Pruning 策略）**

雖然目前的二分搜尋實作在時間複雜度上已經達到最優的 $\mathcal{O}(\log N)$，但在工程實務上，母猩猩的身高序列中可能存在大量**完全相同、重複的身高數值**（例如輸入序列為 `1 2 2 2 2 2 2 3`）。在這種情境下，大量的重複元素會拉長二分搜尋樹的實際跨度，且會導致快取記憶體載入過多無用數據。

* **優化做法**：由於序列在輸入時就已經保證有序，我們可以在資料讀入完成後，直接利用 STL 的 `std::unique` 函式對陣列進行原地去重修剪。

* **效益**：去重後配合 `erase` 縮減陣列實體體積。這能讓陣列中只保留純粹、相異的身高臨界點。這樣一來，二分搜尋時的尋址範圍被大幅度精簡，不僅能提高 CPU 的資料快取命中率（Cache Hit Rate），也能讓整體搜尋常數時間表現更加精悍洗練。

**優化程式碼實作片段：**
```cpp
// 讀入 H 陣列後，立即進行線性去重卡位
auto last = unique(H.begin(), H.end());
H.erase(last, H.end()); // 砍掉尾端多餘的重複記憶體片段
```
