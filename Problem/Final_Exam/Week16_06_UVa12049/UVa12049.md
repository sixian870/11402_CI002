# UVa 12049 - Just Prune The List

## 題目簡述

我有兩個由整數構成的清單（List），第一個清單長度為 $N$，第二個清單長度為 $M$。我的目標是透過**刪除最少數量的元素**，使得這兩個清單最終所包含的元素內容與各元素的出現頻率完全相同（即兩個清單經過排序後會完全一模一樣）。

請計算出在最優的刪除策略下，我最少需要從這兩個清單中移除多少個元素？

**Sample Input**：

  **1** $\rightarrow$ 共有 1 組測試資料。<br>
  **3 4** $\rightarrow$ 第一個清單長度 $N = 3$，第二個清單長度 $M = 4$。<br>
  **1 2 3** $\rightarrow$ 第一個清單的實體元素。<br>
  **2 3 4 5** $\rightarrow$ 第二個清單的實體元素。

**Sample Output**：

  **3** $\rightarrow$ 需要刪除第一個清單的 1，以及第二個清單的 4 和 5，共計 3 個元素。


## 解題思路與平衡計數分析

### 核心觀念：次數差絕對值之和（Element Frequency Balancing）
這道題目的本質是**元素出現頻率的差值統計問題**。

兩個清單要達到完全對等，意味著對於任何一個整數 $x$，它在第一個清單出現的次數 $f_1(x)$ 必須等於在第二個清單出現的次數 $f_2(x)$。
* 如果 $f_1(x) > f_2(x)$：代表第一個清單太過臃腫，我必須從中刪除 $|f_1(x) - f_2(x)|$ 個元素。
* 如果 $f_1(x) < f_2(x)$：代表第二個清單該元素過多，我同樣必須從中刪除 $|f_1(x) - f_2(x)|$ 個元素。

因此，全域所需刪除的最少元素總數，就是所有在清單中出現過的元素，其**出現頻率之差的絕對值總和**：
$$\text{Total Removed} = \sum_{x} |f_1(x) - f_2(x)|$$

為了在不進行低效雙層遍歷的前提下完成統計，我選擇使用平衡檢索樹容器 **`std::map`**（或雜湊表 `std::unordered_map`）來作為頻率快取池。


### 演算法步驟
1. 建立一個對照表 `freq`。
2. **第一階段（累加頻率）**：流式讀入第一個清單的 $N$ 個元素。每讀入一個數值 `val`，就在對照表中將其計數加 1（即 `freq[val]++`）。
3. **第二階段（抵消頻率）**：流式讀入第二個清單的 $M$ 個元素。每讀入一個數值 `val`，就在對照表中將其計數減 1（即 `freq[val]--`）。
4. **第三階段（差值結算）**：此時，`freq` 中每個鍵值對的 `second` 代表的就是該整數在兩清單中的出現次數差（ $f_1(x) - f_2(x)$ ）。我利用一條遍歷迴圈將所有差值的絕對值 `abs(pair.second)` 累加到 `removed` 變數中，即為最終答案。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}((N + M) \log(N + M))$ <br>
  在程式碼實作中使用了基於紅黑樹（Red-Black Tree）的 `std::map`。每次插入或查詢的開銷均為對數時間 $\mathcal{O}(\log U)$（ $U$ 為相異元素的個數，最大不超過 $N+M$）。總共執行了 $N + M$ 次對數尋址操作，因此全域總時間複雜度為 $\mathcal{O}((N + M) \log(N + M))$，可在幾十毫秒內迅速通過評測。

* **空間複雜度**： $\mathcal{O}(N + M)$ <br>
  對照表 `freq` 在最極端惡劣的情境下（所有輸入的整數均不相同）會耗費線性正比的記憶體空間來儲存這些獨立的鍵值對。


## 邊界條件與潛在陷阱

1. **僅出現在單邊清單的元素（Unilateral Elements）**：<br>
   如果某個整數（例如 Sample 中的 `1`）只出現在第一個清單而完全沒出現在第二個清單中，第一階段會使其 `freq[1] = 1`，第二階段不會觸發它。最後結算時，`abs(1) = 1` 會被正確計入。這證明了「雙邊加減抵消模型」能完美自動相容那些非交集的孤立元素。
2. **多組測資記憶體重設（State Reset）**：<br>
   在處理外層 `while (T--)` 迴圈時，每組測資的 `freq` 對照表都必須是完全純淨的。我將 `map<int, int> freq;` 宣告在迴圈內部，利用 C++ 的局部變數區域生命週期機制。當每輪迭代結束時，編譯器會自動呼叫其解構子徹底清空內存，有效防止了 Case 之間的數據互相污染。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int T;
    // 讀入測試資料組數
    if (cin >> T) {
        while (T--) {
            int N, M;
            cin >> N >> M;
            
            // 利用平衡檢索樹紀錄每個整數的相對平衡頻率
            map<int, int> freq;
            
            // 步驟一：讀入第一個清單，將出現次數累加
            for (int i = 0; i < N; ++i) {
                int val;
                cin >> val;
                freq[val]++;
            }
            
            // 步驟二：讀入第二個清單，將出現次數扣除
            for (int i = 0; i < M; ++i) {
                int val;
                cin >> val;
                freq[val]--;
            }
            
            int removed = 0;
            // 步驟三：結算所有元素出現次數差的絕對值總和
            for (const auto& pair : freq) {
                removed += abs(pair.second);
            }
            
            // 輸出此組測資最少需要裁減的元素數量
            cout << removed << "\n";
        }
    }
    return 0;
}
```


## 進階優化思考 (Optimization)

**雜湊重構與線性時間複雜度調優（Unordered_Map Tuning）**

雖然目前的 `std::map` 在實作上已經能拿到優秀的 AC，但從極限效率調優的工程視角來看，紅黑樹在每次插入新資料時，底層都會觸發記憶體節點的新建以及複雜的樹體動態旋轉（樹平衡平衡重組開銷）。

* **優化做法**：我可以將主程式中的 `std::map<int, int>` 替換為以雜湊表為底層結構的 `std::unordered_map<int, int>`。

* **技術精髓**：替換為雜湊表後，第一與第二階段的元素尋址開銷會直接從原本的 $\mathcal{O}(\log(N+M))$ 降維到平均 $\mathcal{O}(1)$ 常數時間。這會使全域總時間複雜度優化為完全線性的 $\mathcal{O}(N + M)$。在海量密集數據的競賽環境中，這能進一步免除指針跳轉與樹體旋轉的常數負擔，讓程式以物理極速通關。
