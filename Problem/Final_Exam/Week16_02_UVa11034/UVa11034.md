# UVa 11034 - Ferry Loading IV

## 題目簡述

有一艘渡輪負責在河的左岸與右岸之間來回運送汽車。渡輪的長度為 $l$ 公尺，而每輛汽車也都有各自的長度（單位為公分）。

**運送規則如下**：
1. 汽車抵達河岸時，會依據到達順序排成兩條佇列：左岸佇列（`left`）與右岸佇列（`right`）。
2. 渡輪載車時，必須嚴格按照排隊順序（先進先出）將車開上船，直到船上所有汽車的長度總和超過渡輪的乘載上限 $l$ 為止。
3. 渡輪最初停靠在**左岸**。不論船上有沒有載車，只要對岸有車在排隊，或者當前河岸有車需要運送，渡輪就會開到對岸。

請計算出在將所有排隊的汽車全部運送完畢的前提下，渡輪總共需要**橫跨河流（Crossings）多少次**？

**輸入規範**：
* 第一行包含一個正整數 $T$，代表測試資料的組數。
* 每組測試資料的第一行包含兩個整數 $l$（渡輪長度，公尺）與 $m$（汽車總數）。
* 接下來的 $m$ 行，每行包含一個整數（汽車長度，公分）與一個字串（`left` 或 `right`，代表車輛到達的河岸）。

**Sample Input**：

  **1** $\rightarrow$ 共有 1 組測試資料。<br>
  **20 4** $\rightarrow$ 渡輪長度 $l = 20$ 公尺（即 2000 公分），共有 $m = 4$ 輛車。<br>
  **380 left** $\rightarrow$ 第一輛車長 380 公分，在左岸排隊。<br>
  **720 left**<br>
  **1340 right**<br>
  **1040 left**

**Sample Output**：

  **3** $\rightarrow$ 渡輪總共橫跨河流 3 次（左 $\rightarrow$ 右、右 $\rightarrow$ 左、左 $\rightarrow$ 右）。


## 解題思路與佇列模擬

### 核心觀念：先進先出佇列與雙岸貪婪模擬（Queue & Greedy Simulation）
這道題目的本質是經典的**先進先出（FIFO）排隊模型與狀態機模擬**。

為了精確還原汽車排隊與渡輪運行的幾何物理過程，最佳的資料結構是採用標準模板庫的 **`std::queue`** 來分別管理左岸與右岸的汽車資料流。

### 演算法與模擬狀態機步驟
1. **單位對齊（重中之重）**：<br>
   讀入的渡輪長度 $l$ 單位是「公尺」，而汽車長度單位是「公分」。在進行任何代數比較前，必須強行將渡輪長度乘以 100（`m *= 100`），統一轉換為公分制。
2. **分流排隊**：<br>
   依序讀入 $m$ 輛汽車。若河岸字串為 `"left"` 則推入 `left` 佇列；若為 `"right"` 則推入 `right` 佇列。
3. **渡輪來回狀態機**：<br>
   宣告布林變數 `isLeft = true` 代表渡輪目前停靠在左岸，並將跨河計數器 `count` 歸零。只要左岸或右岸任一佇列不為空（`!left.empty() || !right.empty()`），模擬就必須持續進行：

   * **在左岸時（`isLeft == true`）**：<br>
     啟用一個長度累加計數器 `load = 0`。只要左岸佇列不為空，且目前船上的總長度加上排頭第一輛車的長度不超過渡輪上限（`load + left.front() <= m`），就將該車開上渡輪（`load += left.front()`）並移出佇列（`left.pop()`）。裝載完畢後，渡輪開往右岸，因此變更狀態 `isLeft = false`，且跨河次數 `count++`。

   * **在右岸時（`isLeft != true`）**：<br>
     執行與左岸完全對稱的裝載邏輯。從 `right` 佇列中貪婪抓取汽車，直到塞滿為止。隨後渡輪返回左岸，變更狀態 `isLeft = true`，且跨河次數 `count++`。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(M)$ <br>
  其中 $M$ 為排隊汽車的總數。在每組測試資料中，每輛汽車在讀入時被推入佇列一次（`push` 耗時 $\mathcal{O}(1)$），在渡輪裝載時被移出佇列一次（`pop` 耗時 $\mathcal{O}(1)$）。整個 `while` 模擬迴圈的演進步長與汽車出隊完全同步，所有車輛清空即煞車。因此，總體時間複雜度與汽車總數 $M$ 呈完全的線性正比，可在幾毫秒內瞬間通過。
* **空間複雜度**： $\mathcal{O}(M)$ <br>
  需要配置兩個 `std::queue<int>` 佇列。在最極端狀態下（所有汽車全在一邊排隊），佇列最多需要同時容納 $M$ 個整數。空間開銷與資料規模 $M$ 呈線性正比，記憶體佈局精簡。


## 邊界條件與潛在陷阱

1. **空船空渡邊界（Empty Run）**：<br>
   題目並未保證渡輪每一次跨河都一定能載到車。舉例來說，當渡輪停靠在左岸且左岸完全沒車，但右岸有車正在排隊時，渡輪必須**空船直接開往右岸**。

   * **程式碼防禦**：原實作內層的 `while (!left.empty() && ...)` 條件控制非常精妙。當 `left.empty()` 為真時，內層裝載迴圈會直接跳過，`load` 保持為 0。程式直接向下執行 `count++` 增長跨河次數，並將 `isLeft` 切換為 `false`。這完美相容了空船開渡的物理語意。
2. **多組測資佇列自動清空與重構**：<br>
   為了防止歷史跨 Case 的資料殘留引發 Wrong Answer，原程式碼將 `left` 與 `right` 佇列宣告在 `while(t--))` 內部。這利用了 C++ 局部變數的生命週期機制，在每一輪迭代開始時自動調用解構子徹底銷毀並重新配置，徹底隔絕了測資間的數據污染。


## 程式碼實作

```cpp
#include <iostream>
#include <queue>
#include <string>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios::sync_with_stdio(false);
    cin.tie(0);

    int t;
    if (cin >> t) {
        while (t--) {
            int m, n;
            cin >> m >> n;
            
            // 核心防禦：渡輪長度為公尺，汽車長度為公分，必須強行統一單位
            m *= 100; 
            
            queue<int> left, right;
            while (n--) {
                int cm;
                string d;
                cin >> cm >> d;
                // 依據抵達河岸分流推入相應的先進先出佇列
                if (d == "left") {
                    left.push(cm);
                }
                if (d == "right") {
                    right.push(cm);
                }
            }
            
            bool isLeft = true; // 狀態變數：追蹤目前渡輪所在的河岸 (最初在左岸)
            int count = 0;      // 跨河次數計數器
            
            // 只要兩岸還有任何一輛車沒送完，渡輪就必須持續運行
            while (!left.empty() || !right.empty()) {
                int load = 0; // 局部累加器：紀錄當前這趟渡輪已承載的汽車長度總和
                
                // 狀況一：渡輪目前在左岸
                if (isLeft == true) {
                    // 貪婪裝載：只要左岸有車排隊且塞得下，就持續拉上船
                    while (!left.empty() && load + left.front() <= m) {
                        load += left.front();
                        left.pop(); // 汽車上船，移出佇列
                    }
                    count++;        // 執行跨河
                    isLeft = false; // 渡輪抵達右岸
                }
                // 狀況二：渡輪目前在右岸
                else if (isLeft != true) {
                    // 對稱貪婪裝載右岸排隊汽車
                    while (!right.empty() && load + right.front() <= m) {
                        load += right.front();
                        right.pop();
                    }
                    count++;       // 執行跨河
                    isLeft = true; // 渡輪返回左岸
                }
            }
            // 輸出總跨河流次數
            cout << count << "\n";
        }
    }
    return 0;
}
```


## 進階優化思考

**程式碼分支精簡與多路多流狀態歸一化**

雖然目前的實作在邏輯上非常直觀，但程式碼中針對 `isLeft == true` 與 `isLeft != true` 撰寫了兩段高度重複、完全對稱的 `while` 裝載代碼。從高階軟體工程的代碼高內聚、低耦合與編譯器最佳化視角來看，過多的重複程式碼會導致編譯產出的二進位制指令體積（Code Size）變大，且不利於未來的結構維護。

* **優化做法**：我們可以引入一個指標陣列或者**引用指標（Reference Wrapper）**，在進入裝載判定前，直接根據 `isLeft` 的狀態，將一個統一的佇列引用 `target_queue` 動態綁定到 `left` 或 `right`。

* **效益**：這樣一來，後續的整個汽車裝載、`pop` 操作以及長度累加邏輯，就都可以完全收攏、歸一化為一條通用軌道。不僅能直接砍掉一半的程式碼量，更能消除冗餘的條件判斷分支，使整體邏輯結構呈現出極高的工程幾何美感。

**優化程式碼實作片段**：
```cpp
// 在大迴圈內部，利用指標或引用動態鎖定當前的目標佇列
queue<int>& target_queue = (isLeft) ? left : right;
// 歸一化通用裝載軌道，兩岸邏輯合二為一
while (!target_queue.empty() && load + target_queue.front() <= m) {
    load += target_queue.front();
    target_queue.pop();
}
count++;          // 跨河計數
isLeft = !isLeft; // 狀態位元直接取反反轉
```
透過這種手法，渡輪無論在哪一岸，執行的都是完全相同的底層抽象指令。代碼變得極切洗練優雅，是高階演算法重構中非常實用的常數結構調優打法。
