# UVa 442 - Matrix Chain Multiplication

## 題目簡述

給定一個包含多個矩陣的集合，每個矩陣都有其特定的列數（Rows）與行數（Columns）。接著會輸入一系列由括號與矩陣名稱組成的矩陣乘法運算式（例如：`(A(BC))`）。

計算並輸出：在該表達式指定的乘法順序下，**總共需要執行多少次基礎純量乘法（Scalar Multiplications）**？

**矩陣乘法數學規則**：
設矩陣 $M_1$ 的維度為 $r_1 \times c_1$，矩陣 $M_2$ 的維度為 $r_2 \times c_2$：
* **相乘前提**：只有當 $c_1 = r_2$ 時，這兩個矩陣才能相乘。若不相等，則該乘法非法，必須輸出 `error`。
* **乘法代價**：兩矩陣相乘所耗費的純量乘法次數為：
  $$\text{Cost} = r_1 \times c_1 \times c_2$$
* **結果維度**：相乘後產生的新矩陣，其維度將會退化為 $r_1 \times c_2$。

**Sample Input**：

  **3** $\rightarrow$ 共有 3 個已知矩陣。<br>
  **A 50 10** $\rightarrow$ 矩陣 A 的維度為 $50 \times 10$。<br>
  **B 10 20**<br>
  **C 20 5**<br>
  **(AA)** $\rightarrow$ 第一組查詢運算式。<br>
  **(A(BC))** $\rightarrow$ 第二組查詢運算式。

**Sample Output**：

  **error** $\rightarrow$ (AA) 中，A 的行數 10 不等於 A 的列數 50，無法相乘。<br>
  **3500** $\rightarrow$ (A(BC)) 中，BC 先乘耗費 $10 \times 20 \times 5 = 1000$ 次，得到新矩陣維度 $10 \times 5$；隨後 A 再與其相乘耗費 $50 \times 10 \times 5 = 2500$ 次。總計 $1000 + 2500 = 3500$ 次。


## 解題思路與堆疊表達式模擬

### 核心觀念：堆疊資料結構與中序運算式求值（Stack & Expression Evaluation）
這道題目的本質是利用 **堆疊（Stack）** 資料結構來解析帶有完全括號的中序運算式。

由於題目給定的運算式中，每一次有效的矩陣乘法都會被一對嚴格相配對的右括號 `')'` 封口。這意味著我們不需要去考慮算式中的優先權（Precedence）調度，直接使用一個存放矩陣維度（對應為 `pair<long long, long long>`）的堆疊，即可依據由內向外的幾何順序流式求解。

### 演算法步驟
1. **建立矩陣資料庫**：<br>
   我使用 `std::unordered_map<char, pair<long long, long long>>` 將大寫字母字元映射到其對應的維度 `{row, col}`。
2. **堆疊流式掃描**：<br>
   逐一讀入運算式字串，並由左至右橫向遍歷每個字元 `ch`：

   * **狀況一（遇到字母）**：代表讀入了一個實體矩陣。我直接從資料庫中抽取出其維度，並將其推入 `st` 堆疊中：`st.push(matrices[ch]);`。
   * **狀況二（遇到左括號 `'('`）**：在本題完全括號的語意下，左括號不帶有任何運算元資訊，可以直接忽略不予處理。
   * **狀況三（遇到右括號 `')'`）**：這代表一個子運算式的結束，**必須立刻從堆疊頂端彈出兩個矩陣進行乘法融合**。
4. **矩陣乘法融合與合法性驗證**：<br>
   當 `ch == ')'` 時，我連續兩次執行 `st.top()` 與 `st.pop()`：
   * 先彈出的矩陣為右矩陣 `m2`，後彈出的矩陣為左矩陣 `m1`（**注意順序絕對不可顛倒**）。
   * 檢查是否滿足 `m1.second == m2.first`。若不滿足，代表行歹列不對齊，立即將 `error` 旗標拉高並煞車中斷。
   * 若合法，累加本次純量乘法代價，並將融合後的新矩陣 `{m1.first, m2.second}` 再次推回堆疊頂端，供外層的下一輪括號運算使用。


## 複雜度分析

* **時間複雜度**： $\mathcal{O}(L)$ <br>
  其中 $L$ 為運算式字串的長度。在整條模擬軌道上，每個字元只會被掃描一次。每個矩陣維度最多只會被推入堆疊一次、彈出一次。所有的堆疊操作與矩陣合法性檢索都在 $\mathcal{O}(1)$ 常數時間內完工。因此，總體時間複雜度與表達式長度 $L$ 呈純粹的線性正比，可在幾毫秒內極速通過。
* **空間複雜度**： $\mathcal{O}(N + L)$ <br>
  雜湊表需要儲存 $N$ 個矩陣的維度（最大 $N = 26$ ），而堆疊在最極端狀態下會存放長度不超過 $L$ 的矩陣物件，空間佈局十分精簡。


## 邊界條件與潛在陷阱

1. **彈出順序與矩陣非交換性（Non-commutativity 防禦）**：<br>
   矩陣乘法不滿足交換律（ $A \times B \neq B \times A$ ）。在堆疊結構中，先彈出來的物件 `st.top()` 在物理算式上其實是**位於右側的矩陣**。
   * **原程式碼分析**：我非常嚴謹地用 `m2` 接收第一次彈出，用 `m1` 接收第二次彈出，並以 `m1.second != m2.first` 進行對齊檢查。這完美捍衛了矩陣乘法的空間幾何順序。
2. **極端大數與純量溢位（Integer Overflow 防禦）**：<br>
   雖然單個矩陣的維度可能只有幾百，但隨著表達式不斷向外疊加融合，乘法次數會產生高昂的乘積增長。

   * **程式碼防禦**：我將矩陣的維度 `r, c`、代價累加器 `ans` 一律提升至 **`long long`**（64 位元有號整數），這成功隔離了因數據爆表而引發的數值溢位截斷風險。
3. **非法單字元表達式防禦**：<br>
   如果運算式只有單個矩陣（例如 `A` ），堆疊大小會保持為 1 且不會觸發右括號。原程式碼外層的特判機制能健康輸出 0，完全相容臨界 Case。


## 程式碼實作

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 提升標準 I/O 串流之效能
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n;
    if (!(cin >> n)) return 0;
    
    // 建立矩陣資料庫：映射字母名稱到其對應的 {列數, 行數} 維度對
    unordered_map<char, pair<long long, long long>> matrices;
    for (int i = 0; i < n; i++) {
        char name;
        long long r, c;
        cin >> name >> r >> c;
        matrices[name] = {r, c};
    }
    
    string expr;
    // 線上查詢流：連續讀入矩陣乘法運算式
    while (cin >> expr) {
        stack<pair<long long, long long>> st; // 存放矩陣維度的動態堆疊
        bool error = false;                  // 追蹤當前算式是否非法的旗標
        long long ans = 0;                   // 純量乘法總次數累加器
        
        for (char ch : expr) {
            // 狀況一：遇到矩陣字母，直接調用維度並推入堆疊頂端
            if (isalpha(ch)) {
                st.push(matrices[ch]);
            } 
            // 狀況二：遇到右括號，強制觸發矩陣相乘融合
            else if (ch == ')') {
                // 安全防禦：堆疊內若少於兩個矩陣，代表括號語法錯誤
                if (st.size() < 2) {
                    error = true;
                    break;
                }
                
                // 核心關鍵：先彈出者為右矩陣 m2，後彈出者為左矩陣 m1
                auto m2 = st.top(); st.pop();
                auto m1 = st.top(); st.pop();

                // 幾何檢驗：左矩陣的行數 (c1) 必須等於右矩陣的列數 (r2)
                if (m1.second != m2.first) {
                    error = true;
                    break;
                }

                // 計算本次相乘產生的純量乘法代價：r1 * c1 * c2
                ans += m1.first * m1.second * m2.second;
                
                // 將乘法交融後產生新矩陣維度 {r1, c2} 再次推回堆疊
                st.push({m1.first, m2.second});
            }
            // 狀況三：遇到左括號 '(' 則直接略過，不予理會
        }
        
        // 輸出判定結果
        if (error) {
            cout << "error\n";
        } else {
            cout << ans << "\n";
        }
    }
    return 0;
}
```


## 進階優化思考

**靜態陣列對照表優化與分支預測調優（Static Array Look-up）**

雖然目前使用 `std::unordered_map` 在進行字串映射與檢索時具備非常優秀的平均常數時間效能，但如果從高性能競賽晶片底層的快取命中率與分支預測調優視角出發，雜湊表的動態尋址機制仍會在背後引發微量的指標跳轉開銷。

* **優化做法**：由於題目明確指出矩陣名稱皆為大寫的英文字母（即 `A` 到 `Z`），其總數被死死限制在 26 個之內。我可以徹底拋棄重量級的雜湊表，直接在主程式開頭宣告一個固定大小為 26 的**靜態結構體陣列（Static Array / Look-up Table）**：
  ```cpp
  pair<long long, long long> mat_table[26];
  ```

* **技術精髓**：當讀入矩陣名稱字元 `name` 時，我直接利用其 ASCII 碼的連續偏移量進行下標鎖定：`mat_table[name - 'A'] = {r, c};` 。在後續表達式遍歷中，堆疊推入時直接改寫為 `st.push(mat_table[ch - 'A'])`。這種原生陣列的物理空間是絕對連續且不可動搖的，能百分之百一次性加載進 CPU 的 L1 快取。它將原本需要進行雜湊碰撞計算與動態鏈結指標尋址的代價，直接降維成了一次簡單的暫存器內記憶體地址偏移加法。這能抹除一切底層隱性常數開銷，將執行速度推向硬體極限。
